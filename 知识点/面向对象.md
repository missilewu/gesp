### 一、面向对象思想 (Object-Oriented Thinking)

#### 1. 从“面向过程”到“面向对象”
*   **面向过程 (Procedure-Oriented)**：关注的是**步骤**。就像做蛋炒饭，第一步热油，第二步放饭，第三步放蛋。代码是一系列函数的集合，数据在这些函数之间传递。
    *   *缺点*：当系统变大，数据和操作分离，容易导致数据被意外修改，代码难以维护。
*   **面向对象 (Object-Oriented)**：关注的是**对象**。世界是由对象组成的。做蛋炒饭，我们有一个“厨师”对象，一个“锅”对象，一个“食材”对象。厨师对象调用自己的“炒菜”方法，锅对象提供“加热”功能。
    *   *核心*：**数据（属性）**和**操作数据的方法（行为）**被绑定在一起，形成一个独立的单元——**类（Class）**。

#### 2. 核心概念映射
*   **类 (Class)**：图纸/模板。例如：“汽车设计图”。它定义了汽车应该有颜色、品牌（属性），以及能跑、能刹车（方法）。
*   **对象 (Object)**：根据图纸造出来的具体实物。例如：“一辆红色的特斯拉”。它是类的**实例化**。

> **教练提示**：在竞赛中，当你发现需要管理大量具有相同属性但不同状态的数据（如地图上的多个怪物、棋盘上的多个棋子）时，立刻想到用“类”来封装，这会让你的代码结构清晰无比。

### 二、类的创建和初始化 (Class Creation & Initialization)

在C++中，类是使用 `class` 关键字定义的。

#### 1. 基本结构
```cpp
class Hero {
public: // 公有成员，外部可访问
    string name;
    int hp;
    
    // 构造函数 (Constructor)
    Hero(string n, int h) {
        name = n;
        hp = h;
    }
    
    // 成员函数 (Method)
    void attack() {
        cout << name << " 发起了攻击!" << endl;
    }
};
```

#### 2. 构造函数与初始化列表 (重点！)
构造函数是在创建对象时自动调用的特殊函数，用于初始化对象。

*   **普通写法**：在函数体内赋值。
*   **推荐写法（竞赛/工程标准）**：使用**初始化列表**。效率更高，特别是对于自定义类型或常量成员。

```cpp
class Player {
public:
    int id;
    const int level; // 常量成员必须在初始化列表中初始化
    string equipment;

    // 初始化列表写法：冒号后面接 成员名(参数)
    Player(int i, int l, string eq) : id(i), level(l), equipment(eq) {
        // 函数体可以为空，或者做其他逻辑处理
    }
};
```

#### 3. 析构函数 (Destructor)
当对象生命周期结束（超出作用域或被 `delete`）时自动调用，用于释放资源（如动态分配的内存、关闭文件）。
```cpp
~Player() {
    // 清理工作
    cout << "Player " << id << " 离开了游戏。" << endl;
}
```

### 三、类的三大特性 (The Three Pillars)

这是面试和高级竞赛考察的重中之重：**封装、继承、多态**。

#### 1. 封装 (Encapsulation)
**定义**：隐藏对象的内部细节，只暴露必要的接口给外部使用。
**目的**：保护数据安全，降低耦合。

*   **访问控制符**：
    *   `private`：私有。只有类内部的函数可以访问。**这是默认权限**。
    *   `public`：公有。任何地方都可以访问。
    *   `protected`：保护。类内部和**子类**可以访问（为继承做准备）。

**示例**：
```cpp
class BankAccount {
private:
    double balance; // 余额设为私有，防止外部直接修改

public:
    BankAccount(double initial) : balance(initial) {}

    // 通过公有方法安全地修改余额
    void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    double getBalance() { // Getter
        return balance;
    }
};
```
> **教练点评**：如果不封装，任何人都可以直接写 `account.balance = -1000000;`，系统就崩溃了。封装强制所有操作必须经过逻辑检查。

#### 2. 继承 (Inheritance)
**定义**：一个新类（子类/派生类）从现有类（父类/基类）那里获得属性和方法。
**目的**：代码复用，建立类之间的层次关系（"Is-a" 关系）。

*   **语法**：`class 子类 : 访问修饰符 父类`
*   **继承方式**：通常使用 `public` 继承。

```cpp
// 基类
class Animal {
protected: // 保护成员，子类可访问
    int age;
public:
    void sleep() { cout << "睡觉中..." << endl; }
};

// 派生类
class Dog : public Animal {
public:
    void bark() {
        cout << "汪汪汪！我今年" << age << "岁了。" << endl; // 可以直接访问父类的 protected 成员 age
    }
};
```

**注意**：
*   构造函数**不会**被继承，子类必须定义自己的构造函数，并在初始化列表中调用父类构造函数。
*   `Dog d;` 既是 `Dog` 也是 `Animal`。

#### 3. 多态 (Polymorphism) —— 最难也最强大
**定义**：同一个接口，在不同的对象上有不同的表现形式。
**核心机制**：**虚函数 (Virtual Function)** 和 **动态绑定 (Dynamic Binding)**。

如果没有多态，父类指针只能调用父类的函数。有了多态，父类指针指向子类对象时，调用的是子类的函数。

**实现步骤**：
1.  在基类中将函数声明为 `virtual`。
2.  在派生类中**重写 (Override)** 该函数。
3.  使用基类指针或引用指向派生类对象。

**代码演示**：
```cpp
#include <iostream>
#include <vector>
using namespace std;

class Shape {
public:
    // 关键：加上 virtual 关键字
    virtual double area() { 
        return 0.0; 
    }
    
    // 虚析构函数：防止通过基类指针删除派生类对象时内存泄漏
    virtual ~Shape() {} 
};

class Circle : public Shape {
private:
    double r;
public:
    Circle(double radius) : r(radius) {}
    
    // 重写 (Override)
    double area() override { 
        return 3.14159 * r * r; 
    }
};

class Rectangle : public Shape {
private:
    double w, h;
public:
    Rectangle(double width, double height) : w(width), h(height) {}
    
    double area() override { 
        return w * h; 
    }
};

int main() {
    // 多态的体现：使用基类指针数组存储不同类型的对象
    vector<Shape*> shapes;
    shapes.push_back(new Circle(5.0));
    shapes.push_back(new Rectangle(4.0, 6.0));

    for (auto s : shapes) {
        // 编译器不知道 s 具体是什么，但在运行时会根据实际对象类型调用对应的 area()
        cout << "面积：" << s->area() << endl; 
    }

    // 清理内存
    for (auto s : shapes) delete s;
    
    return 0;
}
```

**原理解析（给想拿高分的同学）**：
*   **虚函数表 (vtable)**：当一个类包含虚函数时，编译器会为该类生成一张虚函数表，表中存放着该类所有虚函数的地址。
*   **虚函数指针 (vptr)**：每个对象内部隐藏了一个指针，指向其所属类的虚函数表。
*   **动态绑定**：调用 `s->area()` 时，程序不是看 `s` 的类型（Shape*），而是去查 `s` 指向对象的 `vptr`，找到对应的 `vtable`，再调用表中实际的函数地址。这就是为什么 `Circle` 对象会调用 `Circle::area`。

### 四、竞赛中的应用建议

1.  **何时使用类？**
    *   **大模拟题目**：如“操作系统进程调度”、“围棋棋盘”、“复杂的物理引擎模拟”。将每个实体抽象为类，逻辑会非常清晰。
    *   **数据结构封装**：自己实现线段树、平衡树时，用类封装节点和操作，比全局数组+函数更易于调试和扩展。

2.  **避坑指南**：
    *   **不要过度设计**：如果是简单的贪心或搜索题，直接用结构体 (`struct`) 或全局变量更快，写类会增加代码量和编译时间。
    *   **注意性能**：虚函数有微小的运行时开销（查表），在极度追求速度的循环（如 $10^8$ 次操作）中，尽量避免使用多态，改用模板或直接判断。
    *   **内存管理**：使用了 `new` 一定要 `delete`，或者在竞赛中推荐使用智能指针（如果环境支持C++11/14/17）或在程序结束前统一清理。

### 总结
*   **封装**让代码更安全。
*   **继承**让代码可复用。
*   **多态**让代码更灵活、可扩展。
