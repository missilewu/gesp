
## 题目

### 【问题描述】
网站注册需要有用户名和密码，编写程序以检查用户输入密码的有效性。合规的密码应满足以下要求：
1、只能由a-z之间26个小写字母、A-Z之间26个大写字母、0-9之间10个数字以及!@#$四个特殊字符构成。
2、密码最短长度：6个字符，密码最大长度：12个字符。
3、大写字母、小写字母和数字必须至少有其中两种，以及至少有四个特殊字符中的一个。

### 【输入描述】
输入一行不含空格的字符串。约定长度不超过100。该字符串被英文逗号分隔为多段，作为多组被检测密码。

### 【输出描述】
输出若干行，每行输出一组合规的密码。
输出顺序以输入先后为序，即先输入则先输出。

#### 【样例输入1】
```
seHJ12!@,sjdkffH$123,sdf!@&12HDHa!,123&^YUhg@!

```
##### 【样例输出1】
```
seHJ12!@
sjdkffH$123
```
##### 【样例解释1】
输入被英文逗号分为了四组被检测密码：“seHJ12!@”、“sjdkffH$123”、
“sdf!@&12HDHa!”、“123&^YUhg@!”。其中，“sdf!@&12HDHa!”长度超过 12 个字
符，不合规；“123&^YUhg@!”包含四个特殊字符之外的字符“^”，不合规。

## 解题思路
1. 首先遍历输入的字符串line并按照','进行分隔。
2. 对于分隔出来的每一个密码，先判断密码长度是否符合要求，然后遍历所有的字符，并用hasC，hasL，hasD，hasS分别记录是否存在大写字母，小写字母，数字以及特殊字符，若存在以上四种字符外的其它字符则直接返回非法。
3. 判断是否存在特殊字符，若不存在返回非法。
4. 判断是否存在两种及以上的大写字母、小写字母和数字，若不存在返回非法。
5. 以上情况都存在，返回合法并输出。
【考纲知识点】多层分支/循环结构（二级），模拟法、字符串（三级）

## 分析

把密码合规条件的拆解思路展开得更细致，明确每一条文字要求如何转化为**可落地的编程判断逻辑**，同时解释拆解的底层思路（比如为什么这么拆、如何避免漏判/误判），适配GESP C++三级的解题场景。

### 密码合规条件的详细拆解思路
密码合规的3个核心要求，本质是“从不同维度对密码进行约束”，拆解的核心原则是：**把模糊的自然语言要求，转化为“可量化、可判断、无歧义”的编程条件**，同时兼顾验证效率（先筛掉明显不合规的，减少无效计算）。

#### 一、先明确拆解的整体逻辑：“分层验证，先快后慢”
为什么要分层拆解？因为不同条件的验证成本不同：
- 「长度条件」：只需1次`length()`调用，无需遍历字符，验证成本最低；
- 「字符范围条件」：需要遍历每个字符，但只要发现1个违规字符就能立即终止验证；
- 「类型组合条件」：需要遍历所有字符统计类型，验证成本最高。

因此拆解时，先处理“低成本、易判断”的条件，再处理“高成本、需统计”的条件，能大幅提升程序效率（尤其适合GESP考试中“输入长度不超过100”的场景）。

---

#### 二、逐条拆解合规条件（文字→代码判断逻辑）
##### 条件1：字符范围合规（只能由指定字符构成）
**原始要求**：只能由a-z小写字母、A-Z大写字母、0-9数字、!@#$四个特殊字符构成。
###### 拆解步骤1：明确“允许集”和“禁止集”
- 允许集（4类）：必须精准定义，避免歧义：
  | 类别       | 包含内容                | C++判断逻辑（核心）| 补充说明（GESP考点）|
  |------------|-------------------------|---------------------------------------|--------------------------|
  | 小写字母   | a-z（26个）| `c >= 'a' && c <= 'z'`                | 基于ASCII码范围，无需库函数 |
  | 大写字母   | A-Z（26个）| `c >= 'A' && c <= 'Z'`                | 同上，ASCII码A=65，Z=90 |
  | 数字       | 0-9（10个）| `c >= '0' && c <= '9'`                | ASCII码0=48，9=57        |
  | 特殊字符   | !、@、#、$（仅4个）| `c == '!' || c == '@' || c == '#' || c == '$'` | 必须逐个匹配，不能漏/多 |
- 禁止集：所有不在上述4类中的字符（如&、^、*、空格等）。

###### 拆解步骤2：转化为验证逻辑
遍历密码的**每一个字符**，执行以下判断：
```cpp
// 假设当前字符为c
bool is_valid_char = (c >= 'a' && c <= 'z') ||   // 小写
                     (c >= 'A' && c <= 'Z') ||   // 大写
                     (c >= '0' && c <= '9') ||   // 数字
                     (c == '!' || c == '@' || c == '#' || c == '$'); // 特殊字符
if (!is_valid_char) {
    // 只要有1个字符违规，整个密码直接不合规
    break;
}
```
###### 拆解避坑点：
- 不要遗漏特殊字符的范围（比如只判断!和@，漏掉#和$）；
- 不要把“特殊字符”扩大化（比如把&、^也纳入，样例中的123&^YUhg@!就是因为&、^违规）；
- GESP三级不建议用`isalpha()`/`isdigit()`等库函数（部分考场环境可能不熟悉），直接用ASCII码范围更稳妥。

---

##### 条件2：长度合规（6-12个字符）
**原始要求**：密码最短6个字符，最长12个字符。
###### 拆解步骤1：明确量化标准
- 最小值：密码长度 ≥ 6（包含6）；
- 最大值：密码长度 ≤ 12（包含12）；
- 核心：“长度”指**字符个数**，C++中`string`的`length()`/`size()`方法直接返回该值。

###### 拆解步骤2：转化为验证逻辑
```cpp
string password = "seHJ12!@";
if (password.length() < 6 || password.length() > 12) {
    // 长度不合规，直接排除
    continue; // 跳过后续所有验证
}
```
###### 拆解优先级：
这是**最高优先级**的验证条件！因为：
- 样例中的`sdf!@&12HDHa!`长度13，只需1次判断就能排除，无需遍历字符；
- 即使密码有100个字符，只要长度超12，直接跳过，节省大量计算。

---

##### 条件3：类型组合合规（至少两种字母/数字 + 至少1个特殊字符）
**原始要求**：大写字母、小写字母和数字必须至少有其中两种，以及至少有四个特殊字符中的一个。
###### 拆解步骤1：拆分复合要求
这个条件是“且”关系，需拆为两个子条件，**必须同时满足**：
- 子条件A：至少有1个!@#$中的特殊字符；
- 子条件B：大写、小写、数字三类中，至少包含两类。

###### 拆解步骤2：子条件A（特殊字符存在性）的验证逻辑
用**布尔标记变量**（初始为false）统计“是否存在”，而非“存在多少个”（因为只需要“至少1个”）：
```cpp
bool has_special = false; // 标记是否有特殊字符
for (char c : password) {
    if (c == '!' || c == '@' || c == '#' || c == '$') {
        has_special = true;
        // 只要找到1个，就无需再判断，可提前终止（可选优化）
        break;
    }
}
if (!has_special) {
    // 无特殊字符，不合规
    continue;
}
```

###### 拆解步骤3：子条件B（字母/数字组合）的验证逻辑
这是最容易出错的点，核心是“统计‘存在性’的数量”，而非“字符个数”：
1. 定义3个布尔标记变量（初始为false），分别标记三类字符的“存在性”：
   ```cpp
   bool has_upper = false; // 大写字母
   bool has_lower = false; // 小写字母
   bool has_digit = false; // 数字
   ```
2. 遍历密码字符，更新标记：
   ```cpp
   for (char c : password) {
       if (c >= 'A' && c <= 'Z') has_upper = true;
       else if (c >= 'a' && c <= 'z') has_lower = true;
       else if (c >= '0' && c <= '9') has_digit = true;
       // 特殊字符无需处理
   }
   ```
3. 统计“为true的标记数量”，判断是否≥2：
   ```cpp
   // 计算有效类型数
   int valid_type_count = 0;
   if (has_upper) valid_type_count++;
   if (has_lower) valid_type_count++;
   if (has_digit) valid_type_count++;
   
   if (valid_type_count < 2) {
       // 仅1类，不合规
       continue;
   }
   ```

###### 拆解避坑点：
- 错误思路1：统计“字符个数”（比如统计大写字母有多少个）→ 没必要，只要“存在”即可；
- 错误思路2：判断“是否同时有大写和小写”→ 漏判（比如“小写+数字”也符合要求）；
- 正确逻辑：只要三类中“至少两类存在”，无论哪两类都符合。

---

#### 三、组合所有拆解条件（完整验证流程）
将上述拆解的条件按“优先级”组合，形成完整的密码验证逻辑：
```cpp
bool is_password_valid(string password) {
    // 步骤1：验证长度（最高优先级）
    if (password.length() < 6 || password.length() > 12) {
        return false;
    }
    
    // 步骤2：验证字符范围 + 统计类型标记
    bool has_lower = false, has_upper = false, has_digit = false, has_special = false;
    for (char c : password) {
        // 先判断字符是否合规
        if ((c >= 'a' && c <= 'z')) {
            has_lower = true;
        } else if ((c >= 'A' && c <= 'Z')) {
            has_upper = true;
        } else if ((c >= '0' && c <= '9')) {
            has_digit = true;
        } else if (c == '!' || c == '@' || c == '#' || c == '$') {
            has_special = true;
        } else {
            // 字符违规，直接返回false
            return false;
        }
    }
    
    // 步骤3：验证类型组合
    int valid_type_count = (has_upper ? 1 : 0) + (has_lower ? 1 : 0) + (has_digit ? 1 : 0);
    return has_special && (valid_type_count >= 2);
}
```

### 总结
密码合规条件拆解的核心要点：
1. **维度拆分**：将3个核心要求拆为“长度、字符范围、类型组合”3个独立维度，每个维度转化为可量化的判断逻辑；
2. **优先级排序**：先验证“低成本”的长度/字符范围，再验证“高成本”的类型组合，提升效率；
3. **标记统计法**：对“存在性”类要求（如是否有特殊字符、是否有大写字母），用布尔变量标记，而非统计个数，简化逻辑。

通过这样的拆解，能把模糊的文字要求转化为清晰的代码逻辑，既符合GESP C++三级的考点要求，又能避免漏判、误判。
