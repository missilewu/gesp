# GESP三级C++考试核心考点整合总结（2023-2025）
## 一、数据编码：原码、反码、补码

### （一）核心知识点

1. 定义与表示规则
   - 原码：最高位为符号位（0正1负），剩余位为数值绝对值的二进制表示；8位原码范围-127~127，零有正零（`00000000`）和负零（`10000000`）两种表示。
   - 反码：正数反码=原码；负数反码=符号位不变+其余位按位取反；8位反码范围`-127~127`，零同样有两种表示，零有正零（`00000000`）和负零（`11111111`）两种表示
   - 补码：正数补码=原码；负数补码=反码+1；8位补码范围`-128~127`，零仅一种表示（`00000000`），核心作用是将减法转化为加法，简化硬件设计。
1. 关键特性与运算
   - 运算特性：补码符号位参与运算，可通过`a-b=a+(-b)`实现减法转加法。
   - 溢出判断：符号位无进位但次高位有进位→上溢；符号位有进位但次高位无进位→下溢；两者均有进位→结果有效。
   - 存储意义：计算机中负数以补码存储，避免“-0”问题。
3. 编码延伸
   - 编码多样性：除原码、反码、补码外，还有格雷码（通信场景）、哈夫曼编码（数据压缩）、Base64编码（二进制分组）、UTF-8编码（多字节分组）。
   - 无符号数编码：8位无符号二进制范围`0~255`，与有符号数转换规则为“无符号数=有符号数+2⁸（负数时）”。
   - 多字节补码范围：16位（`-32768~32767`）、32位（`-2³¹~2³¹-1`），对应C++中`short`、`int`类型底层存储。

### （三）高频易错点

1. 编码认知局限：误以为数据编码仅原码、反码、补码三种，忽略格雷码、哈夫曼编码等类型。
2. 概念混淆：混淆“数据编码”与“字符编码”（如ASCII码属于字符编码，非原码/反码/补码范畴）。
3. 计算错误：负数反码误将符号位取反；负数补码未执行“反码+1”，直接用原码替代；补码转真值漏做“补码-1→反码”步骤。
4. 范围误解：混淆n位原码与补码范围（补码多一个最小值，如8位补码可表示`-128`，原码不可）；误将8位原码最小数认为是`-128`（实际为`-127`）。
5. 核心作用误解：将补码“增加数值表示范围”当作核心作用，忽略其“简化加减法运算”的本质。
6. 溢出判断失误：无法区分符号位与次高位进位组合对应的溢出类型，误判运算结果有效性。

### （四）相关知识点

1. 补码与十进制双向转换：已知补码求原码（负数：补码-1→反码→数值位取反→原码）。
2. 不同位数补码扩展：短整数补码扩展为长整数时，高位补符号位（如16位补码FFFB扩展为32位仍为FFFFFFFB）。
3. 编码对比：GBK编码（中文2字节）与UTF-8编码（中文3字节）的差异；Base64编码规则（3字节输入→4字节输出，不足补=）。
4. 有符号/无符号数转换：基于补码存储逻辑，明确正负数值转换时的二进制位变化。

## 二、进制转换：二进制、八进制、十进制、十六进制

### （一）核心知识点

1. 基础转换规则
   - 非十进制→十进制：整数部分按位加权求和（位×进制^位权），小数部分按位×进制^(-位权)。
   - 十进制→其他进制：整数部分“除基取余，逆序排列”，小数部分“乘基取整，顺序排列”。
   - 二进制↔八进制/十六进制：3位二进制=1位八进制，4位二进制=1位十六进制（不足补0）。
2. C++进制操作
   - 进制字面量：0开头为八进制（如075）、0x开头为十六进制（如0x70）、0b开头为二进制（C++11及以上，如0b1101）、无前缀为十进制。
   - 进制输出：使用oct（十进制→八进制）、hex（十进制→十六进制）流操作符（需包含<iostream>）。
3. 关联编码进制逻辑
   - Base64编码：6位二进制分组，编码后长度=ceil(输入长度/3)×4。
   - UTF-8编码：1-4字节分组，1字节前缀0xxxxxxx，2字节前缀110xxxxx+10xxxxxx等。
4. 多进制判断：根据字符串中最大字符确定合法进制（二进制≤'1'、八进制≤'7'、十进制≤'9'、十六进制≤'F'）。

### （三）高频易错点
1. 转换步骤错误：16进制转8进制未先转二进制分组；二进制转八进制/十六进制分组方向错误（应从右往左分组，整数部分左侧补0，小数部分右侧补0）。
2. 小数转换失误：二进制小数转十进制时，误按整数位权计算（如0.101误算为5，实际为0.625）；十进制小数转二进制未逐次乘2取整至小数部分为0。
3. 字面量混淆：误将075当作十进制75（实际八进制075=61）、0x70当作十进制70（实际十六进制0x70=112）；混淆0（八进制）、0x（十六进制）、0b（二进制）前缀。
4. 认知错误：误以为“非2的整数次幂的十进制数无法转二进制”，忽略任意进制可相互转换的本质；记错八进制最大数字（误记为8，实际为7）。
5. 编码长度计算错误：Base64编码忽略补位规则，未对不足3字节的情况向上取整。

### （四）相关知识点
1. 快捷转换技巧：十六进制↔二进制（1位对应4位）、八进制↔二进制（1位对应3位）；十进制0~15对应十六进制0~F、二进制0000~1111。
2. 进制位权公式：对于R进制数\(d_{n}d_{n-1}...d_{1}d_{0}\cdot d_{-1}...d_{-m}\)，十进制值=Σdᵢ×Rⁱ（i从-n到m）。
3. 高精度进制转换：超出int范围的大数转换（用字符串存储，手动模拟运算）。
4. 编码与进制关联：ASCII（1字节=8位）、GBK（中文2字节=16位）、UTF-8（中文3字节=24位）的底层进制逻辑。
5. 进制运算原则：不同进制数直接运算需先转换为同一进制，避免出错。

## 三、位运算：与(&)、或(|)、非(~)、异或(^)、左移(<<)、右移(>>)
### （一）核心知识点
1. 基础运算符功能与特性
   - 与(&)：对应位均为1则为1；实用场景：清位、判断奇偶（x&1=1为奇数，0为偶数）、a&0=0、a&全1=a。
   - 或(|)：对应位有1则为1；实用场景：置位、a|0=a、a|全1=全1。
   - 非(~)：按位取反（0↔1）；规则：~x=-x-1，有符号数需结合补码解读。
   - 异或(^)：对应位不同则为1；核心特性：a^a=0、a^0=a、a^b^b=a（两次异或恢复原值）；实用场景：无临时变量交换变量（a=a^b;b=a^b;a=a^b）、判断a==b（a^b==0）。
   - 左移(<<)：整体左移n位，右补0；等价于x×2ⁿ（无溢出时），可能溢出。
   - 右移(>>)：算术右移（有符号数左补符号位，等价于x÷2ⁿ）、逻辑右移（无符号数左补0）。
2. 关键规则与公式
   - 优先级：位运算优先级低于算术运算和关系运算，高于逻辑运算（如a+b&c等价于(a+b)&c，需加括号明确顺序）。
   - 短路求值区别：&&（逻辑与，短路）与&（按位与，非短路）、||（逻辑或，短路）与|（按位或，非短路）不可混用。
   - 核心公式：(x&y)+(x|y)=x+y（简化枚举类编程题）。
3. 应用场景
   - 实用技巧：清最低位1（x&(x-1)）、置位第k位（a|(1<<k)）、清第k位（x&~(1<<k)）、提取低4位（a&0x0F）、求最大公约数（gcd(a,b)=gcd(b,a^b)）、判断2的整数次幂（(x&(x-1))==0且x≠0）。
   - 进阶应用：权限控制（每一位对应一个权限）、位图存储、快速幂算法、数据加密、状态压缩。

### （三）高频易错点
1. 运算符混淆：将&与&&、|与||混用；误将a&~1（清最低位）判为置位，a|10（置右数第2位）判为清位。
2. 右移理解错误：认为负数右移高位补0（实际算术右移补符号位）；误以为右移后左移能恢复原值（忽略低位清零，如5>>1=2，2<<1=4≠5）。
3. 非运算误算：仅考虑8位取反（如~1误算为11111110），忽略实际为32/64位取反（结果为-2）。
4. 优先级失误：未加括号导致执行顺序错误（如a^b&c等价于a^(b&c)，而非(a^b)&c）；误将a+b&c算为a+(b&c)。
5. 交换逻辑错误：异或交换变量遗漏三步操作，或误用与/或运算实现交换，导致变量值丢失。
6. 溢出忽略：左移时未考虑int类型取值范围（如32位int左移31位可能溢出），导致原值恢复失败。
7. 数据类型误解：浮点数不支持位运算，仅整数类型（char、short、int等）可进行位运算。

### （四）相关知识点
1. 逻辑运算符与位运算符区别：逻辑运算符有短路特性，结果为bool值；位运算符无短路特性，按位运算，结果为整数。
2. 跨平台差异：不同编译器对有符号数右移实现可能不同，优先使用无符号数避免歧义。
3. 位运算与算术运算关系：a|b与a+b相等的条件是a和b无重叠的1位（如3|16=3+16=19）。
4. 负数与无符号数运算：负数以补码参与运算，无符号数按全二进制位处理（如unsigned int -1存储为全1）。
5. 32位int位运算边界：取值范围-2³¹~2³¹-1，左移时注意符号位（负数左移可能变为正数）。

## 四、算法与描述
### （一）枚举法、模拟法
#### 1. 核心知识点
- 枚举法（穷举法）：逐一验证所有可能情况，筛选符合条件的解；适用场景：数据量小、条件明确（如完全平方数枚举、素数判断、三位数数位拆分）；优化技巧：缩小枚举范围、利用数学性质剪枝、二分枚举（有序解空间）。
- 模拟法：按题目规则分步实现逻辑，还原问题过程；适用场景：字符串处理、编码转换、状态跟踪（如密码合规检测、储蓄罐存钱统计、日历制作）；实施步骤：抽象场景→数据建模→流程实现→特殊处理。
- 关联算法：贪心算法（分糖果问题、活动安排、找零问题），核心是局部最优推全局最优（如a[i]=max(a[i-1]+1,a[i])）。
- 时间复杂度：枚举法（O(n)、O(n²)）、模拟法（O(n)），适配GESP三级数据范围（如n<10）。

#### 3. 高频易错点
- 循环边界错误：枚举“n到m包含两端”时，循环起始为i=n+1（遗漏n）或i<=n（数组越界）；模拟循环条件写反（如奇偶校验while(c>=0)导致无限循环）。
- 变量初始化遗漏：计数变量（res、count）未初始化为0，导致结果随机；数组找最值时初始值错误。
- 模拟步骤遗漏：忽略特殊情况（如春游问题“所有同学到达”需输出N、密码合规检测遗漏特殊字符限制）；未区分“小朋友自身需求”导致贪心逻辑不完整。
- 效率问题：枚举法未优化范围（如小猫分鱼未逆向枚举），导致程序运行时间过长；未利用位运算公式（如(x&y)+(x|y)=x+y），增加代码复杂度。
- 嵌套循环混乱：外层与内层循环变量混淆，执行顺序错误导致输出偏差。

#### 4. 相关知识点

- 算法时间复杂度分析：根据数据范围选择合适算法（n<=1e5时需优化至O(n)）。

## 五、数据结构：C++一维数组（不包含变长数组）
### （一）核心知识点
1. 基础特性与声明规则
- 声明规则：数据类型 数组名[数组长度]，长度为编译时常量（不可为变量）；合法定义：明确长度+初始化（int a[5]={1,2}）、省略长度+初始化（int a[]={1,2,3}）、字符作为下标（int a['3']等价于int a[51]）；非法定义：[]内用小数、省略长度且无初始化、类型写在[]后。
- 初始化规则：完全初始化（所有元素显式赋值）、部分初始化（未赋值元素默认0）、全局数组未初始化默认0、局部数组未初始化为随机值、字符数组部分初始化未显式赋值元素默认'\0'。
- 内存特性：元素连续存储，下标从0开始（合法范围0~n-1），支持随机访问；总字节数=元素个数×单个元素字节数（char1字节、int4字节、long long8字节、double8字节）。

2. 核心操作
- 基础操作：遍历（正向/逆向for/while循环）、赋值、条件筛选、求和/求最值、元素计数。
- 特殊操作：最大值/最小值索引查找（初始化索引变量，遍历更新）、双指针法（分离奇偶元素）、嵌套循环（二维逻辑一维实现，如日历输出）。
- 长度计算：sizeof(a)/sizeof(a[0])（普通数组）、strlen（字符数组，不含'\0'）。

### （三）高频易错点
1. 越界访问：循环条件写为i<=n（如int a[10]遍历i<=10，访问a[10]）；认为越界访问会编译错误（实际为运行时错误）。
2. 初始化误解：认为int a[10]={1}所有元素为1（实际仅a[0]=1，其余为0）；局部数组未初始化认为元素为0（实际为随机值）；试图用变量作为数组长度（如int n=5;int arr[n];非标准C++）。
3. 长度计算错误：用strlen计算普通数组长度；字符数组长度误算为定义长度（如char str[20]={'G','E','S','P'}长度为4，非20）。
4. 下标与计数混淆：数组存储元素时，索引与计数变量混淆（如arr[i]=count++应为arr[count++]=i）。
5. 变量作用域错误：循环内定义计数变量（如for循环内定义sum=0，每次循环重置）。
6. 数组名误解：将数组名当作首元素输出（实际为内存地址）；用==比较两个数组内容（实际比较地址）。
7. 双指针错误：分离奇偶元素时，右指针判断条件写反（找偶数而非奇数）。

### （四）相关知识点
1. 数组与指针关系：数组名本质是指向首元素的常量指针（a[i]==*(a+i)），支持指针算术运算（a+1指向a[1]）。
2. 内存管理：静态数组存储在栈区，大数组（n<=1e5）建议定义为全局变量或用vector，避免栈溢出；可使用ios::sync_with_stdio(false)加速输入。
3. 动态数组替代：C++ vector类（动态调整大小，vector<int> arr(n)）。
4. 数组延伸操作：数组去重（双指针法）、两数之和（有序数组双指针法）、数组反转（首尾交换）。
5. 越界危害：程序崩溃、数据污染（修改其他变量内存）、结果不确定。

## 六、字符串及其函数：大小写转换、字符串搜索、分割、替换等
### （一）核心知识点
1. 字符串存储类型
- 字符数组（char[]）：需以'\0'结尾，长度=实际字符数+1；赋值需用strcpy，比较需用strcmp，长度用strlen（不含'\0'）或sizeof（含'\0'）。
- string类（推荐）：自动管理长度和'\0'，支持动态操作；支持直接赋值（=）、拼接（+）、比较（==），长度用length()/size()（不含'\0'）。
- 编码相关：字符数为有效字符个数（与编码无关）；字节数与编码相关（ASCII英文1字节、GBK中文2字节、UTF-8中文3字节）。

2. 核心操作与函数
- 大小写转换：单个字符（tolower(c)、toupper(c)，需包含<cctype>）；字符串（transform(s.begin(),s.end(),s.begin(),::tolower)，需包含<algorithm>）；手动转换（str[i]+='A'-'a'（小写→大写）、str[i]+='a'-'A'（大写→小写））。
- 搜索：find(char/str)（从开头查找，返回索引，未找到返回string::npos）、rfind(char/str)（从末尾查找）。
- 替换与截取：replace(pos, len, str)（从pos开始替换len个字符）、substr(pos, len)（从pos开始截取len个字符，len省略则截取至末尾）。
- 其他操作：insert(pos, str)（插入字符串）、erase(pos, len)（删除字符）、append(str)（追加字符串）、compare(str)（比较字符串，返回0相等）。
- 分割：按分隔符（如逗号、.）拆分，通过find+substr循环实现。

### （三）高频易错点
1. 字符与ASCII混淆：将字符当作数字处理（如"0629"求和误算0+6+2+9=17，实际48+54+50+57=209）；字符判断用连续比较（'A'<=c<='Z'等价于('A'<=c)<='Z'，恒为true，正确为('A'<=c)&&(c<='Z')）。
2. 函数参数误解：replace(pos, len, str)误将len当作结束索引；substr(pos, len)误将len当作结束索引；rfind函数误取首次出现下标而非最后一次。
3. 长度混淆：strlen（字符数组，不含'\0'）与sizeof（含'\0'）混用；误将字符串字节数当作字符数（如“GESP考试”字符数6，UTF-8字节数10）。
4. 转义字符错误：字符串中包含单引号未用\'转义；混淆单双引号（单引号仅包裹单个字符）。
5. 存储与赋值错误：字符数组用=直接赋值、==比较内容；string越界访问（下标超过length()-1）。
6. 分割遗漏：按分隔符分割时遗漏最后一段（如“a,b,c”遗漏“c”）。
7. 大小写遗漏：词频统计时未转换大小写（Apple与apple视为不同单词）。

### （四）相关知识点
1. 字符数组与string类区别
| 特性 | 字符数组（char[]） | string类 |
| --- | --- | --- |
| 结束标记 | 需手动添加'\0' | 自动管理，无需'\0' |
| 长度获取 | strlen()（不含'\0'）、sizeof()（含'\0'） | length()/size()（不含结束符） |
| 赋值方式 | 不能整体赋值，需逐个元素或strcpy | 支持直接赋值（=）、拼接（+） |
| 动态修改 | 长度固定，修改需重新定义或strcat | 支持push_back、append、replace等 |
| 越界检测 | 无自动检测，需手动控制 | 部分编译器支持越界检测 |

2. 转义字符表：\'（单引号）、\"（双引号）、\n（换行）、\\（反斜杠）。
3. 字符串分割优化：长字符串（n<=1e5）用find+substr循环拆分，避免字符串流（效率低）。
4. 词频统计优化：使用unordered_map<string, int>（哈希表，查询效率O(1)）。
5. 字符串格式化：sprintf（字符数组）、stringstream（string类，需包含<sstream>）。
6. 编码兼容：统一编码格式（如UTF-8），避免中文乱码；ASCII、GBK、UTF-8编码差异对比。
7. 字符类型转换：字符转数值（int num=c-'0'）、数值转字符（char c=num+'0'）。
