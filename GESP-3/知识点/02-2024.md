
# 2024年GESP三级C++全年考试知识点整合总结（按知识块分类）
## 一、数据编码：原码、反码、补码
### （一）核心知识点
1. 定义：
   - 原码：符号位（0正1负）+ 数值绝对值的二进制表示；
   - 反码：正数反码=原码，负数反码=符号位不变+其余位取反；
   - 补码：正数补码=原码，负数补码=反码+1（解决减法转加法问题）。
2. 运算特性：补码可将减法运算转化为加法运算，简化计算机硬件设计；
3. 存储意义：计算机中负数以补码形式存储，避免“-0”问题；
4. 编码范围：n位补码范围为$-2^{n-1} \sim 2^{n-1}-1$（如16位补码：$-32768\sim32767$）。

### （三）高频易错点
1. 负数反码计算错误：误将符号位一同取反（正确：符号位不变，仅数值位取反）；
2. 补码计算步骤遗漏：负数补码未执行“反码+1”，直接将原码当作补码；
3. 原码/补码解读混淆：如12月第1题`[10000011]原`与补码的十进制值易搞反；
4. 编码范围误解：混淆n位原码与补码的范围（补码范围比原码多一个最小值，如16位补码可表示-32768，原码不可）。

### （四）相关知识点
1. 补码与十进制的双向转换：已知补码求原码（负数：补码-1→反码→原码）；
2. 加减法运算原理：$a - b = a + (-b)$（将减法转化为补码加法）；
3. 不同位数补码的扩展：短整数补码扩展为长整数时，高位补符号位（如16位补码`FFFB`扩展为32位仍为`FFFFFFFB`）。

## 二、进制转换：二进制、八进制、十进制、十六进制
### （一）核心知识点
1. 互转规则：
   - 十进制→二进制/八进制/十六进制：整数部分“除基取余，逆序排列”，小数部分“乘基取整，顺序排列”；
   - 二进制→八进制/十六进制：3位二进制=1位八进制，4位二进制=1位十六进制（不足补0）；
   - 八进制/十六进制→十进制：按位加权求和（基数^位权）。
2. 进制字面量：`0`开头为八进制（如`075`），`0x`开头为十六进制（如`0x70`），无前缀为十进制。

### （三）高频易错点
1. 多进制中转错误：16进制转8进制未先转二进制分组（如12月第3题，正确步骤：16进制→二进制→3位分组→8进制）；
2. 小数转二进制漏步骤：如9月第4题0.8125转二进制，未逐次乘2取整至小数部分为0；
3. 字面量混淆：误将`075`当作十进制75（实际八进制`075=61`）、`0x70`当作十进制70（实际十六进制`0x70=112`）；
4. 分组方向错误：二进制转八进制/十六进制时，从右往左分组，不足位在左侧补0（整数部分）或右侧补0（小数部分）。

### （四）相关知识点
1. 快捷转换技巧：
   - 十六进制↔二进制：1位十六进制对应4位二进制（如`0xF=1111`）；
   - 八进制↔二进制：1位八进制对应3位二进制（如`07=111`）；
2. 进制范围对应：十进制0~15对应十六进制0~F、二进制0000~1111；
3. 浮点进制转换：了解十进制小数无法精确表示的原因（如0.1的二进制是无限循环小数）。

## 三、位运算：与(&)、或(|)、非(~)、异或(^)、左移(<<)、右移(>>)
### （一）核心知识点
1. 运算符功能：
   - 与（&）：对应位均为1则为1（用于清位、判断奇偶）；
   - 或（|）：对应位有1则为1（用于置位）；
   - 非（~）：按位取反（正数→负数，负数→正数，`~x = -x-1`）；
   - 异或（^）：对应位不同则为1（用于交换变量、翻转位）；
   - 左移（<<）：整体左移n位，右补0（等价于`x*2^n`，无溢出时）；
   - 右移（>>）：算术右移（负数左补符号位，正数左补0），等价于`x//2^n`。
2. 应用场景：变量交换、位操作（置位/清位）、数值运算优化。

| 2024.12  | 第5题（位运算结果判断）、第6题（补码右移运算）、第8题（a|10功能） |

### （三）高频易错点
1. 运算符功能混淆：如将`a&~1`（清最低位为0）误判为置位，`a|10`（置右数第2位为1）误判为清位；
2. 右移符号位补位错误：认为负数右移时高位补0（实际算术右移补符号位），如9月第4题-5<<1>>1仍为-5；
3. 优先级误解：混淆位运算与逻辑运算优先级（如`5&&3==0`实际是`5&&(3==0)`）；
4. 异或用途误解：将异或三次交换变量（`a^=b;b^=a;a^=b`）误判为异或运算，而非变量交换；
5. 非运算结果误算：认为`~1`的二进制是`11111110`（仅考虑8位），忽略实际是32/64位取反，结果为-2。

### （四）相关知识点
1. 实用位运算技巧：
   - 交换变量：`a^=b;b^=a;a^=b`（无临时变量）；
   - 清最低位1：`a&(a-1)`（判断2的幂次：`(x&(x-1))==0`）；
   - 置位第k位：`a|(1<<k)`；
   - 提取低4位：`a&0x0F`。
2. 位运算与算术运算区别：`a|b`与`a+b`相等的条件是a和b无重叠的1位（如3|16=3+16=19）；
3. 无符号数与负数位运算：负数以补码参与运算，无符号数按全二进制位处理（如9月第10题`unsigned int -1`存储为全1）。

## 四、算法与描述
### （一）枚举法、模拟法
#### 1. 核心知识点
- 枚举法：逐一验证所有可能情况，筛选符合条件的解（适用范围小、条件明确的问题）；
- 模拟法：按题目规则分步实现逻辑，还原问题过程（如字符串处理、编码转换）；

#### 3. 高频易错点
- 循环边界错误：如枚举“n到m包含两端”时，循环起始为`i=n+1`（遗漏n），或`i<=n`（数组越界）；
- 变量初始化遗漏：计数变量（如`res`、`count`）未初始化为0，导致结果随机；
- 条件判断不完整：如闰年判断漏“能被100整除但不能被400整除”的例外情况；
- 时间复杂度忽略：枚举法未优化（如编程题2`n=1000`时双重循环O(n²)可行，但需避免冗余计算）。

#### 4. 相关知识点
- 枚举法优化：缩小枚举范围（如找四位数“雷劈数”仅枚举1000~9999）、利用数学性质剪枝；
- 模拟法步骤拆解：将复杂问题拆分为“输入处理→逻辑执行→输出结果”三步骤；
- 前缀和优化：将枚举求和的O(n)优化为O(1)（如9月编程题1平衡序列判断）。

## 五、数据结构：C++一维数组（不包含变长数组）
### （一）核心知识点
1. 定义与初始化：`int a[10]`（固定长度）、部分初始化（`int a[10]={1}`）、全初始化（`int a[10]={1,2,...,10}`）；
2. 内存特性：数组元素在内存中连续存储，下标从0开始（合法范围`0~n-1`）；
3. 基本操作：遍历（正向/逆向）、赋值、条件筛选、求和/求最值、元素计数；
4. 长度相关：`sizeof(a)/sizeof(a[0])`计算数组长度，`strlen`计算字符数组有效长度（不含`'\0'`）。

### （二）关联考题

|----------|----------------|
| 2024.03  | 第6题（数组条件筛选）、第7题（数组逆序输出）、第11题（数组相邻元素和判断）、第12题（字符数组长度） |
| 2024.06  | 第10题（数组找最大值）、第11题（数组存储能被7整除的数）、第13题（数组身高筛选计数） |
| 2024.09  | 第12题（数组合法遍历）、第13题（数组越界访问）、编程题1（数组求最值与替换） |
| 2024.12  | 第10题（字符数组内存空间）、编程题1（数组元素替换） |

### （三）高频易错点
1. 越界访问：循环条件写为`i<=n`（如`int a[10]`遍历`i<=10`，访问`a[10]`），导致结果不确定；
2. 初始化规则误解：认为`int a[10]={1}`表示所有元素为1（实际仅`a[0]=1`，其余为0）；
3. 计数逻辑错误：数组存储元素时，索引与计数变量混淆（如6月第11题`arr[i]=count++`，正确为`arr[count++]=i`）；
4. 长度计算错误：用`strlen`计算普通数组长度（`strlen`仅适用于字符数组），或认为字符数组长度=定义长度（如`char str[20]={'G','E','S','P'}`长度为4，非20）；
5. 变量作用域错误：循环内定义计数变量（如`for(int i=0;i<10;i++){int sum=0;sum+=a[i];}`），导致每次循环重置。

### （四）相关知识点
1. 数组初始化规则：
   - 全局数组未初始化时，元素默认值为0；
   - 局部数组未初始化时，元素为随机值；
   - 字符数组部分初始化时，未显式赋值的元素默认是`'\0'`；
2. 越界风险：越界访问可能修改其他变量内存，导致程序崩溃或结果异常，需严格遵循`i < 数组长度`；
3. 数组与指针关系：数组名本质是指向首元素的指针（`a[i] == *(a+i)`）；
4. 大数据处理：`n<=1e5`时，数组需定义为全局变量（避免栈溢出），或用`ios::sync_with_stdio(false);`加速输入。

## 六、字符串及其函数：大小写转换、字符串搜索、分割、替换等
### （一）核心知识点
1. 字符串类型：`char`数组（`char str[20]`）、`string`类（推荐使用，支持动态长度）；
2. 核心操作：
   - 大小写转换：利用ASCII码（`str[i]+='A'-'a'`（小写→大写）、`str[i]+='a'-'A'`（大写→小写））、`toupper`/`tolower`函数；
   - 搜索：`string::find`（查找字符/子串，返回索引，未找到返回`string::npos`）；
   - 分割：按分隔符（如`.`）拆分字符串（`find`+`substr`）；
   - 替换：`string::replace(pos, len, str)`（从pos开始，替换len个字符为str）；
   - 长度：`string::length()`/`string::size()`（`string`类）、`strlen`（字符数组）。

### （三）高频易错点
1. 字符与ASCII码混淆：将字符当作数字处理（如6月第12题`"0629"`求和时，误算`0+6+2+9=17`，实际是`48+54+50+57=209`）；
2. 函数参数误解：
   - `replace(pos, len, str)`：误将`len`当作结束索引（如12月第7题`s.replace(1,5,str)`，从索引1开始替换5个字符）；
   - `substr(pos, len)`：误将`len`当作结束索引（正确：从pos开始截取len个字符，len省略则截取至末尾）；
3. 转义字符错误：字符串中包含单引号时，未用`\'`转义（如9月第14题`"They\'re"`），或混淆单双引号（单引号仅包裹单个字符）；
4. 字符串结束符误解：认为`ch[5]==NULL`与`ch[5]=='\0'`等价（`NULL`是指针空值，`'\0'`是字符串结束符，逻辑上不可等同）；
5. `find`返回值误判：未判断`find`返回`string::npos`，直接使用返回值（如未找到字符时，索引为无效值）。

### （四）相关知识点
1. `string`类常用函数拓展：
   - `substr(pos, len)`：如`"abcde".substr(1,3)`返回`"bcd"`；
   - `erase(pos, len)`：删除从pos开始的len个字符；
   - `append(str)`：在字符串末尾添加str；
   - `compare(str)`：比较两个字符串是否相等（返回0表示相等）；
2. 字符转换优化：使用`<cctype>`头文件的`toupper(c)`/`tolower(c)`（避免手动计算ASCII码误差）；
3. 转义字符表：
   - `\'`：单引号；`\"`：双引号；`\n`：换行；`\\`：反斜杠；
4. 字符串分割优化：对于长字符串（`n<=1e5`），使用`find`+`substr`循环拆分，避免使用字符串流（效率较低）；
5. 字符数组与`string`类区别：`string`类自动管理`'\0'`，支持动态扩容，无需手动计算长度，优先推荐使用。
