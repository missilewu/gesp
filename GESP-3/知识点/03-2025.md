
# 2025年GESP三级C++ 核心知识块整合总结
本文整合2025年3月、6月、9月三次GESP三级C++考试内容，按指定6大知识块梳理知识点、关联考题、易错点及延伸知识点，形成完整知识体系。

## 一、 数据编码：原码、反码、补码
### （一） 核心知识点
1.  **原码**
    -  表示规则：最高位为符号位（0=正、1=负），剩余位为数值位（直接表示绝对值）；
    -  关键特性：8位原码表示范围`-127~127`，零有两种表示（正零`00000000`、负零`11111111`）；
    -  示例：-5的8位原码为`10000101`，5的8位原码为`00000101`。
2.  **反码**
    -  转换规则：正数反码与原码一致；负数反码为“符号位不变，数值位按位取反”；
    -  关键特性：8位反码表示范围`-127~127`，零同样有正零、负零两种表示形式。
3.  **补码**
    -  转换规则：正数补码与原码一致；负数补码为“反码+1”（逆运算：补码-1→反码→数值位取反得原码）；
    -  关键特性：8位补码表示范围`-128~127`，零仅有一种表示（`00000000`）；核心作用是简化整数加减法（将减法转化为加法，符号位参与运算）；
    -  运算特性：正数补码算术右移等价于除以2（符号位保持不变）；溢出判断（符号位无进位但次高位有进位→上溢；符号位有进位但次高位无进位→下溢；两者均有进位→结果有效）。

### （三） 易错点
1.  原码与补码最小数混淆：误将8位原码最小数认为是`-128`（实际是`-127`，`-128`仅为8位补码最小数）；
2.  补码转真值步骤遗漏：计算负数补码对应的真值时，漏做“补码-1求反码”步骤，直接对补码数值位取反导致结果错误；
3.  反码零的表示误解：认为反码零仅有一种表示形式，忽略负零的存在；
4.  补码核心作用误解：将“增加数值表示范围”当作补码的核心作用，忽略其“简化加减法运算”的本质；
5.  补码溢出判断失误：无法区分“符号位进位”与“次高位进位”的组合对应的溢出类型，误判运算结果有效性。

### （四） 相关知识点
1.  无符号数编码：8位无符号二进制表示范围`0~255`，与有符号数转换规则（无符号数=有符号数+2⁸，当有符号数为负时）；
2.  编码延伸：Base64编码（基于二进制分组的编码方式，关联补码二进制存储逻辑）、GBK编码（中文2字节编码，与UTF-8的差异对比）；
3.  多字节补码：16位/32位补码的表示范围（16位：`-32768~32767`，32位：`-2³¹~2³¹-1`），对应C++中`short`、`int`类型的底层存储。

## 二、 进制转换：二进制、八进制、十进制、十六进制
### （一） 核心知识点
1.  **基础进制转换规则**
    -  非十进制→十进制：整数部分按对应进制的幂次累加（从右往左，位权为`进制^0`、`进制^1`...）；小数部分按对应进制的负幂次累加（从左往右，位权为`进制^-1`、`进制^-2`...）；
    -  十进制→二进制：整数部分“除2取余，逆序排列”；小数部分“乘2取整，顺序排列”；
    -  二进制→八进制/十六进制：二进制转八进制（每3位一组，不足补0）；二进制转十六进制（每4位一组，不足补0），反向转换同理。
2.  **C++进制操作**
    -  进制输出：使用`oct`（十进制→八进制）、`hex`（十进制→十六进制）流操作符（需包含`<iostream>`）；
    -  二进制直接声明：C++11及以上支持`0b`前缀表示二进制数（如`0b1101`表示十进制13）；
    -  十六进制声明：`0x`前缀（如`0x1A`表示十进制26）。
3.  **关联编码进制逻辑**
    -  Base64编码：基于6位二进制分组（对应64个字符），每3字节输入→4字节输出，不足3字节用`=`补位，编码后长度=`ceil(输入长度/3)×4`；
    -  UTF-8编码：基于1-4字节二进制分组，不同长度字节有固定前缀标识（1字节：`0xxxxxxx`，2字节：`110xxxxx+10xxxxxx`等）。

### （三） 易错点
1.  小数部分进制转换失误：将二进制小数转十进制时，误按整数位权规则计算（如将`0.101`误算为`5`，实际为`0.625`）；
2.  Base64长度计算错误：忽略补位规则，仅按“输入长度÷3×4”计算，未对不足3字节的情况向上取整；
3.  进制前缀混淆：将八进制`0`前缀、十六进制`0x`前缀、二进制`0b`前缀记混，导致数值判断错误；
4.  二进制分组失误：二进制转八进制时按4位分组、转十六进制时按3位分组，导致转换结果偏差。

### （四） 相关知识点
1.  进制转换优化：十进制→任意进制的通用方法（除对应进制取余，逆序排列）；
2.  高精度进制转换：超出`int`范围的大数进制转换（使用字符串存储，手动模拟运算）；
3.  编码与进制的关联：ASCII编码（1字节=8位二进制）、GBK编码（中文2字节=16位二进制）、UTF-8编码（中文3字节=24位二进制）的底层进制逻辑；
4.  进制运算：不同进制数的直接运算（需先转换为同一进制再计算，避免直接运算出错）。

## 三、 位运算：与(&)、或(|)、非(~)、异或(^)、左移(<<)、右移(>>)
### （一） 核心知识点
1.  **基础位运算规则**
    -  按位与（`&`）：对应位均为1时结果为1，否则为0；实用特性：判断整数奇偶（`x&1=1`→奇数，`x&1=0`→偶数）、清除指定位；
    -  按位或（`|`）：对应位有1时结果为1，否则为0；实用特性：置1指定位；
    -  按位非（`~`）：对应位取反（0→1，1→0）；注意：有符号数按位非后需结合补码规则解读；
    -  按位异或（`^`）：对应位不同时结果为1，相同时为0；核心特性：`x^x=0`、`x^0=x`、支持无临时变量交换变量（`a=a^b;b=a^b;a=a^b;`）；
    -  左移（`<<`）：所有位向左移动n位，右侧补0，等价于`x×2ⁿ`（无溢出时）；
    -  右移（`>>`）：算术右移（有符号数）：左侧补符号位，等价于`x÷2ⁿ`；逻辑右移（无符号数）：左侧补0。
2.  **关键特性与公式**
    -  短路求值区别：`&&`（逻辑与，短路求值）与`&`（按位与，非短路，左右均执行）不可混用；`||`（逻辑或）与`|`（按位或）同理；
    -  核心公式：`(x & y) + (x | y) = x + y`（可简化枚举类编程题）；
    -  优先级：位运算优先级低于算术运算和关系运算，需加括号明确执行顺序（如`a&b+1`等价于`a&(b+1)`）。

### （三） 易错点
1.  位运算与逻辑运算混淆：将`&`当作`&&`用于逻辑判断，将`|`当作`||`使用，导致非预期结果（如`0&1=0`，但逻辑判断中可能因非短路执行浪费效率或出错）；
2.  异或交换变量方法记错：遗漏异或三次操作的步骤，或误用与、或运算实现交换，导致变量值丢失；
3.  位运算公式遗忘：编程题中未利用`(x&y)+(x|y)=x+y`公式，仍采用冗余枚举，增加代码复杂度；
4.  右移运算误解：认为有符号数右移等价于简单的除法，忽略符号位补位规则（如`-4>>1`结果为`-2`，而非`2`）；
5.  优先级失误：未加括号导致位运算执行顺序错误，如`a^b&c`误判为`(a^b)&c`，实际等价于`a^(b&c)`。

### （四） 相关知识点
1.  更多实用位运算公式：`x & (x-1)`（清除最低位的1，用于统计二进制1的个数优化）、`x | (1<<k)`（将第k位置1）、`x & ~(1<<k)`（将第k位清0）；
2.  位运算应用场景：权限控制（每一位对应一个权限）、位图存储（节省内存）、快速幂算法（利用左移实现幂次运算）；
3.  位运算与数据类型：浮点数不支持位运算，仅整数类型（`char`、`short`、`int`、`long`等）可进行位运算；
4.  跨平台位运算差异：不同编译器对有符号数右移的实现可能存在差异（优先使用无符号数进行位运算避免歧义）。

## 四、 算法与描述
### （一） 子模块1：枚举法、模拟法
1.  **核心知识点**
    -  枚举法（穷举法）
      -  核心逻辑：遍历所有可能的解空间，根据条件筛选符合要求的解；
      -  典型应用：三位数数位拆分（百位`i/100`、十位`(i/10)%10`、个位`i%10`）、最大值/最小值索引查找、美丽数字筛选（`a%9==0 && a%8!=0`）；
      -  优化技巧：明确枚举边界（减少无效遍历）、利用数学公式简化解空间（如位运算公式减少枚举范围）。
    -  模拟法
      -  核心逻辑：按照题目描述的步骤，一步步模拟操作流程，得到最终结果；
      -  典型应用：奇偶校验（统计二进制1的个数并判断奇偶）、数组清零、日历制作（月份天数存储、星期几计算、格式化输出）；
    -  关联贪心算法：分糖果问题（`a[i] = max(a[i-1]+1, a[i])`，局部最优推全局最优，GESP三级高频拓展算法）。

| 2025.06 | 单选题11题（三位数枚举筛选）、编程题1（奇偶校验模拟）、编程题2（分糖果贪心算法）                   |

3.  **易错点**
    -  枚举范围冗余：未缩小解空间，导致代码效率低下（如无需遍历1~2025，直接用公式求解）；
    -  模拟步骤遗漏：忽略题目中的关键约束（如分糖果未考虑“小朋友自身需求”，仅考虑“前一位+1”）；
    -  循环条件错误：模拟循环中条件写反（如奇偶校验循环条件`while(c>=0)`导致无限循环）；
    -  嵌套循环逻辑混乱：未理清外层与内层循环的执行顺序，导致输出结果偏差；
    -  贪心逻辑不完整：局部最优选择未满足全局约束，导致结果不符合题目要求。

4.  **相关知识点**
    -  枚举法优化：剪枝操作（提前排除不符合条件的解，减少遍历次数）、二分枚举（适用于有序解空间）；
    -  模拟法通用思路：明确操作步骤→抽象变量→确定循环边界→验证中间结果；
    -  贪心算法其他应用：活动安排问题、找零问题（需满足硬币面额贪心条件）；
    -  算法时间复杂度：枚举法（O(n)、O(n²)）、模拟法（O(n)）的时间复杂度分析，适配GESP三级数据范围。

## 五、 数据结构：C++一维数组(不包含变长数组)
### （一） 核心知识点
1.  **数组基础特性**
    -  声明规则：`数据类型 数组名[数组长度]`（数组长度为编译时确定的常量，不可为变量）；
    -  初始化规则：完全初始化（所有元素显式赋值）、部分初始化（未赋值元素默认初始化为0）、不允许空初始化（需指定长度或显式初始化）；
    -  下标规则：数组下标从0开始，最后一个元素下标为`数组长度-1`，支持随机访问。
2.  **数组核心操作**
    -  元素访问与修改：`arr[index]`（直接访问下标对应的元素，可读取或赋值）；
    -  遍历操作：使用for/while循环遍历数组，循环条件通常为`i < 数组长度`（避免下标越界）；
    -  特殊操作：
      -  最大值/最小值索引查找：初始化索引变量，遍历数组时更新索引；
      -  双指针法：分离奇偶元素（左指针找偶数、右指针找奇数，找到后交换）；
      -  嵌套循环：二维逻辑的一维数组实现（如日历制作的行/列输出）。

| 2025.03 | 单选题11题（数组最大值索引查找）、单选题12题（双指针法分离奇偶元素）                                                     |
| 2025.06 | 单选题10题（数组正确声明方式）、单选题11题（三位数枚举（数组存储候选值））                                               |
| 2025.09 | 数组与字符串题（数组初始化、下标访问、边界控制、嵌套循环遍历）                                                         |

### （三） 易错点
1.  数组下标越界：访问`arr[数组长度]`（如`int arr[5]`访问`arr[5]`），或循环条件写为`i <= 数组长度`，导致程序异常；
2.  初始化误区：忘记部分初始化时未赋值元素默认为0，或试图用变量作为数组长度声明（如`int n=5; int arr[n];`，非标准C++语法）；
3.  双指针条件写反：分离奇偶元素时，右指针判断条件写反（找偶数而非奇数），导致交换逻辑错误；
4.  数组元素比较错误：用`==`比较两个数组的内容（实际比较地址，需遍历元素逐一比较）；
5.  嵌套循环执行顺序混乱：外层与内层循环的循环变量混淆，导致输出结果不符合预期。

### （四） 相关知识点
1.  动态数组替代方案：C++`vector`类（动态调整大小，避免数组长度固定的限制，`vector<int> arr(n)`）；
2.  数组内存管理：静态数组存储在栈区，超出栈空间大小会导致栈溢出（大数组建议使用`vector`或动态分配内存）；
3.  数组延伸操作：数组去重（双指针法）、两数之和（有序数组双指针法）、数组反转（首尾交换）；
4.  数组与指针：C++中数组名本质是指向数组首元素的常量指针（`arr`等价于`&arr[0]`），支持指针算术运算（`arr+1`指向`arr[1]`）。

## 六、 字符串及其函数：大小写转换、字符串搜索、分割、替换等
### （一） 核心知识点
1.  **字符串基础**
    -  两种字符串类型：`string`类（C++标准库，便捷操作）与字符数组（`char[]`，底层存储）；
    -  核心区别：`string`支持直接赋值（`=`）、内容比较（`==`）、长度获取（`length()`/`size()`）；字符数组需使用`strcpy`、`strcmp`、`strlen`函数（需包含`<cstring>`）；
    -  字节数与字符数：字符数为有效字符个数（与编码无关）；字节数与编码相关（ASCII：英文1字节，GBK：中文2字节，UTF-8：中文3字节）。
2.  **核心函数与操作**
    -  大小写转换：`transform(s.begin(), s.end(), s.begin(), ::tolower)`（转小写）、`::toupper`（转大写，需包含`<algorithm>`和`<cctype>`）；单个字符转换：`tolower(c)`、`toupper(c)`；
    -  字符串搜索：`find(char/str)`（从开头查找，返回首次出现下标，未找到返回`string::npos`）、`rfind(char/str)`（从末尾查找，返回最后一次出现下标）；
    -  字符串替换：`replace(pos, len, str)`（从下标`pos`开始，替换`len`个字符为`str`）；
    -  字符串截取：`substr(pos, len)`（从下标`pos`开始，截取`len`个字符，长度不足时返回剩余字符）；
    -  其他常用函数：`insert(pos, str)`（在下标`pos`插入`str`）、`erase(pos, len)`（删除指定位置字符）。

### （三） 易错点
1.  函数参数混淆：`replace`/`substr`的`pos`（起始下标）与`len`（长度）记混，导致操作结果错误（如`substr(5,4)`误写为`substr(4,5)`）；
2.  大小写转换遗漏：词频统计时未转换大小写，导致`Apple`与`apple`被视为不同单词，统计结果错误；
3.  字符数组与`string`混用错误：用`==`比较两个字符数组的内容，或用`=`给字符数组赋值，导致编译错误或逻辑错误；
4.  字节数与字符数混淆：误将字符串字节数当作字符数（如“GESP考试”字符数为6，UTF-8字节数为10），导致选择题误选；
5.  `rfind`函数误解：将`rfind`当作`find`使用，误取首次出现的下标而非最后一次出现的下标。

### （四） 相关知识点
1.  更多`string`成员函数：`append(str)`（字符串追加）、`compare(str)`（字符串比较，返回0表示相等）、`clear()`（清空字符串）；
2.  字符串分割：无内置分割函数，可通过`find`+`substr`实现（按分隔符拆分字符串）；
3.  词频统计优化：使用`unordered_map<string, int>`（哈希表，查询效率O(1)，比`map`的O(logn)更高）；
4.  字符串格式化：`sprintf`（字符数组格式化）、`stringstream`（`string`类格式化，需包含`<sstream>`）；
5.  编码知识延伸：ASCII、GBK、UTF-8编码的兼容问题，避免中文乱码（统一编码格式）。
