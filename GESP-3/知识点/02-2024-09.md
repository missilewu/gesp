# GESP三级C++2024年9月考试逐题深度解析
## 一、单选题（共15题）
### 第1题
1. **考察的知识点**：数据结构（double类型浮点数精度特性）
2. **知识点详解**：C++中`double`类型遵循IEEE 754标准，采用64位存储（1位符号位、11位指数位、52位尾数位）。由于二进制浮点数无法精确表示部分十进制小数（如0.1、0.9），只能存储近似值。例如，0.9的二进制表示是无限循环小数，存储时会截断，导致1.0 - 0.9的结果并非精确的0.1，而是接近0.1的近似值，因此`(b - a) == 0.1`的判断结果为`false`。
3. **易错点**：
   - 误认为十进制小数的简单运算在浮点数中可精确实现，直接按数学逻辑判断相等。
   - 不了解浮点数的存储原理，忽略精度误差导致的判断错误。
4. **相关的知识点**：
   - 浮点数与整数的存储差异（整数无精度损失，浮点数可能有）。
   - 浮点数比较的正确方法：判断差值绝对值是否小于极小值（如`1e-9`），例：`fabs(b - a) < 1e-9`。
   - `float`与`double`的精度区别（`float`为32位，精度更低，误差更大）。

### 第2题
1. **考察的知识点**：数据编码（原码、反码、机器数与真值的定义）
2. **知识点详解**：
   - 机器数：计算机中存储的二进制数，包含符号位（最高位0为正、1为负），形式值与真值不一定一致（如负数的机器数）。
   - 原码：符号位 + 真值的绝对值，符号位不变，数值部分为真值的二进制表示。
   - 反码：正数的反码与原码相同；负数的反码为符号位不变，数值部分按位取反。
   - 选项分析：A错误（负数机器数与真值不一致）；B正确（原码定义）；C错误（机器数可无符号，如`unsigned int`）；D错误（[-1]原=10000001，反码=11111110，补码=11111111）。
3. **易错点**：
   - 混淆原码与反码的转换规则，误将负数反码当作补码。
   - 认为“机器数一定带符号”，忽略无符号类型的存在。
   - 对8位二进制数的范围（原码：-127~127，反码：-127~127，补码：-128~127）记忆错误。
4. **相关的知识点**：
   - 补码的计算（负数补码=反码+1）及优势（解决原码“+0”“-0”歧义，简化减法运算）。
   - 符号位的作用（区分正负，参与运算但不改变数值大小）。
   - 不同编码下的数值运算规则（原码加法需考虑符号，补码可直接加减）。

### 第3题
1. **考察的知识点**：进制转换（八进制转十六进制）
2. **知识点详解**：八进制转十六进制的核心是通过二进制中转（八进制1位对应二进制3位，十六进制1位对应二进制4位），步骤如下：
   - 第一步：将八进制数3703按每1位拆分为二进制（3→011，7→111，0→000，3→011），拼接得二进制数011 111 000 011（补前导0使总位数为4的倍数：0111 1100 0011）。
   - 第二步：将二进制数按每4位分组，转换为十六进制（0111→7，1100→C，0011→3），结果为7C3，对应选项A。
1. **易错点**：
   - 八进制转二进制时，未补够3位（如3直接写11，而非011），导致后续分组错误。
   - 二进制转十六进制时，分组方向错误（应从右往左分组，不足补前导0）。
   - 混淆十六进制字符（C对应12，A对应10，B对应11，D对应13）。
4. **相关的知识点**：
   - 各进制的表示标识（八进制以0开头，如03703；十六进制以0x开头，如0x7C3）。
   - 十进制中转法（八进制→十进制→十六进制）：3703(8)=3×8³+7×8²+0×8¹+3×8⁰=3×512+7×64+0+3=1536+448+3=1987(10)；1987÷16=124余3，124÷16=7余12（C），7÷16=0余7，逆序得7C3(16)。
   - 进制转换的验证方法（十六进制→二进制→八进制，反向核对）。

### 第4题
1. **考察的知识点**：进制转换（十进制小数转二进制）
2. **知识点详解**：十进制小数转二进制遵循“乘2取整，顺序排列”规则，步骤如下：
   - 0.8125×2=1.625→取整数部分1（高位）；
   - 0.625×2=1.25→取整数部分1；
   - 0.25×2=0.5→取整数部分0；
   - 0.5×2=1.0→取整数部分1（低位）；
   - 拼接整数部分得0.1101，对应选项D。
3. **易错点**：
   - 混淆“乘2取整”的顺序（应按计算顺序排列，先取的为高位）。
   - 遇到小数部分无法整除2时（如0.1），误以为能精确转换，导致无限循环。
   - 计算过程中遗漏步骤（如0.8125×2=1.625，误将小数部分当作0.625继续计算，而非正确取整）。
4. **相关的知识点**：
   - 十进制整数转二进制（除2取余，逆序排列），例：8→1000。
   - 二进制小数转十进制（按位乘2的负次幂求和），例：0.1101=1×2⁻¹+1×2⁻²+0×2⁻³+1×2⁻⁴=0.5+0.25+0+0.0625=0.8125。
   - 进制转换的应用场景（计算机存储、网络传输中常用二进制，编程中常用十六进制简化二进制表示）。

### 第5题
1. **考察的知识点**：位运算（与&、或|）、八进制数表示
2. **知识点详解**：
   - 位运算规则：&（按位与，全1为1）、|（按位或，有1为1）；八进制数以0开头（01表示十进制1，010表示十进制8）。
   - 选项分析：
     - A：22(10)=10110，01(8)=1(10)=00001，22&01=0；22&&01是逻辑与（非0为真），结果为真（1），0≠1，A错误。
     - B：23(10)=10111，11(10)=01011，10111|01011=11111(31)≠30，B错误。
     - C：23|10=10111|01010=11111(31)，C正确。
     - D：23|01=10111|00001=10111(23)≠31，D错误。
3. **易错点**：
   - 误将八进制01当作十进制11，导致数值计算错误。
   - 混淆位运算&与逻辑运算&&（位运算操作二进制位，逻辑运算判断真假）。
   - 位运算优先级低于算术运算，未加括号时计算顺序错误（如a+b&c等价于(a+b)&c）。
4. **相关的知识点**：
   - 位运算的常见应用（&判断奇偶、|置1指定位、^交换变量）。
   - 各进制数参与位运算的本质（自动转换为二进制补码后运算）。
   - 逻辑运算（&&、||、!）与位运算的区别（结果类型：逻辑运算为bool，位运算为整数；运算粒度：逻辑运算针对整体，位运算针对每一位）。

### 第6题
1. **考察的知识点**：位运算（右移>>、异或^、非~）
2. **知识点详解**：
   - 右移>>：正数右移补0，负数补1（算术右移），右移n位等价于除以2ⁿ（向下取整）。
   - 异或^：相同为0，不同为1；非~：按位取反（补码翻转）。
   - 选项分析：
     - A：2>>1=1，1>>1=0，1≠0，A错误。
     - B：2>>2=0，1>>1=0，0=0，B正确。
     - C：11(10)=1011，00(10)=0000，1011^0000=1011(11)；1^0=1，11≠1，C错误。
     - D：~0是全1（补码），对应十进制-1（有符号数），而非1，D错误。
3. **易错点**：
   - 认为右移运算“正负统一补0”，忽略负数算术右移补1的规则。
   - 异或运算中误将“00”当作二进制，而非十进制0（11^00实际是11^0）。
   - 对非运算~的结果理解错误（~x = -x -1，例：~1=-2，~0=-1）。
4. **相关的知识点**：
   - 左移<<与右移>>的区别（左移补0，高位溢出丢弃，等价于乘以2ⁿ）。
   - 异或运算的性质（a^a=0，a^0=a，a^b^c=a^(b^c)）。
   - 无符号数的位运算（非运算结果为正数，例：unsigned int x=1，~x=4294967294）。

### 第7题
1. **考察的知识点**：位运算（异或^）、变量交换逻辑
2. **知识点详解**：代码利用异或运算的性质实现无临时变量交换，核心逻辑：
   - 第一步：a ^= b → a = a^b（此时a存储原a和原b的异或结果）。
   - 第二步：b ^= a → b = b^(a^b) = a（异或交换律、结合律，b变为原a）。
   - 第三步：a ^= b → a = (a^b)^a = b（a变为原b）。
   - 注：判断a≠b是避免自我异或（a^a=0，导致变量值清零），最终实现a和b的值交换，对应选项C。
3. **易错点**：
   - 仅关注异或运算本身，忽略代码的整体逻辑是交换变量。
   - 不理解异或交换的数学原理，误认为是“异或运算”或“高低位互换”。
   - 遗漏a==b的边界情况，导致变量值被清零。
4. **相关的知识点**：
   - 变量交换的其他方法（临时变量法：int t=a;a=b;b=t；加减法：a=a+b;b=a-b;a=a-b，存在溢出风险）。
   - 异或运算的应用（加密、校验、快速比较两个数是否相等）。
   - 引用参数（int &a）的作用（直接操作实参，而非副本，确保交换生效）。

### 第8题
1. **考察的知识点**：位运算（与&、非~）的组合应用
2. **知识点详解**：
   - ~1的二进制表示（以8位为例）：1的二进制是00000001，~1是11111110（按位取反）。
   - a & ~1的逻辑：与运算中，~1的最低位为0，其余位为1，因此无论a的最低位是0还是1，运算后最低位都变为0，其余位保持不变，即“使a的最低位为0”，对应选项C。
3. **易错点**：
   - 误将~1当作十进制-1（有符号数补码），忽略位运算的本质是操作二进制位。
   - 混淆“最低位”与“最高位”，或误认为运算目的是置1而非置0。
   - 未考虑不同位数整数的~1表示（如32位整数~1是0xFFFFFFFE，最低位仍为0）。
4. **相关的知识点**：
   - 位运算掩码（mask）的设计：如取低四位用0x0F（00001111），置最高位为1用0x80（10000000）。
   - 常见位运算组合：a | 1（最低位置1）、a ^ 1（最低位翻转）、a & ~(1<<n)（第n位置0）。
   - 位运算的效率（直接操作二进制位，比算术运算更快）。

### 第9题
1. **考察的知识点**：位运算（左移<<）
2. **知识点详解**：左移运算规则：按位左移n位，低位补0，高位溢出丢弃，左移n位等价于乘以2ⁿ（无溢出时）。
   - 原a=10101110（二进制），左移2位：

3. **易错点**：
   - 左移时误将高位补到低位，或低位补1而非0。
   - 忽略整数的位数限制（如8位、16位），未考虑高位溢出的情况。

4. **相关的知识点**：
   - 左移与右移的区别（左移无符号扩展/符号扩展差异，右移有算术右移/逻辑右移之分）。
   - 溢出的概念（数值超出变量类型的存储范围，结果不可预测）。
   - 位运算在性能优化中的应用（如左移代替乘法，右移代替除法）。

### 第10题
1. **考察的知识点**：位运算（与&）、有符号数与无符号数的存储差异
2. **知识点详解**：
   - 第一部分：a=123(10)=00000000 00000000 00000000 01111011，b=1=00000000...00000001，a&b=00000000...00000001=1，result=1。

   - 误认为a2&b2的结果是-1，未考虑有符号数与无符号数运算时的类型转换（无符号数优先，有符号数转换为无符号数后运算，再转回有符号数）。
4. **相关的知识点**：
   - 有符号数与无符号数的存储差异（符号位的存在与否）。

### 第11题
1. **考察的知识点**：算法与描述（枚举法、模拟法）、数列求和
2. **知识点详解**：题目规律为“第k段有k天，每天浇水k次”，需先确定100天包含的完整段数，再计算剩余天数的浇水次数：
   - 第一步：求最大k使得1+2+3+...+k ≤100（等差数列求和公式S=k(k+1)/2）。
     - 试算：k=13时，S=13×14/2=91天；k=14时，S=14×15/2=105天（超过100），因此完整段为1~13段（91天），剩余100-91=9天（第14段，每天浇水14次）。
   - 第二步：计算总浇水次数=Σ（k×k）（k=1~13） + 9×14。
     - Σk²=1²+2²+...+13²=13×14×27/6=819（平方和公式：n(n+1)(2n+1)/6）。
     - 剩余9天：9×14=126，总次数=819+126=945？注意：题目选项中D为945，但原答案标注为D？需重新核对：
     - 更正：1+2+3+...+13=91天，剩余9天（第92~100天）属于第14段，每天浇水14次，总次数=（1×1）+（2×2）+...+（13×13）+（9×14）= 819 + 126=945，对应选项D（原答案正确）。
3. **易错点**：
   - 错误划分段数（如将第1段视为2天），导致求和基数错误。
   - 忽略剩余天数（超过完整段的部分），仅计算完整段的和。
   - 平方和公式记忆错误，导致计算量增大且易出错。
4. **相关的知识点**：
   - 等差数列求和公式（S=n(a1+an)/2）、平方和公式（S=n(n+1)(2n+1)/6）。
   - 枚举法的应用（逐一计算每段的浇水次数并累加）。
   - 循环结构的设计（用for循环遍历每段，计算天数和浇水次数）。

### 第13题

### 第14题
1. **考察的知识点**：算法与描述（枚举法、逻辑推理）
2. **知识点详解**：核心条件“只有小偷说假话，其他人说真话”，采用枚举法逐一验证：
   - 假设A是小偷（A说假话）：A说“不是我”（假→是A）；B说“是C”（真→矛盾），排除A。
   - 假设B是小偷（B说假话）：B说“是C”（假→不是C）；A说“不是我”（真→不是A）；C说“是D”（真→是D，矛盾），排除B。
   - 假设C是小偷（C说假话）：C说“是D”（假→不是D）；A说“不是我”（真→不是A）；B说“是C”（真→是C）；D说“C瞎说”（真→C说谎），所有条件满足，C是小偷，对应选项C。
   - 假设D是小偷（D说假话）：D说“C瞎说”（假→C说真话→是D）；B说“是C”（假→矛盾），排除D。
3. **易错点**：
   - 逻辑推理混乱，未严格遵循“只有小偷说假话”的条件。
   - 遗漏某个嫌疑人的验证，或验证时前后矛盾。
   - 误将“说假话”与“是小偷”的逻辑关系颠倒（不是“说假话的一定是小偷”，而是“小偷一定说假话”）。
4. **相关的知识点**：
   - 枚举法的应用场景（有限可能情况，逐一验证条件）。
   - 逻辑命题的真假判断（与、或、非的组合应用）。

## 三、编程题（共2题）
### 第1题（平衡序列）
1. **考察的知识点**：算法与描述（枚举法、模拟法）、数据结构（一维数组）、求和逻辑
2. **知识点详解**：
   - 题目要求：判断是否存在i（1≤i<n），使得前i个元素和等于后n-i个元素和（即前i个元素和×2=总 sum）。
   - 核心思路：
     1. 计算序列总 sum（若总 sum 为奇数，直接输出No，因无法平分）。
     2. 枚举i从1到n-1，累加前i个元素和tot，若tot×2==sum，标记为平衡（fl=1），跳出循环。
     3. 根据fl的值输出Yes或No。
   - 参考程序分析：数组存储序列，循环读取测试用例，累加总 sum，再枚举前缀和，时间复杂度O(n)（每组测试用例），高效且简洁。
3. **易错点**：
   - 忽略n=1的边界情况（n=1时无法拆分，直接输出No）。
   - 枚举i时循环条件错误（i<=n，导致i=n时后n-i=0个元素，不符合题意）。
   - 累加前缀和时计算错误（如tot初始值不为0，或漏加元素）。
   - 未优化总 sum 为奇数的情况，增加不必要的计算。
4. **相关的知识点**：
   - 数组的输入与遍历（循环读取n个元素）。
   - 累加器的使用（sum存储总 sum，tot存储前缀和）。
   - 多组测试用例的处理（while(t--)循环）。
   - 边界条件的判断（n=1、sum为奇数时直接返回No）。
