# GESP C++ 五级素数筛复习要点

刷真题时（2026年6月），发现素数筛是最近几次考试的必考题，不但会出现在单选题和判断题中，而且在编程题中也会出现。因此，这个知识点一定要吃透，能够盲写，可以根据题意自由的变化返回值，以及设置全局变量。最重要的是：一定要掌握循环的边界条件，以及避免重复标记的`break` 技巧。
## 一、埃氏筛

提到线性筛，我们的脑海中首先应该有以下的概念

- **核心思想**：找到质数，标记其全部倍数为合数
-  **复杂度**：$O(n\log\log n)$，合数存在重复标记
-  **内层两种起点**：`2*i`（易懂）、`i * i`（优化少循环）
-  **短板**：无法做到线性
-  **适用**：小数范围 ( $10^5$ )，代码简洁易实现

接下来可以尝试盲写代码，想不起来，可以参考这个埃氏筛核心思路：
1. 从小到大遍历数字 `i`；
2. 如果 `i` 没有被标记为合数 → `i` 是质数，存入质数列表；
3. 把这个质数所有更大的倍数全部标记为合数；
4. 所有标记完后，没标记的数全是质数。

下面是2026年3月选择题的代码，供参考。（注意：这个代码只是返回找到的质数，如果把`is_composite`放到全局，可以作为筛查表来用）

```cpp
vector<int> eratosthenes_sieve(int n) {
	vector<bool> is_composite(n + 1, false);
	vector<int> primes;
	for (int i = 2; i <= n; i++) {
		if (is_composite[i]) continue;
		primes.push_back(i);
		for (long long j = (long long)i * i; j <= n; j += i)
			is_composite[j] = true;
	}
	return primes;
}
```

### 1. 内层循环起点 `j = i*i` 为什么不从 `2*i` 开始？

举例子质数 i=3：
- `2*i = 6`，6 早在外层 `i=2` 的循环里，`j=4,6,8...` 时，`6` 已经被标记为合数；
- `3i=9`, `9=3 x 3`，最小质因子是 3，前面没有更小质数能标记它，必须在 `i=3` 这一轮标记；所以只需要从 `i * i=9` 开始标记，`6` 属于重复操作，可以直接跳过。


再举质数 `i=5` 加深理解

`i=5`，`i * i=25`

- `2 x 5 = 10` → 质数 `2` 已标记
- `3 x 5 = 15` → 质数 `3` 已标记
- `4 x 5 = 20` → 质数 `2` 已标记

只有 `25、30、35...` 里之前没有质数能标记，其余小于 `25` 的 `5` 的倍数全部提前标记完毕。因此：
- 小于 `i*i` 的 `i` 的倍数，一定存在更小质因子，早就被前面更小的质数标记完毕；
- 从 `i*i` 起步可以减少重复标记，做小幅优化。

相关的数学结论：对于质数 i，任意倍数 $k\cdot i$，若满足 $k < i$：
- k 必然存在比 i 更小的质因子 p，因此 $k\cdot i$ 一定会在遍历质数 p 时提前标记为合数，无需在 i 这一轮重复标记。

> 补充：写成 `j = 2LL * i` 也是正确埃氏筛，只是标记次数更多，速度略慢。

### 2. `j += i`

每次增加 i，等价于遍历 `i*i, i*i+i, i*i+2i...`，也就是 i 的所有倍数。

### 3. 优缺点

优点
1. 代码极短，逻辑简单好写，不容易写错；
2. 小数据范围（n≤1e5）速度够用。

缺点
1. 时间复杂度 $O(n\log\log n)$，存在大量重复标记；例：数字12，会被质数2、质数3分别标记两次；数字30会被2、3、5各标记一次。
2. 数据量大（$10^6、10^7$）时，效率远低于欧拉线性筛。


### 4. 优化原始外层：`for (int i = 2; i <= n; i++)`

缺点是大量无效循环：当 $i>\sqrt{n}$ 时，$i*i>n$，内层循环完全不执行，只是单纯判断 `is_composite[i]` 然后加入质数列表，做了很多无用遍历。

优化方案是外层只循环到 $\sqrt{n}$，大于 $\sqrt{n}$ 的质数最后统一收集，减少循环次数：

```cpp
// 埃氏筛：返回筛选出来的素数数组
vector<int> sieveOfEratosthenes(int n) {
    vector<bool> is_prime(n + 1, true); // 1. 初始化：默认全是素数
	is_prime[0] = is_prime[1] = false; // 0和1不是素数

	// 2. 核心筛除循环
    for (int p = 2; p * p <= n; ++p) {
        if (is_prime[p]) { // 如果p是素数，筛掉它的所有倍数
            // 从 p*p 开始标记，因为更小的倍数已被之前的素数标记过
            // 注意这里的步长是 p: i += p
            for (long long i = (long long)p * p; i <= n; i += p) {
                is_prime[i] = false;
            }
        }
    } 

    vector<int> primes;
    // 收集所有素数
    for (int i = 2; i <= n; ++i) {
        if (is_prime[i]) {
            primes.push_back(i);
        }
    }
    return primes;
}
```

**优化原理**

- 任何合数 $x\le n$ 一定存在一个质因子 $\le \sqrt{x}\le\sqrt{n}$；
- 全部合数在 $i\le\sqrt{n}$ 阶段就已经标记完毕；
- 大于 $\sqrt{n}$ 未被标记的数字一定是质数，单独一轮遍历收集即可。

**优化收益**

- 外层循环次数从 n 次缩减到 $\sqrt{n}$ 次，n 越大提升越明显；
    
    例：$n=10^6$，原外层循环 1e6 次，优化后仅 1000 次。

## 二、线性筛（欧拉筛）

提到线性筛，我们的脑海中首先应该有以下的概念

- **核心特性**：**每个合数仅被它的最小质因子标记一次**，全程无重复标记操作；
- 数学原理（算术基本定理）：任意合数 `x` 唯一分解：$x = p_{\text{min}} \times k$
	- $p_{\text{min}}$：`x` 的**最小质因子**；
	- $k \ge p_{\text{min}}$。
- **时间复杂度**：严格 `O(n)` 线性复杂度，所有数字仅处理一遍；
- 对比埃氏筛：埃氏筛复杂度 $O(n\log\log n)$，大量合数被重复标记（如 12 会被 2、3 各筛一次），大数据范围效率差距明显。

其次是思考代码的核心逻辑和循环的边界条件，以及如何保证只被最小质因子标记。下面是2026年3月选择题的代码，供参考。

```cpp
vector<int> euler_sieve(int n) {
	vector<bool> is_composite(n + 1, false);
	vector<int> primes;
	for (int i = 2; i <= n; i++) {
		if (!is_composite[i])
			primes.push_back(i);
		for (int j = 0; j < primes.size() && (long long)i * primes[j] <= n; j++) {
			is_composite[i * primes[j]] = true;
			if (i % primes[j] == 0)
				break;
		}
	}
	return primes;
}
```
### 1. 数组初始化

- `is_composite[]`：布尔数组，`is_composite[x]=false` 代表 x 暂定为素数；如果放到全局，可以作为筛选的结果，供其他函数使用，需要主要默认`0、1` 初始置为 true，这个真题代码中没有体现，因为这个函数的目标是为了筛出素数数组 `primes`。
- `primes[]`：顺序存储遍历过程中找到的所有素数。

### 2. 双层循环逻辑

1. 外层：i 从 `2` 遍历到 `n`(包括n)。
2. 若 `is_composite[i] == false` → `i` 是素数，存入 `primes`。
3. 内层：遍历 `primes` 中每一个质数 `primes[j]`：    
    - 计算合数 $num = i \times primes[j]$，若 $num>n$ 直接跳出内层循环，因此内层的循环终止条件就是：`j < primes.size() && (long long)i * primes[j] <= n`。
    - 标记合数 $num = i \times primes[j]$ ，即：`is_composite[num] = true`。
    - **关键断点**：若 `i % primes[j] == 0`，立刻 `break` 内层循环。
    
### 3. 断点 `break` 原理

若 $i \% primes[j] = 0$，说明 `primes[j]` 是 `i` 的最小质因子，因为 `primes[]` 里面的素数是从小到大排列的。结合前面提到的数学原理（算术基本定理）。
- $p_{\text{min}} = primes[j]$
- $k=i = 某个数 \times primes[j] = 某个数 \times P_{min}$
c
此时，我们可以注意到 `i` 已经包含了一个最小质数 $P_{min}$ 。如果继续循环下去，`primes[j+1]` 是一个比 $P_{min}$ 大的质数了，如果现在提前标记，就会造成重复筛，破坏 $O(n)$ 线性特性，因此必须终止内层循环。

> 网上有些材料会这么介绍：供参考。若继续取下一个更大素数 `p'`，合数 $i \times p' = p \times (i/p) \times p'$，它的**最小质因子仍是 p**，本该在后续更大的 $i'=(i/p)\times p'$ 时再由 `p` 筛除；

**举例演示（n=12）**

合数 12 = 2 × 6，最小质因子是 2

- 只会在外层 `i=6`、内层 `primes[j]=2` 时被标记；
- `i=4、primes[j]=3` 不会标记 12，杜绝重复。

### 4. 优缺点

**优点**
1. 时间复杂度严格 $O(n)$，每个合数仅被最小质因子标记一次，无重复操作，大数据效率远超埃氏筛。
2. 可同步线性预处理欧拉函数、莫比乌斯函数、最小质因子等积性函数，数论题目刚需。
3. 标记逻辑严谨，可顺带记录每个数字的最小质因子，辅助分解质因数。

**缺点**
1. 代码逻辑比埃氏筛复杂，需要维护质数数组与`i%p==0`中断判断，新手难理解。
2. 常数略高于简易埃氏筛，极小数据范围时优势不明显。
3. 空间需要额外开辟数组存储所有找到的质数，多一点内存开销。

## 三、埃氏筛 vs 欧拉筛核心对比
| 筛法  | 复杂度              | 标记特点      |
| --- | ---------------- | --------- |
| 埃氏筛 | $O(n\log\log n)$ | 合数重复标记    |
| 欧拉筛 | $O(n)$           | 每个合数仅标记1次 |
