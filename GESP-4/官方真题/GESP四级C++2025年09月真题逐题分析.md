# 选择题

## 第1题
### 1. 考察的知识点
指针 - 指针类型定义变量、指针类型变量的赋值、解引用

### 2. 知识点详解
- 指针类型定义变量：`int* p` 定义了一个指向int类型的指针变量p；
- 指针赋值：`p = &a` 将变量a的内存地址赋值给指针p，使p指向a；
- 解引用：`*p` 表示访问指针p指向的内存地址中的值，对`*p`的修改等价于对其指向变量的直接修改。

### 3. 选项对错分析
- A. 42：错误，程序中对`*p`执行了`+1`操作，等价于a自增1，值不再是42；
- B. 43：正确，`*p = *p +1` 即`a = a +1`，42+1=43；
- C. 编译错误：错误，代码语法符合C++指针使用规范，无编译错误；
- D. 不确定：错误，指针明确指向a，操作结果唯一确定。

### 4. 答案
B

### 5. 易错点分析
混淆**指针本身的赋值**和**指针解引用的赋值**，误将`p = &a`理解为对p的内容赋值，或忘记`*p`直接关联指向变量的内存值。

### 6. 相关的知识点
指针与普通变量的内存关系、指针的基本运算（仅值操作，无地址偏移）、一元取地址符`&`的使用。

## 第2题
### 1. 考察的知识点
指针+二维及多维数组 - 数组名的本质、数组的基本特性、sizeof运算符对数组的作用

### 2. 知识点详解
- 数组名是**指针常量**：指向数组首元素的地址，其值不可修改（不能自增/自减）；
- 数组的随机访问：通过下标`arr[i]`可直接访问任意元素，时间复杂度O(1)，便捷高效；
- sizeof(arr)：对数组名使用sizeof时，返回**整个数组占用的总字节数**，而非指针大小；若数组名退化为指针（如传参），则返回指针字节数。

### 3. 选项对错分析
- A. 数组名是一个指针常量：正确，数组名指向首元素，地址不可变；
- B. 随机访问数组的元素方便快捷：正确，数组连续存储，下标直接映射地址；
- C. 数组可以像指针一样进行自增操作：错误，数组名是常量，常量不可执行自增/自减等修改操作；
- D. sizeof(arr) 返回的是整个数组arr 占用的字节数：正确，数组名未退化时，sizeof计算整体字节数。

### 4. 答案
C

### 5. 易错点分析
将**数组名**和**普通指针变量**混淆，认为数组名可以像指针变量一样进行地址偏移操作；忽略数组名的**常量属性**。

### 6. 相关的知识点
数组名退化为指针的场景（函数传参）、sizeof对指针和数组的不同计算结果、指针变量的自增/自减（地址偏移）。

### 6. 相关的知识点

## 第9题
### 1. 考察的知识点
排序算法 - 冒泡排序、插入排序、选择排序；算法稳定性

### 2. 知识点详解
- 算法稳定性：**稳定排序**指排序后，原数组中相等元素的**相对位置保持不变**；不稳定排序则会改变相等元素的相对位置；
- 常见排序的稳定性：冒泡排序、插入排序是稳定排序；选择排序、快速排序是不稳定排序。
  选择排序不稳定原因：直接选择未排序区间的最小/最大值与当前位置交换，可能导致相等元素位置交换。

### 3. 选项对错分析
- A. 稳定的排序算法不改变相等元素的相对位置：正确，算法稳定性的定义；
- B. 冒泡排序是稳定的排序算法：正确，冒泡排序仅交换相邻的逆序元素，相等元素不交换；
- C. 选择排序是稳定的排序算法：错误，选择排序是典型的不稳定排序；
- D. 插入排序是稳定的排序算法：正确，插入排序仅将元素插入到合适位置，相等元素保留原相对位置。

### 4. 答案
C

### 5. 易错点分析
记混常见排序算法的稳定性，误以为选择排序是稳定排序；或对**算法稳定性的定义**理解不清，将“元素大小顺序”与“相对位置”混淆。

### 6. 相关的知识点
排序算法稳定性的实际意义、快速排序/归并排序的稳定性、不稳定排序转为稳定的方法。

## 第10题
### 1. 考察的知识点
排序算法 - 选择排序的实现；算法复杂度（隐含）

### 2. 知识点详解
- 选择排序（升序）核心逻辑：
  1. 将数组分为已排序区间和未排序区间，初始已排序区间为空；
  2. 遍历未排序区间，找到**最小值的下标**minIndex；
  3. 将最小值与未排序区间的第一个元素交换，扩大已排序区间；
  4. 重复上述步骤，直到整个数组有序。
- 核心操作：**比较找最小值**+**交换最小值与当前首元素**。

### 3. 选项对错分析
- A. nums[j] < nums[minIndex]、swap(nums[i], nums[minIndex])：正确，前者找到未排序区间更小值，更新最小值下标；后者将最小值交换到已排序区间末尾（i位置）；
- B. nums[j] > nums[minIndex]、swap(nums[i], nums[minIndex])：错误，比较条件写反，会找到最大值，实现降序排序；
- C. nums[j] <= nums[minIndex]、swap(nums[j], nums[minIndex])：错误，交换条件错误，无需交换j和minIndex，且<=会导致不必要的下标更新；
- D. nums[j] <= nums[minIndex]、swap(nums[i], nums[j])：错误，比较条件和交换操作均错误，无法实现选择排序。

### 4. 答案
A

### 5. 易错点分析
- 选择排序的**比较条件**写反（找最大值而非最小值）；
- 混淆**交换的对象**，误将当前j位置与minIndex交换，而非未排序区间首元素i与minIndex交换；
- 多余使用`<=`，忽略选择排序找最小值的核心逻辑（`<`即可）。

### 6. 相关的知识点
选择排序的时间复杂度（O(n²)，最好/最坏均为O(n²)）、选择排序的空间复杂度（O(1)，原地排序）、swap函数的使用。

## 第11题
### 1. 考察的知识点
排序算法 - 插入排序的实现

### 2. 知识点详解
- 插入排序（升序）核心逻辑：
  1. 将数组分为已排序区间和未排序区间，初始已排序区间为第一个元素；
  2. 取未排序区间的第一个元素作为**关键字key**，向前遍历已排序区间；
  3. 若已排序区间的元素**大于key**，则将该元素后移，为key腾出位置；
  4. 找到key的合适位置，将key插入，扩大已排序区间；
  5. 重复上述步骤，直到整个数组有序。
- 核心操作：**向前比较后移**+**插入关键字**。

### 3. 选项对错分析
- A. arr[j] > key、arr[j + 1] = key：正确，前者判断已排序元素是否大于key，若是则后移；后者将key插入到j+1的位置（j是最后一个大于key的元素下标）；
- B. arr[j] < key、arr[j + 1] = key：错误，比较条件写反，会将key插入到错误位置，无法实现升序；
- C. arr[j] > key、arr[j] = key：错误，插入位置错误，j位置是大于key的元素，应插入到j+1；
- D. arr[j] < key、arr[j] = key：错误，比较条件和插入位置均错误。

### 4. 答案
A

### 5. 易错点分析
- 插入排序的**比较条件**写反，混淆升序/降序的判断逻辑；
- 忘记**关键字的插入位置**是j+1，误将key赋值给j位置；
- 忽略while循环的`j >= 0`边界条件，导致数组越界（本题已给出，无需填写）。

### 6. 相关的知识点
插入排序的时间复杂度（最好O(n)、最坏O(n²)）、插入排序的空间复杂度（O(1)）、插入排序的优化（折半插入排序）。

## 第12题
### 1. 考察的知识点
排序算法 - 插入排序的时间复杂度；简单算法复杂度的估算

### 2. 知识点详解
- 插入排序的时间复杂度由**元素比较次数**和**元素移动次数**决定，与数组初始有序程度相关：
  1. **最好情况**：数组已经升序有序，此时只需遍历数组一次，无需移动元素，时间复杂度为**O(n)**；
  2. **最坏情况**：数组逆序有序，此时每个元素都需要向前遍历整个已排序区间，比较和移动次数均为O(n²)，总时间复杂度为**O(n²)**；
- 时间复杂度的表示：使用大O表示法，仅保留最高阶项，忽略常数和低阶项。

### 3. 选项对错分析
- A. 最好情况和最坏情况的时间复杂度都是O(n²)：错误，最好情况为O(n)；
- B. 最好情况是O(n)，最坏情况是O(n²)：正确，符合插入排序的时间复杂度特性；
- C. 最好情况是O(n)，最坏情况是O(2ⁿ)：错误，插入排序是多项式复杂度，非指数复杂度；
- D. 最好情况是O(n²)，最坏情况是O(2ⁿ)：错误，完全违背插入排序的复杂度特性。

### 4. 答案
B

### 5. 易错点分析
- 记混插入排序的**最好/最坏时间复杂度**，误以为所有情况都是O(n²)；
- 混淆**多项式复杂度（O(n^k)）**和**指数复杂度（O(2ⁿ)）**，将插入排序归为指数复杂度。

### 6. 相关的知识点
冒泡排序/选择排序的时间复杂度、算法时间复杂度的分析方法、大O表示法的定义。

## 第13题
### 1. 考察的知识点
递推算法 - 递推算法基本思想、递推关系式推导；爬楼梯问题的递推模型

### 2. 知识点详解
- 爬楼梯递推模型：每次爬1或2阶，到达第n阶的方法数`f(n) = f(n-1) + f(n-2)`（到达n-1阶后爬1阶，或到达n-2阶后爬2阶）；
- 初始条件：`f(1)=1`、`f(2)=2`；
- 递推实现（迭代法）：用两个变量保存前两项的值，循环计算当前项，避免递归的重复计算，时间复杂度O(n)，空间复杂度O(1)。
  核心步骤：`current = prev1 + prev2` → 更新`prev2 = prev1` → 更新`prev1 = current`（循环前需先计算current）。
**注**：原题选项A、B重复，为排版遗漏，核心考点为递推式的迭代实现。

- B. （同A，排版错误）；
- C. prev1 = current; current = prev1 + prev2; prev2 = prev1; 错误，赋值顺序混乱，计算出的current非前两项之和；
- D. （原题正确选项为**current = prev1 + prev2; prev2 = prev1; prev1 = current;**，选项排版遗漏）：正确，先计算当前项为前两项之和，再更新前两项为下一次迭代做准备；
**注**：原题答案为B，为选项排版问题，核心逻辑为**先算current，再更新前驱变量**。

### 5. 易错点分析

**对**

2. 4和3交换 → {1,3,4,1,5,2}
3. 4和1交换 → {1,3,1,4,5,2}
4. 4和5不交换 → 保持{1,3,1,4,5,2}
5. 5和2交换 → {1,3,1,4,2,5}
最终一轮冒泡后结果为`{1,3,1,4,2,5}`（题目中写为{4,1,3,1,2,5}为笔误，核心是最大元素5放到最后），因此判断正确。

本题是经典的**01矩阵中最大全1矩形**问题，结合数据范围特点采用了暴力枚举的解题思路，核心考察C++二维数组的操作、暴力枚举的边界控制、条件判断与最值更新，是对基础编程能力和逻辑思维的综合考查。

## 1. 题意的理解
地图被抽象为**n行m列的01网格**，其中`1`表示该网格适合排兵，`0`表示不适合。要求在网格中选择一个**矩形区域**，该矩形内**所有网格都必须为1**（无任何0），最终求解满足条件的矩形区域能包含的**最大网格数量**（即矩形的面积，面积=行数×列数）。

数据范围明确`1 ≤ n、m ≤12`，该范围是解题思路选择的关键依据。

## 2. 题目核心要求
1. 遍历二维数组的所有可能矩形区域，筛选出**内部全为1**的有效矩形；
2. 计算每个有效矩形的面积（网格数）；
3. 记录并输出所有有效矩形中的**最大面积**；
4. 边界要求：矩形必须是网格中的连续区域，行、列均不可断开。

## 3. 解题思路
结合题目**n、m≤12**的极小数据范围，**暴力枚举所有可能的矩形**是最优且最易实现的思路（时间复杂度在可接受范围内），具体枚举逻辑为**固定矩形的上下边界和左边界，向右扩展右边界并验证有效性**，步骤如下：
1. **枚举上边界u**：遍历每一行作为矩形的顶部行，范围`1~n`（代码中采用1-based索引，更符合直观）；
2. **枚举下边界d**：对于每个上边界u，遍历`u~n`作为矩形的底部行，确定矩形的行范围；
3. **枚举左边界l**：遍历每一列作为矩形的左列，范围`1~m`；
4. **扩展右边界r**：对于每个左边界l，遍历`l~m`作为矩形的右列，逐步向右扩展；
5. **有效性验证**：对于当前枚举的矩形（u~d行，l~r列），检查内部所有网格是否均为1；若出现0，则该右边界及更右侧的列均无法构成有效矩形，直接中断当前右边界的扩展；
6. **最值更新**：若当前矩形有效，计算其面积并与已记录的最大面积比较，更新最大面积。

**核心优化点**：当右边界扩展中遇到0时，直接中断该左边界下的右边界遍历（因为矩形是连续的，右侧列必然包含该0，无需继续验证），减少无效计算。

## 5. 完整的代码和逻辑解析
### 完整可运行代码（1-based索引，C++标准写法）
```cpp
#include <iostream>
#include <algorithm>
using namespace std;

// 数据范围n、m≤12，定义15足够
const int N = 15;
// 存储01网格，1-based索引
int a[N][N];
// 记录最大面积，初始为0
int ans = 0;
int n, m;

int main() {
    // 输入行数和列数
    cin >> n >> m;
    // 输入二维网格，1-based索引遍历
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            cin >> a[i][j];
        }
    }

    // 枚举矩形的上边界u
    for (int u = 1; u <= n; u++) {
        // 枚举矩形的下边界d，d >= u
        for (int d = u; d <= n; d++) {
            // 枚举矩形的左边界l
            for (int l = 1; l <= m; l++) {
                // 标记当前矩形是否全1，初始为1（有效）
                int is_all_one = 1;
                // 枚举矩形的右边界r，r >= l
                for (int r = l; r <= m; r++) {
                    // 检查u~d行、r列是否全1（逐行验证当前列）
                    for (int x = u; x <= d; x++) {
                        // 按位与，只要有一个0，is_all_one变为0
                        is_all_one &= a[x][r];
                    }
                    // 若当前矩形包含0，中断右边界扩展
                    if (!is_all_one) {
                        break;
                    }
                    // 计算当前有效矩形的面积：行数量(d-u+1) × 列数量(r-l+1)
                    int area = (d - u + 1) * (r - l + 1);
                    // 更新最大面积
                    ans = max(ans, area);
                }
            }
        }
    }

    // 输出最大面积
    cout << ans << endl;
    return 0;
}
```

### 代码逻辑解析
1. **变量与常量定义**：`const int N=15`适配题目数据范围，`a[N][N]`存储01网格，`ans`初始为0用于记录最大面积，`n、m`存储网格的行和列；
2. **输入处理**：采用**1-based索引**读取网格（避免0-based索引的边界判断麻烦，更符合枚举逻辑）；
3. **四层循环枚举矩形**：
   - 外层两层：枚举上边界`u`和下边界`d`，确定矩形的行范围；
   - 内层两层：枚举左边界`l`和右边界`r`，确定矩形的列范围；
4. **有效性验证**：通过`is_all_one &= a[x][r]`逐行验证当前列`r`是否为1，只要有一个0，`is_all_one`变为0，直接中断右边界扩展；
5. **面积计算与最值更新**：有效矩形的面积为`(d-u+1)*(r-l+1)`，通过`max(ans, area)`更新最大面积；
6. **输出结果**：最终输出记录的最大面积`ans`。

## 7. 易错点和注意事项
### 7.1 索引相关易错点
1. **0-based与1-based混淆**：若混合使用两种索引，会出现**越界访问**或**漏查网格**的问题（本题推荐1-based，枚举边界更直观）；
2. **循环边界错误**：如枚举下边界`d`时写成`d < n`（正确应为`d <= n`）、枚举右边界`r`时写成`r < m`，导致漏查最后一行/列的矩形。

### 7.2 枚举与验证易错点
1. **验证逻辑顺序错误**：若先计算面积再验证有效性，会将包含0的无效矩形计入面积，导致结果错误；
2. **未及时中断右边界扩展**：若遇到0后继续扩展右边界，会进行大量无效的验证计算（虽数据量小不影响结果，但违反算法优化逻辑，竞赛中易超时）；
3. **矩形面积计算错误**：误将面积计算为`d*r - u*l`或`(d-u)*(r-l)`，遗漏**+1**（如行1到行3共3行，`3-1+1=3`，而非`3-1=2`）。

### 7.3 变量与初始化易错点
1. **验证标记`chk/is_all_one`未重新初始化**：若将`chk`定义在左边界循环外，会导致上一个左边界的验证结果影响当前左边界，出现**误判有效/无效**的问题（必须在**每个左边界l**内初始化`chk=1`）；
2. **最大面积`ans`初始值错误**：若初始化为1，当网格全为0时，结果会错误输出1（正确初始值为0，全局变量默认0，局部变量需手动赋值0）。

### 7.4 输入处理易错点
文档中样例输入存在**排版混乱**，实际编程中需注意**按行读取**，确保每行读取m个数字，避免因输入格式错误导致网格数据存储混乱。

### 7.5 竞赛通用注意事项
1. **头文件包含**：需包含`<algorithm>`（使用`max`函数）和`<cstdio>/<iostream>`（输入输出），遗漏头文件会导致编译错误；
2. **数据类型**：本题n、m≤12，最大面积为`12×12=144`，使用`int`完全足够，无需使用更大类型；
3. **暴力枚举的适用场景**：仅当数据范围极小时（如n、m≤20）使用暴力枚举，若数据范围扩大（如n、m≤100），需改用**单调栈法**（时间复杂度O(nm)）求解最大全1矩形。


# 编程题2：最长连续段

# 豆包


本题是经典的**最长连续序列**变形题，结合“可重排数组”的条件简化了问题，核心考察C++数组排序、线性遍历、去重逻辑与最值维护，同时兼顾**大数据量处理**（$n≤10^5$）的算法时间复杂度要求，是对基础算法设计和竞赛编程优化思维的综合考查。

## 1. 题意的理解
给定一个由$n$个整数构成的数组，**可以任意重排数组中元素的顺序**。定义**连续段**：一个子数组中，后一个元素始终比前一个元素大1（即$b_{i+1}=b_i+1$）。要求求解重排后，数组中所有属于**连续段**的子数组的**最长长度**。

关键隐含条件：**数组可重排**，因此无需考虑原数组的元素顺序，只需关注元素的**数值分布**，连续段的本质是**连续的整数序列**（无间隔、无重复）。

## 2. 题目核心要求
1. 利用**数组可重排**的条件，将问题转化为寻找**数值上连续的整数序列的最大长度**；
2. 处理数组中的**重复元素**：重复元素不影响连续段（如数组有多个1，重排后仍只能作为连续段中“1”的一个位置）；
3. 算法时间复杂度需满足**大数据量要求**（$n≤10^5$），需避免$O(n^2)$及更高复杂度的算法；
4. 最终输出最长连续段的子数组长度。

## 3. 解题思路
结合“可重排”的核心条件，问题被简化为**寻找数组中去重后数值连续的整数的最大长度**，最优解题思路为**排序+线性遍历**，时间复杂度为$O(n\log n)$（排序的时间复杂度），完全满足$n≤10^5$的要求，具体步骤如下：
1. **排序数组**：将原数组升序排序，使数值连续的元素集中在一起，重复元素也相邻；
2. **初始化变量**：定义`last`记录上一个有效数值（初始为数组第一个元素）、`cnt`记录当前连续段长度（初始为1）、`mx`记录最长连续段长度（初始为1）；
3. **线性遍历数组**：从第二个元素开始遍历：
   - 若当前元素与`last`**相等**：为重复元素，跳过（不影响连续段）；
   - 若当前元素等于`last+1`：数值连续，当前连续段长度`cnt++`，更新`last`为当前元素；
   - 若当前元素大于`last+1`：数值断开，重置当前连续段长度`cnt=1`，更新`last`为当前元素；
4. **维护最值**：每次遍历后，用当前连续段长度`cnt`更新最长连续段长度`mx`；
5. **输出结果**：遍历结束后，`mx`即为答案。

**核心优化点**：
- 排序使连续数值集中，避免了暴力枚举所有子数组的高复杂度；
- 遍历中直接跳过重复元素，无需额外创建数组去重，节省空间和时间。

## 5. 完整的代码和逻辑解析
### 完整可运行代码（适配$n≤10^5$，C++标准写法）
```cpp
#include <iostream>
#include <algorithm>
using namespace std;

// 适配n≤1e5，定义数组大小为1e5+5，避免越界
const int N = 1e5 + 5;
// 存储原数组
int a[N];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0); // 关闭同步，加速cin输入（大数据量必备）
    
    int n;
    cin >> n;
    // 输入n个元素
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }
    
    // 对数组升序排序，O(nlogn)复杂度
    sort(a, a + n);
    
    // 初始化：last为第一个元素，cnt当前连续长度，mx最长长度
    int last = a[0];
    int cnt = 1;
    int mx = 1;
    
    // 线性遍历数组，从第二个元素开始
    for (int i = 1; i < n; i++) {
        if (a[i] == last) {
            // 重复元素，跳过
            continue;
        } else if (a[i] == last + 1) {
            // 数值连续，当前长度+1
            cnt++;
            // 更新最长长度
            mx = max(mx, cnt);
            // 更新上一个有效数值
            last = a[i];
        } else {
            // 数值断开，重置当前长度
            cnt = 1;
            last = a[i];
        }
    }
    
    // 输出最长连续段长度
    cout << mx << endl;
    return 0;
}
```

### 代码逻辑解析
1. **头文件与常量**：包含`<algorithm>`（排序函数`sort`）、`<iostream>`（输入输出），`const int N=1e5+5`适配大数据量；
2. **输入加速**：`ios::sync_with_stdio(false); cin.tie(0);`是C++处理$10^5$级别数据的**必备操作**，避免cin因同步导致的超时；
3. **排序**：`sort(a, a+n)`对数组升序排序，将连续数值和重复元素集中；
4. **变量初始化**：`last`记录上一个有效数值，`cnt`为当前连续段长度，`mx`为最长长度，均初始化为1（单个元素的连续段长度为1）；
5. **线性遍历**：
   - 重复元素：直接跳过，不改变连续段状态；
   - 连续数值：`cnt++`并更新最值`mx`；
   - 数值断开：重置`cnt=1`，重新开始统计；
6. **输出结果**：最终`mx`即为重排后最长连续段的子数组长度。

```cpp
int a[N]; // 存储输入数组
int n;    // 数组长度
int last, cnt, mx; // last：上一有效值；cnt：当前连续长度；mx：最长长度

int main() {
    // 输入数组长度n
    scanf("%d", &n);
    // 输入n个元素，1-based索引（竞赛常用，避免0索引习惯问题）
    for (int i = 1; i <= n; i++) {
        scanf("%d", &a[i]);
    }
    
    // 对数组升序排序，排序范围1~n
    sort(a + 1, a + n + 1);
    
    // 初始化：从第一个元素开始统计
    last = a[1];
    cnt = mx = 1;
    
    // 线性遍历数组，从第二个元素开始（修正原代码i=1的错误）
    for (int i = 2; i <= n; i++) {
        if (a[i] == last) {
            // 重复元素，跳过不处理
            continue;
        }
        // 数值连续，更新当前长度
        if (a[i] == last + 1) {
            cnt++;
        } else {
            // 数值断开，重置当前长度
            cnt = 1;
        }
        // 更新上一有效值
        last = a[i];
        // 维护最长连续段长度
        mx = max(cnt, mx);
    }
    
    // 输出结果
    printf("%d\n", mx);
    return 0;
}
```

### 参考代码核心特点
1. **1-based索引**：竞赛编程常用写法，符合部分选手的编程习惯，避免0索引的边界问题；
2. **scanf/printf输入输出**：比cin/cout更快，无需额外加加速语句，适合处理$10^5$级别数据；
3. **逻辑简化**：将`last`的更新放在条件判断外，减少代码冗余，不影响逻辑正确性；
4. **时间空间优化**：无需额外创建去重数组，在遍历中直接跳过重复元素，空间复杂度为$O(n)$（仅存储原数组）。

## 7. 易错点和注意事项
### 7.1 算法设计易错点
1. **忽略“可重排”条件**：若未意识到可重排的简化作用，尝试暴力枚举原数组的所有子数组，会导致时间复杂度为$O(n^2)$，在$n=10^5$时**直接超时**；
2. **错误选择去重方式**：额外创建`set`或`vector`去重，虽逻辑正确，但会增加空间复杂度和时间开销（如`set`的插入时间为$O(n\log n)$），属于冗余操作。

### 7.2 遍历与条件判断易错点
1. **循环起始位置错误**：如从`i=1`开始遍历（1-based索引），会导致第一个元素与自身比较，若元素重复则直接跳过，初始统计错误；
2. **重复元素处理遗漏**：若未判断`a[i]==last`，会将重复元素判定为“数值断开”，导致连续段长度被错误重置（如数组[0,0,1]，会被统计为[0]、[0]、[1]，而非正确的[0,1]）；
3. **条件判断顺序错误**：若先判断`a[i]==last+1`，再判断`a[i]==last`，会导致重复元素被误判为连续数值，`cnt`错误增加。

### 7.3 变量初始化与更新易错点
1. **初始值错误**：将`cnt`或`mx`初始化为0，当数组只有一个元素时，会输出0（正确应为1）；
2. **`last`更新遗漏**：在条件判断中忘记更新`last`，会导致后续所有元素与初始值比较，统计完全错误；
3. **最值更新时机错误**：若仅在“数值连续”时更新`mx`，逻辑正确，但需注意边界；若在“数值断开”时未更新，不影响结果（因断开后`cnt`重置为1，不会超过当前`mx`）。

### 7.4 大数据量处理易错点
1. **数组大小不足**：若定义的数组大小小于$10^5+5$，会导致**数组越界**，程序崩溃；
2. **输入输出超时**：使用`cin/cout`处理$10^5$级别数据时，未加`ios::sync_with_stdio(false); cin.tie(0);`，会因输入输出速度过慢导致超时；
3. **排序范围错误**：如1-based索引的数组，排序范围写为`sort(a, a+n)`，会遗漏最后一个元素，导致排序不完整。

### 7.5 边界情况处理易错点
本题需重点考虑**边界情况**，若处理不当会导致答案错误，核心边界情况如下：
1. **数组只有一个元素**：如`n=1，a=[5]`，答案应为1；
2. **数组全为重复元素**：如`n=5，a=[2,2,2,2,2]`，答案应为1；
3. **数组本身就是连续数值**：如`n=5，a=[5,3,4,1,2]`，排序后为[1,2,3,4,5]，答案应为5；
4. **数组包含负数**：如`n=4，a=[-2,-1,0,2]`，答案应为3（连续段：-2,-1,0），代码无需额外处理，排序后可正常统计。

### 7.6 竞赛通用注意事项
1. **头文件包含**：必须包含`<algorithm>`，否则`sort`函数和`max`函数会编译错误；
2. **数据类型**：本题中元素值范围为$-10^9≤a_i≤10^9$，但仅需比较数值大小，使用`int`即可（C++中`int`可存储±2×10^9，满足要求）；
3. **时间复杂度把控**：对于$n≤10^5$的题目，**排序+线性遍历**（$O(n\log n)$）是安全选择，需避免递归、多层循环等高复杂度算法。
