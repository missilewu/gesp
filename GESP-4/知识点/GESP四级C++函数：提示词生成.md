# C++函数教学提示词生成

## 核心指令

你是一位经验丰富的C++教学专家，正在为编程初学者设计一堂关于“C++函数”的专题课程。请遵循以下框架和原则，创作一份**启发式、渐进式、互动性强**的完整教学材料。

## 教学目标

通过本课程，学生应能：

1. **理解动机**：深刻理解为何需要函数，以及函数在解决“代码重复”和“复杂任务分解”问题上的核心价值。
2. **掌握机制**：透彻掌握函数的定义、声明、调用全过程。
3. **辨析概念**：清晰区分形参与实参，理解参数传递的三种方式（值、引用、指针）及其影响。
4. **理解边界**：明确全局、局部、块作用域对变量生命周期和可见性的影响。

## 教学风格与框架要求

**总体风格**：采用“提出问题 -> 引导思考 -> 揭示原理 -> 总结归纳”的苏格拉底式教学法。避免平铺直叙地罗列概念，而是通过精心设计的问题链，让学生在思考中自己构建知识体系。

**课程结构**：请按以下五个阶段展开教学，每个阶段包含核心问题、启发式提问示例和知识讲解要点。

### 阶段一：从“重复劳动”到“抽象工具”——为什么要用函数？

- **核心问题**：当一段代码需要在程序中多个地方使用时，直接复制粘贴会带来哪些问题？
- **启发式提问设计**：
    1. 展示一个计算圆面积并在多处调用的程序（重复代码）。提问：“如果圆周率精度需要从3.14改为3.14159，你需要修改多少个地方？”
    2. 展示一个包含复杂逻辑（如判断闰年）的程序片段。提问：“如果这段逻辑有错误，或者需要优化，在多个副本中逐一修改，容易出错吗？”
- **知识讲解要点**：
    - 引出函数的**核心价值**：**代码复用**和**逻辑封装**。将函数比喻为“可重复使用的工具”或“专业厨师”。
    - 明确本阶段目标：将学生从“面向过程的行列式编程”思维，引导至“模块化函数式编程”思维。

### 阶段二：函数的“诞生”与“召唤”——定义、声明与调用

- **核心问题**：如何创建一个函数？创建后如何在不同地方使用它？
- **启发式提问设计**：
    1. **定义**：以`int add(int a, int b) { return a + b; }`为例。逐部分提问：“`int`在最前面代表什么？`add`是什么？括号里的`int a, int b`又是什么？大括号`{}`包含了什么？`return`语句的作用是什么？”引导学生自己总结出函数定义的四个部分：返回类型、函数名、参数列表、函数体。
    2. **声明 vs. 定义**：将函数定义放在`main`函数之后，编译会报错。提问：“编译器是从上往下阅读代码的，当它在`main`中遇到`add(5, 3)`时，它知道`add`是什么吗？”引出“声明”的概念。对比“声明”（告诉编译器函数的存在和样式）与“定义”（提供函数的具体实现）。
    3. **调用**：演示函数调用的几种形式：作为独立语句、作为表达式一部分、作为另一个函数的参数。提问：“`printMessage();`和`int sum = add(1, 2);`这两种调用方式，反映了函数什么不同的特性？”（无返回值 vs. 有返回值）。
- **知识讲解要点**：
    - 详解函数定义的语法格式。
    - 强调声明的作用是解决编译顺序问题，其格式是函数头加分号。
    - 区分三种调用场景，并关联`void`返回类型与语句调用的关系。

### 阶段三：数据的“传递”与“隔阂”——形参、实参与传递方式

- **核心问题**：调用函数时，数据是如何传入函数内部的？在函数内部修改参数，会影响外部的变量吗？
- **启发式提问设计**：
    1. **形参与实参**：给出代码 `void swap(int a, int b) {...}` 和 `swap(x, y);`。提问：“函数定义中的`a, b`和调用时的`x, y`是什么关系？它们是完全相同的变量吗？” 引导学生理解形参是“形式上的占位符”，实参是“实际传入的值”。用“配方中的‘蔬菜’（形参）和实际下锅的‘白菜’（实参）”来类比。
    2. **值传递的“影印本”陷阱**：使用上述`swap`函数（值传递实现），但交换失败。提问：“为什么`x`和`y`的值没有改变？函数内部的`a`和`b`不是已经交换了吗？” 引导学生画出内存示意图，理解值传递是**拷贝实参的值**创建一个新的局部变量（形参），修改形参不影响实参。
    3. **引用传递的“别名”魔法**：将`swap`参数改为引用`int &a, int &b`。提问：“现在为什么能交换成功了？`a`和`x`现在是什么关系？” 强调引用是变量的别名，操作引用就是直接操作原变量。
    4. **指针传递的“地址”操作**：将`swap`参数改为指针`int *a, int *b`。提问：“这种方式和引用传递在效果上类似，但语法上有什么不同？`&x`和`*a`分别代表什么操作？” 对比指针传递（传递地址，需解引用）和引用传递（语法更简洁）。
- **知识讲解要点**：
    - 明确形参是函数内部的局部变量，实参是外部具体的值。
    - 对比三种传递方式的核心区别：
        - **值传递**：拷贝值，安全但可能低效，无法修改实参。
        - **引用传递**：传递别名，高效且可直接修改实参，是C++推荐方式。
        - **指针传递**：传递地址值，可通过解引用修改实参，但语法稍复杂。
    - 通过`swap`案例的三种实现，让学生直观感受差异。

### 阶段四：变量的“视野”与“生命周期”——作用域

- **核心问题**：在函数内部定义的变量，能在`main`函数中使用吗？为什么同名变量有时会互相干扰？
- **启发式提问设计**：
    1. 在`main`和另一个函数`foo`中分别定义同名变量`int num = 10;`。提问：“这两个`num`是同一个变量吗？修改`foo`中的`num`会影响`main`中的`num`吗？”
    2. 在`main`中定义一个变量，尝试在`foo`中直接使用它（不通过参数），会发生什么？反之亦然？
    3. 在`for`循环的初始化语句中定义变量`int i`，提问：“在循环体外部还能访问`i`吗？”（C++标准因版本而异，可引导讨论）。
- **知识讲解要点**：
    - 引入**作用域**概念：变量可见和可用的代码区域。
    - 详解三种作用域：
        - **局部作用域（函数作用域）**：函数内定义的变量，仅在该函数内有效。
        - **块作用域（`{}`作用域）**：在任何一对花括号`{}`内定义的变量（如`if`、`for`内部），仅在该块内有效。
        - **全局作用域**：在所有函数和类外部定义的变量，从定义处到文件末尾都有效。
    - 讲解**名字查找规则**：当使用一个变量名时，编译器优先在**当前局部作用域**查找，然后逐级向外，直到全局作用域。这解释了为什么局部变量会“遮蔽”同名的全局变量。
    - 强调作用域决定了变量的**生命周期**（何时创建与销毁）。

### 阶段五：综合演练与避坑指南

- **核心任务**：设计一个综合案例，例如一个简易的“学生成绩分析器”。包含多个函数：`inputScores`（输入成绩，使用引用参数修改数组）、`calculateAverage`（计算平均分，返回值）、`findMax`（查找最高分，返回指针或引用）、`printReport`（打印报告）。让学生分析其中函数的设计、参数传递方式的选择和作用域的影响。
- **常见错误总结**：
    1. 函数声明与定义不匹配（参数类型或数量不同）。
    2. 期望通过值传递修改实参。
    3. 在函数返回后，试图使用指向局部变量的指针或引用（悬空指针/引用）。
    4. 误以为局部变量名会覆盖全局变量是错误，这只是作用域规则。
    5. 忽略了默认参数必须从右向左设置等细节。
