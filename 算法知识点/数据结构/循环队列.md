
同学们好！我是你们的GESP、NOI、IOI专业教练。今天我们来深入剖析数据结构中一个非常经典且实用的概念——**循环队列（Circular Queue）**。

在算法竞赛（如CSP-J/S, NOIP, NOI）和工程实践中，普通队列在某些场景下会遭遇“假溢出”的瓶颈，而循环队列正是解决这一问题的利器。

---

### 一、什么是循环队列？为什么要用它？

#### 1. 普通顺序队列的痛点：假溢出
想象一下，我们用数组 `q[N]` 来实现一个队列，设定 `head` 指向队头，`tail` 指向队尾（下一个可插入位置）。
- **入队**：`q[tail++] = x`
- **出队**：`x = q[head++]`

**问题出现了：**
当我们要不断出队时，`head` 会向后移动。如果此时数组前面空出了一大片空间，但 `tail` 已经到达了数组末尾 `N`，即使前面有空位，我们也无法再入队了。这种现象叫做**“假溢出”**。

*如果不使用循环队列，我们只有两个选择：*
1.  **移动元素**：每次出队都把后面所有元素向前移一位。-> **时间复杂度 $O(N)$，太慢！** 竞赛中会超时（TLE）。
2.  **不移动**：直到 `tail` 撞墙。-> **空间利用率极低**。

#### 2. 循环队列的解决方案
循环队列将数组视为一个**首尾相接的圆环**。
- 当 `tail` 到达数组末尾时，如果数组开头有空位，`tail` 可以绕回到 `0` 继续存放数据。
- 同样，`head` 也可以绕回。

**核心思想**：利用**取模运算（%）**来实现索引的“自动回绕”。

---

### 二、核心原理与实现细节

假设数组大小为 `MAX_SIZE`。

#### 1. 指针的移动公式
这是循环队列的灵魂，请务必背下来：
- **入队后移动 tail**：`tail = (tail + 1) % MAX_SIZE`
- **出队后移动 head**：`head = (head + 1) % MAX_SIZE`

#### 2. 关键难点：如何判断“队空”和“队满”？
在循环队列中，`head == tail` 既可能表示队列为空，也可能表示队列已满（当尾巴追上脑袋时）。为了解决这个歧义，通常有两种主流策略：

**策略 A：牺牲一个存储单元（推荐，竞赛常用）**
我们规定：**当队列中只剩下一个空闲位置时，就认为队列满了。**
- **队空条件**：`head == tail`
- **队满条件**：`(tail + 1) % MAX_SIZE == head`
- **实际容量**：`MAX_SIZE - 1`

> **教练点评**：这种方法判断逻辑最简单，代码出错率最低，是NOI/IOI选手的首选。

**策略 B：增加一个计数器 `size` 或标志位 `flag`**
- 记录当前元素个数 `size`。
- **队空**：`size == 0`
- **队满**：`size == MAX_SIZE`
- 每次入队 `size++`，出队 `size--`。

> **教练点评**：逻辑直观，但多了一个变量维护，稍微繁琐一点点，但在某些需要精确知道大小的场景很有用。

#### 3. 代码模板（C++ 风格，策略 A）

```cpp
const int MAX_SIZE = 100005; // 根据题目需求调整，通常比最大数据量大一点
int q[MAX_SIZE];
int head = 0, tail = 0; // 初始化都指向0

// 判断是否为空
bool isEmpty() {
    return head == tail;
}

// 判断是否已满
bool isFull() {
    return (tail + 1) % MAX_SIZE == head;
}

// 入队
bool push(int x) {
    if (isFull()) return false; // 队列满，入队失败
    q[tail] = x;
    tail = (tail + 1) % MAX_SIZE; // 关键：取模回绕
    return true;
}

// 出队
bool pop() {
    if (isEmpty()) return false; // 队列空，出队失败
    head = (head + 1) % MAX_SIZE; // 关键：取模回绕
    return true;
}

// 获取队头元素
int front() {
    if (isEmpty()) return -1; // 或者抛出异常
    return q[head];
}

// 获取当前元素个数
int size() {
    return (tail - head + MAX_SIZE) % MAX_SIZE;
}
```

### 三、应用场景

在算法竞赛和实际开发中，循环队列主要应用于以下场景：

#### 1. BFS（广度优先搜索）
这是最常见的场景。BFS需要按层遍历图或树，必须使用队列。
- **为什么用循环队列？** 虽然STL的 `std::queue` 底层通常是 `deque`（双端队列），但在内存受限或对性能要求极高的嵌入式环境/特定题目中，手写数组实现的循环队列比 `std::queue` 更快，且内存连续，缓存命中率更高。
- **注意**：在NOI系列比赛中，如果题目内存限制非常紧（例如几MB），或者需要频繁进行百万级的入队出队操作，手写循环队列往往能节省大量内存并提升速度。

#### 2. 固定大小的缓冲区（Ring Buffer）
- **场景**：网络数据包接收、音频视频流处理、日志记录。
- **原理**：生产者不断写入数据，消费者不断读取数据。当缓冲区满时，可以选择覆盖最旧的数据（修改逻辑即可）或者阻塞生产者。循环队列天然适合这种“先进先出”且大小固定的流式处理。

#### 3. 操作系统中的任务调度
- 轮转调度算法（Round Robin）中，就绪队列通常是一个循环队列，CPU时间片用完的进程会被重新放到队尾。

### 四、竞赛避坑指南（Coach's Tips）

1.  **数组大小要开够**：
    如果你需要存 $N$ 个元素，采用“牺牲一个单元”的策略时，数组大小至少要开 $N+1$。否则明明能存 $N$ 个，结果存 $N-1$ 个就报满了。
    *错误示范*：题目说最多1000个数，你开 `q[1000]`，结果只能存999个。
    *正确示范*：开 `q[1005]` 或 `q[2000]`（留有余地）。

2.  **负数取模问题**：
    在计算 `size` 时，公式 `(tail - head + MAX_SIZE) % MAX_SIZE` 中的 `+ MAX_SIZE` 是为了防止 `tail < head` 时出现负数（虽然在无符号整数或特定语言中表现不同，但在C++中保险起见加上它）。
    *注意*：如果是纯入队出队操作，`head` 和 `tail` 始终是非负的，直接 `%` 没问题。

3.  **不要用 `std::queue` 的情况**：
    虽然 `std::queue` 很方便，但在以下情况建议手写循环队列：
    - 需要严格控制内存占用（`std::deque` 有额外的节点开销）。
    - 需要实现“覆盖写”功能（即队满时自动丢弃队头元素，这在标准库中不直接支持）。
    - 极度追求常数优化（Hand-written is faster）。

4.  **GESP/CSP-J 考点**：
    这类考试常考填空题，让你补全 `(tail + 1) % N` 这样的代码，或者判断队满的条件。一定要熟练掌握 `(tail + 1) % MAX_SIZE == head` 这个判定式。

---

### 五、总结

循环队列是用**空间换时间**（牺牲一个格子）和**数学技巧**（取模）来完美解决顺序队列“假溢出”问题的数据结构。

- **核心公式**：`index = (index + 1) % SIZE`
- **判满条件**：`(tail + 1) % SIZE == head`
- **判空条件**：`tail == head`
- **适用领域**：BFS、流式数据处理、缓冲区。

# 经典题目

作为你的教练，我为你精选了**4道**从“基础语法”到“算法应用”再到“思维拓展”的经典题目。这些题目在洛谷（Luogu）、Codeforces 或各大OJ上都非常常见，是掌握循环队列的必经之路。

---

### 第一阶段：基础语法与模拟（熟悉指针移动）

这一阶段的目的是让你**手写**一个循环队列，彻底搞懂 `head`、`tail` 和取模运算 `%` 的关系。

#### 🏆 题目 1：【模板】队列操作 / 报数问题
*   **来源**：洛谷 P1996 (约瑟夫问题变种) 或 各类教材习题“模拟队列”
*   **题目描述**：
    $n$ 个人围成一圈，从第 1 个人开始报数，报到 $m$ 的人出列，求出列顺序。
    *或者更简单的版本*：给定一系列操作（入队、出队、查询队头），模拟队列行为。
*   **为什么选它**：
    - 这是最纯粹的**模拟**。你需要手动维护 `head` 和 `tail`。
    - 你会深刻体会到：当 `tail` 到达数组末尾时，必须通过 `(tail + 1) % N` 回到开头，否则程序会崩溃或逻辑错误。
    - **训练点**：熟练掌握 `push`, `pop`, `front` 的手写实现，以及判空判满逻辑。
*   **教练提示**：
    不要直接用 `std::queue`！试着用数组 `int q[10005]` 自己写一遍。注意数组大小要开够，防止“假溢出”导致的越界。

---

### 第二阶段：广度优先搜索（BFS）的核心应用

这是循环队列在算法竞赛中**90%**的使用场景。虽然 `std::queue` 能过，但理解底层原理对优化至关重要。

#### 🏆 题目 2：【模板】走迷宫 / 营救任务
*   **来源**：洛谷 P1443 (马的遍历) 或 P1162 (填涂颜色) 或 P1036 (选数 - 虽不是典型迷宫但涉及层序) -> 推荐 **P1141 01迷宫** 或 **P1747 好奇怪的游戏**
*   **题目描述**：
    在一个 $N \times M$ 的网格中，从起点 $(sx, sy)$ 走到终点 $(ex, ey)$，只能上下左右移动，避开障碍物，求最少步数。
*   **为什么选它**：
    - BFS 的本质就是**一层一层地扩展**，必须用队列。
    - 数据量大时（如 $N, M \le 1000$），入队出队次数可能达到百万级。
    - **训练点**：理解为什么 BFS 必须用队列（先进先出保证最短路径），并观察如果手写循环队列，内存占用会比 `std::queue` 小多少（这对内存限制严格的题目很关键）。
*   **教练提示**：
    尝试对比 `std::queue<pair<int,int>>` 和你手写的 `struct Node {int x, y;} q[MAX];` 的运行时间和内存。你会发现手写数组版通常更快、更省内存。

---

### 第三阶段：滑动窗口（单调队列的前置知识）

这是循环队列的高级应用，也是 **NOIP/NOI** 的高频考点。虽然这里通常配合“单调性”使用，但底层结构依然是循环队列。

#### 🏆 题目 3：滑动窗口 / 最大最小值
*   **来源**：洛谷 P1886 (滑动窗口 / [模板] 单调队列)
*   **题目描述**：
    有一个长为 $n$ 的序列，和一个大小为 $k$ 的窗口。窗口从左向右滑动，每次滑动一个位置，求每个位置窗口内的最大值和最小值。
*   **为什么选它**：
    - 窗口滑动时，左边的元素要“出队”，右边的新元素要“入队”。
    - 这是一个典型的**固定大小缓冲区**模型。
    - **训练点**：理解如何用循环队列维护一个“动态区间”。虽然这道题标准解法是“单调队列”，但其物理结构完全依赖循环队列的索引回绕特性。如果不理解循环队列，很难写出 $O(N)$ 的解法。
*   **教练提示**：
    先尝试用普通双端队列做，再思考如果用数组模拟，下标该如何处理？特别是当窗口滑到数组末尾时，如何利用取模让逻辑继续？（注：此题通常不需要真的取模，因为窗口长度 $k$ 远小于 $n$，但理解这种“丢弃旧数据”的思想是核心）。

### 第四阶段：思维拓展与特殊技巧

#### 🏆 题目 4：银行排队系统 / 进程调度模拟
*   **来源**：PAT (Advanced Level) 1014 Waiting in Line 或 类似的模拟题
*   **题目描述**：
    多个窗口服务客户，客户到来时进入最短的队列，服务完成后离开。模拟整个过程，计算每个人的结束时间。
*   **为什么选它**：
    - 现实世界的抽象。需要维护**多个**循环队列。
    - 可能会遇到“队列满了怎么办？”的问题（是拒绝服务，还是覆盖？）。
    - **训练点**：综合运用。你需要定义一个结构体数组 `Queue q[20]`，每个里面都有 `head, tail, data[]`。这能锻炼你封装代码和管理复杂状态的能力。
*   **教练提示**：
    注意题目中的时间模拟细节。当队列满时，根据题意决定是直接 `return` 还是覆盖（如果是覆盖，就要修改标准的循环队列逻辑，允许 `tail` 追上 `head` 并覆盖数据）。
