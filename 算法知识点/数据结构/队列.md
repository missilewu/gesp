### 一、什么是队列？（核心概念）

**定义**：
队列是一种特殊的线性表，它只允许在表的前端（front）进行删除操作，在表的后端（rear）进行插入操作。

**核心特性**：
*   **先进先出 (FIFO - First In First Out)**：这是队列的灵魂。就像我们在食堂排队打饭，第一个来的人第一个打到饭并离开，后来的人必须排在后面。
*   **对比栈 (Stack)**：栈是“后进先出”（LIFO），而队列是“先进先出”（FIFO）。

**生活场景类比**：
*   打印任务队列：先发送的打印任务先被打印机处理。
*   操作系统进程调度：等待CPU处理的进程队列。
*   消息中间件：用户请求进入服务器处理队列。

### 二、队列的原理与实现方式

在竞赛中，我们通常关注两种实现方式：**数组模拟**和**标准库**。理解底层原理对于处理极端数据（如卡常、内存限制）非常重要。

#### 1. 数组模拟队列（推荐竞赛使用）
虽然C++有`std::queue`，但在NOI/IOI级别的高阶比赛中，为了追求极致的运行效率或实现特殊队列（如双端队列、单调队列），我们常手写数组模拟。

*   **基本变量**：
    *   `q[N]`：存储数据的数组。
    *   `head`：队头指针，指向当前队头元素。
    *   `tail`：队尾指针，指向**下一个**可以插入元素的位置（或者当前队尾元素，视习惯而定，下文采用指向下一个空位的习惯）。

*   **基本操作**：
    *   **入队 (Push)**：`q[tail++] = x;`
    *   **出队 (Pop)**：`head++;`
    *   **判空**：`head == tail`
    *   **取队头**：`q[head]`
    *   **取队尾**：`q[tail-1]`

*   **关键难点：循环队列 (Circular Queue)**
    如果只用普通数组，`head`和`tail`一直向后移，数组空间很快就会用完。
    **解决方案**：利用取模运算 `%`，让指针回到数组开头。
    *   入队：`q[tail] = x; tail = (tail + 1) % N;`
    *   出队：`head = (head + 1) % N;`
    *   **判满**：`(tail + 1) % N == head` (通常预留一个空位区分空和满)
    *   **判空**：`head == tail`

#### 2. C++ STL `std::queue`
适合日常练习和代码量较大的题目，开发效率高。

```cpp
#include <queue>
using namespace std;

queue<int> q;

// 入队
q.push(10); 

// 出队
q.pop(); 

// 获取队头元素
int front_val = q.front(); 

// 判断是否为空
if (q.empty()) { ... }

// 获取元素个数
int size = q.size(); 
```
*注意：STL queue 底层通常由 `deque` 或 `list` 实现，动态分配内存，速度略慢于静态数组模拟，且无法直接遍历内部元素。*

### 三、队列的经典应用场景（竞赛重点）

作为教练，我必须强调：**不要为了用队列而用队列，要识别题目模型。**

#### 1. 广度优先搜索 (BFS) —— 最经典应用
**场景**：走迷宫求最短步数、图的层次遍历、状态空间搜索。
**原理**：BFS需要按“层”扩展。先把起点入队，然后每次取出队头，将其所有未访问的邻居入队。因为队列的FIFO特性，保证了先被发现的节点（距离近的）先被处理，从而天然保证找到的是**最短路径**（在边权为1的图中）。

> **代码模板片段**：
> ```cpp
> queue<pair<int, int>> q;
> q.push({start_x, start_y});
> dist[start_x][start_y] = 0;
> 
> while(!q.empty()){
>     auto [x, y] = q.front(); q.pop();
>     // 遍历四个方向
>     for(int i=0; i<4; i++){
>         int nx = x + dx[i], ny = y + dy[i];
>         if(合法且未访问){
>             dist[nx][ny] = dist[x][y] + 1;
>             q.push({nx, ny});
>         }
>     }
> }
> ```

#### 2. 单调队列 (Monotonic Queue) —— 难点与高频考点
**场景**：滑动窗口最大值/最小值、优化动态规划（如 $dp[i] = \min(dp[j]) + val[i]$，其中 $j$ 在某个区间内）。
**原理**：维护一个队列，使得队列中的元素保持单调递增或递减。
*   **入队时**：如果新元素比队尾元素更“优”（例如求最小值时，新元素更小），则队尾元素永远不可能成为答案，直接弹出队尾，直到满足单调性再入队。
*   **出队时**：检查队头元素是否滑出了窗口范围，如果是，则弹出队头。
*   **时间复杂度**：每个元素最多入队一次、出队一次，复杂度为 $O(N)$，远优于暴力解法的 $O(NK)$。

> **典型例题**：洛谷 P1886 滑动窗口 / [NOI 2005] 瑰丽华尔兹（部分分）。

#### 3. 多源BFS
**场景**：地图上有多个起点，求所有点到最近起点的距离。
**做法**：初始化时，将**所有**起点同时入队，距离设为0，然后正常跑BFS。这相当于有一个“超级源点”连接了所有起点。

#### 4. 拓扑排序 (Topological Sort)
**场景**：课程安排、依赖关系处理、确定执行顺序。
**做法**：统计所有节点的入度，将入度为0的节点入队。每次取出队头，将其指向的节点入度减1，若减为0则入队。如果最终处理过的节点数小于总节点数，说明图中有环。

#### 5. 阻塞队列与并发（进阶/工程向）
在多线程编程或模拟复杂系统时，用于生产者-消费者模型。虽然NOI/IOI主要考察单线程算法，但理解此概念有助于系统设计题。

### 四、教练的避坑指南与备考建议

1.  **数组大小要开够**：
    *   如果是循环队列，数组大小通常要比最大元素个数多1，或者严格计算 `(tail + 1) % N == head` 的判满条件。
    *   在BFS中，队列最大长度可能达到 $N \times M$（网格图），务必根据题目数据范围估算。

2.  **结构体封装**：
    *   BFS状态往往不仅包含坐标 $(x, y)$，还可能包含步数 `step`、当前方向 `dir`、甚至掩码 `mask`（状压BFS）。一定要定义 `struct Node` 存入队列，不要试图用多个并行队列，容易出错。

3.  **单调队列的思维转换**：
    *   很多同学能写出普通队列，但遇到单调队列就卡壳。记住口诀：**“进队前踢掉不如自己的，出队前检查过期的”**。
    *   单调队列优化的DP通常是难点，建议专项训练（如：烽火传递、修剪草坪等题目）。

4.  **双端队列 (`std::deque`)**：
    *   如果需要两头都能进出，或者实现单调队列不想手写数组，可以使用 `std::deque`。它支持 `push_back`, `pop_back`, `push_front`, `pop_front`。
    *   **注意**：`deque` 的常数比数组大，在极度卡时间的题目中（如 $N=10^7$），优先考虑手写数组模拟双端队列。

5.  **0-1 BFS**：
    *   当边的权重只有 0 和 1 时，求最短路不需要堆优化的Dijkstra ($O(E \log V)$)，可以用双端队列做到 $O(V+E)$。
    *   **规则**：边权为0，从**队头**入队；边权为1，从**队尾**入队。这样能保证队列中的距离始终具有单调性。

### 第一阶段：基础语法与模拟（熟悉 `push`, `pop`, `front`）
**目标**：掌握队列的基本操作，理解 FIFO 特性，学会处理“循环”或“淘汰”逻辑。

#### 1. 洛谷 P1996 [NOIP 1996 普及组] 约瑟夫问题
*   **难度**：入门/普及-
*   **考点**：队列模拟、循环报数。
*   **题目描述**：$n$ 个人围成一圈，从 1 开始报数，报到 $m$ 的人出列，求最后出列的顺序。
*   **教练点评**：
    *   这是队列最经典的“入门礼”。
    *   **思路**：将所有人入队。每次取出队头，如果计数未到 $m$，则将该人重新放入队尾；如果到了 $m$，则输出该人编号并不再入队，计数器归零。
    *   **收获**：深刻理解“出队后重新入队”来实现循环逻辑。

#### 2. 洛谷 P1160 队列安排
*   **难度**：普及-
*   **考点**：队列的基本插入与删除，链表思维（或用数组模拟）。
*   **题目描述**：初始队列只有1号同学。后续同学可以插队在某位同学左边或右边，或者移除某位同学。
*   **教练点评**：
    *   虽然可以用双向链表做，但用队列思维理解“插入位置”很有帮助。
    *   **注意**：这道题如果用纯 `std::queue` 可能比较麻烦（因为要在中间插入），更适合用来思考**为什么普通队列不能随机访问**，从而引出链表或数组下标模拟的重要性。

---

### 第二阶段：广度优先搜索 (BFS) —— 队列的灵魂
**目标**：理解队列在图论中的应用，掌握“最短路径”模型。这是 NOI/CSP 必考内容。

#### 3. 洛谷 P1443 马的遍历
*   **难度**：普及-
*   **考点**：二维网格 BFS、结构体入队、方向数组。
*   **题目描述**：给定棋盘大小和马的起始位置，求马到达棋盘每个点的最少步数。
*   **教练点评**：
    *   **必做题！** 它是二维 BFS 的模板题。
    *   **关键点**：定义 `struct Node { int x, y, step; }`，利用队列按层扩展。
    *   **易错点**：忘记标记 `visited` 数组导致死循环；边界判断错误。

#### 4. 洛谷 P1162 填涂颜色
*   **难度**：普及-
*   **考点**：反向思维 BFS、封闭区域判定。
*   **题目描述**：在一个由 0 和 1 组成的方阵中，将被 1 包围的 0 填涂为 2。
*   **教练点评**：
    *   直接找“被包围的 0”很难，但找“没被包围的 0”（即与边界连通的 0）很简单。
    *   **思路**：从边界上的 0 开始 BFS，将所有能访问到的 0 标记为“外部”，剩下的未访问的 0 就是“内部”。
    *   **收获**：学会**正难则反**的解题策略。

#### 5. 洛谷 P1036 [NOIP 2002 普及组] 选数 (变种：BFS版) 或 P1032 字串变换
*   **推荐替代**：**洛谷 P1032 字串变换** (提高-)
*   **考点**：字符串 BFS、状态空间搜索、`map` 去重。
*   **题目描述**：给定两个字符串和一组变换规则，求最少变换次数。
*   **教练点评**：
    *   这是 BFS 从“网格图”扩展到“状态图”的经典题。
    *   **难点**：状态是字符串，需要用 `map<string, int>` 来记录访问过的状态和步数，防止重复搜索。

### 第三阶段：单调队列（进阶优化）
**目标**：突破 $O(N^2)$ 瓶颈，掌握 $O(N)$ 线性算法。这是区分普及组和提高组/省选的关键。

#### 6. 洛谷 P1886 滑动窗口 / [模板] 单调队列
*   **难度**：提高+/省选-
*   **考点**：单调队列模板、双端队列 (`deque`) 或手写数组。
*   **题目描述**：有一个大小为 $k$ 的滑动窗口，从左向右滑动，求每次窗口内的最大值和最小值。
*   **教练点评**：
    *   **单调队列的“Hello World”**。
    *   **核心逻辑**：维护一个下标递增、值单调递减（求最大值时）的队列。新元素进队前，把队尾比它小的都弹掉；队头如果超出窗口范围也弹掉。
    *   **要求**：必须能手写数组模拟版本，因为 `std::deque` 在某些极端数据下可能会超时或爆内存。

#### 7. 洛谷 P2216 [HAOI 2007] 理想的正方形
*   **难度**：提高+/省选-
*   **考点**：二维单调队列、降维打击。
*   **题目描述**：在 $a \times b$ 的矩阵中找一个 $n \times n$ 的子矩阵，使得子矩阵中最大值与最小值的差值最小。
*   **教练点评**：
    *   一维单调队列的升级版。
    *   **思路**：先对每一行做滑动窗口，得到每个位置向左 $n$ 个的最值；再对得到的结果矩阵的每一列做滑动窗口。
    *   **收获**：学会如何将二维问题拆解为两次一维处理。

### 第四阶段：特殊技巧与综合应用
**目标**：应对复杂场景，如 0-1 BFS、多源 BFS。

#### 8. 洛谷 P3956 [NOIP 2017 普及组] 棋盘
*   **难度**：普及+/提高-
*   **考点**：带权 BFS、0-1 BFS 思想、状态压缩（颜色 + 坐标）。
*   **题目描述**：在棋盘上移动，有颜色限制和花费（魔法棒），求最小花费。
*   **教练点评**：
    *   普通的 BFS 只能求步数最少，这题求**花费最少**。
    *   虽然可以用 Dijkstra，但因为边权只有 0 和 1（不用魔法棒花费0，用魔法棒花费1，或者跨越颜色花费1等），可以使用**双端队列 BFS (0-1 BFS)** 优化到 $O(NM)$。
    *   **技巧**：花费为 0 的走法从**队头**入队，花费为 1 的从**队尾**入队。

#### 9. 洛谷 P1141 01 迷宫
*   **难度**：普及+/提高-
*   **考点**：连通块、记忆化搜索/BFS、并查集（另一种解法）。
*   **题目描述**：01 矩阵，只能走到数值不同的相邻格子，问从某点出发能到达多少个格子。
*   **教练点评**：
    *   如果多次查询，每次 BFS 会超时。
    *   **思路**：利用 BFS 找出所有连通块，给每个连通块染色并记录大小。查询时直接输出该点所属连通块的大小。
    *   **收获**：理解**预处理**的重要性，避免重复计算。

### 💡 教练的最后叮嘱
1.  **判空检查**：在 `pop()` 或 `front()` 之前，永远先检查 `!q.empty()`，否则程序会崩溃（RE）。
2.  **空间预估**：BFS 时，队列最大长度可能是节点总数。如果图很大（$10^6$ 点），不要用递归代替队列，会栈溢出；同时注意内存限制。
3.  **手写优先**：在正式比赛（尤其是 NOIP/NOI）中，对于单调队列，**强烈建议手写数组模拟**。不仅速度快，而且方便调试（可以直接打印数组内容），还能灵活控制头尾指针。
