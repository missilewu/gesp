
# 基础链表形态

链表主要根据两个维度进行分类：

1. **指针方向**：是只有向后指针（单向），还是既有向前又有向后指针（双向）。
2. **连接方式**：是尾节点指向空（普通/非循环），还是尾节点指回头节点（循环）。

这两个维度组合，形成了你提到的三种核心链表结构，再加上最基础的“单向非循环链表”，共构成了**四大基础链表形态**。在GESP、NOI和IOI竞赛中，理解它们的区别对于选择合适的数据结构至关重要。

以下是详细的分类对比、结构图示及竞赛适用场景：

### 1. 四大基础链表形态分类表

|分类名称|指针方向|首尾连接|结构特征|典型应用场景|
|:--|:--|:--|:--|:--|
|**单向非循环链表**  <br>(Singly Linked List)|单向 (`next`)|断开 (尾->NULL)|`A -> B -> C -> NULL`|栈、队列、基础遍历、内存受限场景|
|**单向循环链表**  <br>(Singly Circular List)|单向 (`next`)|**闭合** (尾->头)|`A -> B -> C -> A` (成环)|**约瑟夫环**、轮询调度、死锁检测|
|**双向非循环链表**  <br>(Doubly Linked List)|**双向** (`prev`, `next`)|断开 (头<-NULL, 尾->NULL)|`NULL <- A <-> B <-> C -> NULL`|需要频繁前后移动、浏览器前进后退|
|**双向循环链表**  <br>(Doubly Circular List)|**双向** (`prev`, `next`)|**闭合** (尾->头, 头<-尾)|`... <-> C <-> A <-> ...` (无NULL)|LRU缓存、复杂模拟、音乐播放列表|

---

### 2. 详细结构与代码差异分析

#### (1) 单向循环链表 (Singly Circular Linked List)

- **定义**：最后一个节点的 `next` 指针不再指向 `NULL`，而是指向**头节点**（或第一个有效节点）。
- **关键判断**：遍历结束的条件不是 `curr == NULL`，而是 `curr->next == head` 或 `curr == head`。
- **竞赛考点**：
    - **约瑟夫环问题 (Josephus Problem)**：这是最经典的考题。$N$个人围成一圈，数到$M$出列。用单向循环链表模拟非常自然，删除节点后直接继续数，无需处理边界。
    - **判环算法**：虽然通常是用快慢指针在普通链表中找环，但单向循环链表本身就是个环。
- **C风格代码片段**：
    
    ```c
    // 遍历单向循环链表
    void traverseCircular(Node* head) {
        if (head == NULL) return;
        Node* curr = head;
        do {
            printf("%d ", curr->data);
            curr = curr->next;
        } while (curr != head); // 关键：回到头部停止
        printf("\n");
    }
    ```
    

#### (2) 双向非循环链表 (Doubly Linked List)

- **定义**：每个节点有 `prev` 和 `next`。头节点的 `prev` 是 `NULL`，尾节点的 `next` 是 `NULL`。
- **关键判断**：需要同时维护两个方向的指针，且必须处理头尾的 `NULL` 边界。
- **竞赛考点**：
    - **编辑器模拟**：光标左右移动，插入删除字符。
    - **需要回溯的场景**：比如在DFS过程中需要撤销上一步操作。
- **缺点**：代码量大，边界判断多（`if (curr->prev != NULL)`）。

#### (3) 双向循环链表 (Doubly Circular Linked List)

- **定义**：结合了双向和循环的特点。
    - 头节点的 `prev` 指向**尾节点**。
    - 尾节点的 `next` 指向**头节点**。
    - **整个链表中没有任何 `NULL` 指针**（如果使用哨兵头节点）。
- **优势**：
    - **无边界判断**：从任意节点都可以向任意方向无限遍历（当然逻辑上要停）。
    - **插入/删除极其统一**：无论是在头部、尾部还是中间插入，代码逻辑完全一致，不需要写 `if (head == NULL)` 或 `if (tail == NULL)`。
- **竞赛考点**：
    - **LRU Cache (最近最少使用)**：需要快速删除任意节点并移到头部，双向循环配合Hash表是标准解法。
    - **复杂的循环模拟**：如滑块游戏、循环缓冲区。

---

### 3. 竞赛中的选择策略 (GESP/NOI/IOI)

在考试中，面对一道模拟题，如何选择链表类型？

1. **如果是“围成一圈”的问题**（如报数、圆桌会议）：
    
    - 首选 **单向循环链表**。
    - 理由：只需要向后找，单向足够，节省内存和代码量。如果是静态链表实现，只需一个 `next` 数组。
2. **如果需要“前后随意跳转”或“频繁在头尾操作”**：
    
    - 首选 **双向循环链表**（带哨兵）。
    - 理由：代码最健壮，不容易因为漏判 `NULL` 导致 RE (Runtime Error)。特别是在删除节点时，双向可以直接找到前驱，无需从头遍历。
3. **如果内存限制极其严格 (如 64MB 以下，节点数 10^7)**：
    
    - 考虑 **单向非循环链表** 或 **静态单向链表**。
    - 理由：少一个指针域（4字节或8字节），能省下大量内存。
4. **如果题目涉及“撤销/重做”或“光标移动”**：
    
    - 必须用 **双向链表**（循环或非循环视边界需求而定）。

### 4. 结构对比图解

为了更直观地理解，我们可以想象它们的内存布局：

- **单向非循环**:  
    `[Data|Next] -> [Data|Next] -> [Data|NULL]`  
    _(走到尽头就停了)_
    
- **单向循环**:  
    `[Data|Next] -> [Data|Next] -> [Data|Next] --(指回第一个)-->`  
    _(像个戒指，没有尽头)_
    
- **双向非循环**:  
    `NULL <- [Prev|Data|Next] <-> [Prev|Data|Next] <-> [Prev|Data|Next] -> NULL`  
    _(两头堵死，中间互通)_
    
- **双向循环**:  
    `<--(尾指头)-- [Prev|Data|Next] <-> [Prev|Data|Next] <-> [Prev|Data|Next] --(头指尾)-->`  
    _(完美的环，前后互通，无NULL)_
    

### 总结

你提到的**双链表**（通常指双向非循环）、**单向循环链表**、**双向循环链表**不仅是存在的，而且是链表知识体系中的**核心分类**。

- **GESP 3-4级**：重点掌握单向链表（非循环）的创建和遍历。
- **GESP 5-6级 & NOI 普及组**：必须熟练掌握**单向循环链表**（解决约瑟夫环）和**双向链表**的基本操作。
- **NOI 提高组 & IOI**：倾向于使用**静态链表**来模拟上述所有结构，或者使用**双向循环链表**来处理复杂的数据维护（如平衡树的手写实现中有时会用到类似结构，或者作为高级数据结构的底层组件）。

在编写代码时，**双向循环链表 + 哨兵节点** 通常是功能最强大且Bug最少的选择，除非题目明确限制了内存或只需要单向功能。


# 扩展链表形态

除了基础的单向、双向、循环链表外，在计算机科学和算法竞赛（NOI/IOI）中，为了优化特定的操作（如**快速查找**、**区间操作**、**版本控制**或**内存效率**），衍生出了许多**高级或特殊形态的链表**。

以下是这些特殊形态链表的详细分类、原理及竞赛应用场景：

---

### 1. 跳跃链表 (Skip List)

- **核心思想**：**“空间换时间”** + **“多层索引”**。
    - 在普通单链表的基础上，随机地为部分节点建立“高层”指针。
    - 第0层是完整链表，第1层每隔约2个节点有一个指针，第2层每隔约4个节点……以此类推。
    - 查找时从最高层开始跳着走，遇到目标附近再降级到下一层。

- **竞赛应用**：
    - **平衡树的替代品**：当题目需要有序集合（支持 `lower_bound`, `rank` 等操作），但手写红黑树或AVL树太复杂时，跳跃链表是极佳的替代方案（代码量小，常数小）。
    - **动态第K大/第K小问题**。
- **特点**：基于概率，最坏情况 $O(N)$，但在随机数据下表现极佳。

### 2. 块状链表 (Block Linked List / Unrolled Linked List)

- **核心思想**：**“链表 + 数组”的混合体**（分块思想）。
    - 链表的每个节点不再存储一个数据，而是存储一个**定长数组**（Block，通常大小为 $\sqrt{N}$）。
    - 链表维护这些块的顺序，块内维护具体数据。
- **复杂度**：插入、删除、查询均为 $O(\sqrt{N})$。
- **竞赛应用**：
    - **区间修改与查询**：这是**分块算法**的数据结构基础。
    - **代替线段树**：当线段树难以维护（如复杂的插入删除导致区间下标变化）时，块状链表可以暴力维护块内数组，代码极其短小，适合“骗分”或解决特定难题。
    - **文本编辑器模拟**：处理大量字符的插入删除。
- **优势**：实现比线段树简单，常数较小，支持动态插入。

### 3. 静态链表 (Static Linked List)

- **核心思想**：**“用数组模拟指针”**。
    - 不使用 `malloc/new`，而是预定义一个大数组 `pool[MAXN]`。
    - 节点的 `next` 不再是内存地址指针，而是数组的**下标**（整数）。`-1` 或 `0` 表示空。
    - 通常配合一个“空闲链表”（Free List）来管理哪些下标可用。
- **竞赛应用**：**NOI/IOI 中的首选实现方式**。
    - **图的邻接表**：存储图结构时，静态链表比 `vector` 更快且省内存。
    - **避免 MLE/TLE**：动态分配内存慢且碎片化，静态链表一次性分配，速度极快，无内存泄漏风险。
    - **可持久化数据结构的基础**：方便复制节点。
- **代码特征**：
    
    ```cpp
    struct Node { int val, next; } pool[100005];
    int head, idx = 0; // idx 充当 malloc 的返回值
    ```
    

### 4. 可持久化链表 (Persistent Linked List)

- **核心思想**：**“版本控制”** + **“路径复制”**。
    - 每次修改（插入/删除）时，不直接修改原节点，而是**复制**受影响的节点链，生成一个新版本的头指针。
    - 未受影响的节点由新旧版本**共享**。

- **竞赛应用**：
    - **可持久化线段树（主席树）**：虽然叫树，底层逻辑常借用链表的节点复用思想。
    - **历史版本查询**：题目要求“查询第K次操作后的链表状态”。
    - **回滚操作**：支持撤销到任意历史步骤。

### 5. 十字链表 (Orthogonal List) & 邻接多重表

- **核心思想**：**“多维指针”**，用于存储复杂关系。
    - **十字链表**：专门用于**有向图**。每个节点既有“出边”链表，又有“入边”链表。同一个弧节点同时存在于两个链表中。
    - **邻接多重表**：专门用于**无向图**。每条边只存储一次，但被两个顶点共享，方便同时遍历两个顶点的关联边。
- **竞赛应用**：
    - **稀疏矩阵运算**：快速定位行和列的非零元素。
    - **复杂图论题**：需要频繁删除边或同时访问入度/出度信息的题目。

### 6. 异或链表 (XOR Linked List)

- **核心思想**：**“位运算压缩空间”**。
    - 双向链表需要两个指针 (`prev`, `next`)。异或链表只存一个值：`ptrdiff = prev XOR next`。
    - 遍历时，利用公式 `next = ptrdiff XOR prev` 推导下一个节点地址。
- **竞赛应用**：
    - **极度节省内存**：在内存限制极其苛刻（如嵌入式或特殊OI题）且必须双向遍历时使用。
    - **注意**：在标准C++竞赛中较少见，因为调试困难且不符合常规内存模型，更多出现在黑客松或特定底层考察中。

### 7. 展开链表 (Unrolled Linked List)

- **核心思想**：类似块状链表，但更侧重于**缓存友好性**。
    - 节点内部是一个紧凑的数组，填满后才分裂。
    - 目的是减少指针跳转带来的 CPU Cache Miss。
- **应用**：主要用于工程优化（如 C++ STL 的某些实现变体），竞赛中通常归类为块状链表。

---

### 总结：竞赛选型指南

|链表形态|核心优势|典型考题场景|推荐指数 (NOI/IOI)|
|:--|:--|:--|:--|
|**静态链表**|**速度最快**，无内存泄漏，易调试|图的邻接表、大规模数据模拟|⭐⭐⭐⭐⭐ (必会)|
|**块状链表**|支持**动态区间操作**，代码短|区间插入/删除/求和，代替线段树|⭐⭐⭐⭐ (高分利器)|
|**跳跃链表**||动态排名、平衡树替代|⭐⭐⭐ (备选方案)|
|**可持久化链表**|**保留历史版本**|历史状态查询、主席树基础|⭐⭐⭐ (高级考点)|
|**十字链表**|高效处理**有向图/矩阵**|稀疏矩阵、复杂图遍历|⭐⭐ (特定场景)|
|**异或链表**|空间压缩到极致|极端内存限制题|⭐ (罕见)|

### 给考生的建议

1. **掌握静态链表**：在写任何链表题（尤其是图论）时，养成用数组模拟链表的习惯，这能帮你避开很多指针错误和超时问题。
2. **学会块状链表**：当你发现线段树太难写，或者题目涉及大量的“区间插入”导致下标频繁变动时，块状链表是救命稻草。
3. **理解跳跃链表**：如果你不想背红黑树或Treap的代码，跳跃链表是解决有序集合问题的最佳“偷懒”方案（只要题目不卡常数或构造极端数据）。

这些高级形态本质上都是为了解决**基础链表查找慢 ($O(N)$)** 或 **数组插入慢 ($O(N)$)** 的痛点而诞生的混合结构。
