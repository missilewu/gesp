# 编程题1解析

这道题目是典型的**算法优化**问题，考察了**二分答案**、**数学推导**以及**贪心策略**的综合运用。

针对 GESP 五级及以上（NOI/IOI 方向）的考生，这道题是一个非常好的区分度题目，因为它不仅要求你会写代码，还要求你有很强的数学建模能力。

---

### 1. 题意的理解

**场景描述：**
小 A 有两种货币（券）：课堂优秀券（$n$ 张）和作业优秀券（$m$ 张）。
他想兑换奖品，有两种兑换方案：
*   **方案一：** 消耗 $a$ 张课堂券 + $b$ 张作业券。
*   **方案二：** 消耗 $b$ 张课堂券 + $a$ 张作业券。

**目标：**
求小 A 最多能兑换多少份奖品。

**核心逻辑：**
这是一个资源分配问题。我们需要决定兑换多少份方案一，多少份方案二，使得总份数最大。

---

### 2. 题目核心要求

1.  **输入规模巨大：** 注意数据范围，$n, m$ 高达 $10^9$。这意味着 $O(n)$ 的暴力循环或者是模拟法（一张张兑换）会直接超时（TLE）。我们需要 $O(\log n)$ 级别的算法。
2.  **混合兑换：** 不能只盯着一种方案兑换，必须混合使用两种方案才能达到最优。
3.  **整数运算：** 所有的券都是整数，不能切分。

---

### 3. 解题思路

#### 第一步：预处理（对称性优化）
观察题目，方案一和方案二其实是对称的。
为了简化逻辑，我们可以假设：
*   $n \le m$（课堂券少，作业券多）
*   $a \le b$（方案一消耗的课堂券少，方案二消耗的课堂券多）

**为什么要这样做？**
如果不交换，我们需要讨论很多种情况（比如 $n$ 大 $a$ 小，或者 $n$ 小 $a$ 大）。
通过 `swap` 操作，我们强制让 $n$ 成为“短板”资源，$a$ 成为“省 $n$”的方案。
此时：
*   **方案一 ($a, b$)**：消耗较少的 $n$，较多的 $m$。这是**保护短板**的方案。
*   **方案二 ($b, a$)**：消耗较多的 $n$，较少的 $m$。这是**消耗短板**的方案。

#### 第二步：二分答案
直接求“最多兑换多少份”很难，因为涉及到两个变量的组合。
但是，如果我们**猜测**一个答案 $k$（即兑换 $k$ 份），判断能否凑出来就相对容易了。
由于答案具有单调性（如果能兑换 $k$ 份，那一定能兑换 $k-1$ 份），我们可以对**奖品份数**进行二分查找。

#### 第三步：设计 Check 函数（贪心策略）
这是本题最难的地方。假设我们要兑换 $k$ 份奖品，怎么判断手里的券够不够？

1.  **底线思维：**
    每一份奖品，无论选哪种方案，至少都要消耗 $\min(a, b)$ 即 $a$ 张课堂券。
    所以，$k$ 份奖品至少需要 $k \times a$ 张课堂券。
    *   如果 $n < k \times a$，直接失败。

2.  **填坑思维（贪心）：**
    为了凑齐 $k$ 份，我们优先使用**方案一**（消耗 $a$ 张课堂券，$b$ 张作业券），因为它省课堂券。
    假设 $k$ 份全用方案一：
    *   消耗课堂券：$k \times a$
    *   消耗作业券：$k \times b$

    **情况分析：**
    *   如果作业券够用（$m \ge k \times b$），那太棒了，直接成功。
    *   如果作业券不够用（$m < k \times b$），说明我们必须把一部分“方案一”换成“方案二”。
        *   每把 1 个方案一换成方案二，作业券消耗会减少 $(b - a)$。
        *   我们需要补足的作业券缺口是：$(k \times b - m)$。
        *   需要替换的份数 $t = \lceil \frac{k \times b - m}{b - a} \rceil$。
        *   替换后，课堂券的消耗会增加。我们需要检查：剩下的课堂券是否足够支付这些替换带来的额外消耗？

---

### 4. 样例的分析

**样例 1：**
*   输入：$n=8, m=8, a=2, b=1$
*   预处理：$n, m$ 已经是 $8, 8$。但 $a > b$，交换后变为 $a=1, b=2$。
    此时：我有 8 张课堂券，8 张作业券。方案一(1课+2作)，方案二(2课+1作)。


---

### 5. 完整的代码和逻辑解析

这里提供一份标准的 C++ 代码实现，并附带详细注释。

```cpp
#include <cstdio>
#include <algorithm>
using namespace std;

// 全局变量方便 check 函数访问
int n, m, a, b;

// 检查是否能兑换 v 份奖品
bool check(int v) {
    // 1. 转为 long long 防止乘法溢出
    // 计算如果全部用“省课堂券”的方案（即方案一）需要的资源
    long long need_n_all_a = 1ll * v * a;
    long long need_m_all_b = 1ll * v * b;

    // 2. 基础判断：如果连最省课堂券的方案都满足不了课堂券数量，直接失败
    if (need_n_all_a > n) return false;

    // 3. 判断作业券是否足够
    if (need_m_all_b <= m) {
        // 作业券也够，那肯定行
        return true;
    } else {
        // 作业券不够，需要把部分方案一换成方案二
        // 缺多少作业券？
        long long diff_m = need_m_all_b - m;

        // 每换一个方案，能省多少作业券？(b - a)
        // 需要换多少个？向上取整：(diff_m + (b - a) - 1) / (b - a)
        long long t = (diff_m + (b - a) - 1) / (b - a);

        // 换了 t 个方案二后，课堂券会增加消耗
        // 新的课堂券需求 = 原需求 + t * (b - a)
        long long final_need_n = need_n_all_a + t * (b - a);

        // 检查课堂券够不够
        return final_need_n <= n;
    }
}

int main() {
    scanf("%d%d", &n, &m);
    scanf("%d%d", &a, &b);

    // 【核心技巧】统一顺序，减少分类讨论
    // 保证 n <= m (n是短板)
    if (n > m) swap(n, m);
    // 保证 a <= b (a是省资源的消耗)
    if (a > b) swap(a, b);

    // 特殊情况：如果 a == b，两种方案一样，直接看 n/a
    if (a == b) {
        printf("%d\n", n / a);
        return 0;
    }

    // 二分答案
    int l = 0, r = n; // 最多也就 n 份（因为 a>=1）
    while (l < r) {
        // 向上取整防止死循环
        int mid = (l + r + 1) >> 1;
        if (check(mid)) {
            l = mid; // 可行，尝试更多
        } else {
            r = mid - 1; // 不可行，减少
        }
    }
    printf("%d\n", l);
    return 0;
}
```

### 6. 参考代码的逻辑解析和注释

针对你提供的参考代码，有几个非常“竞赛风”的写法需要重点掌握：

1.  **`1ll * v * a` (防溢出)**
    *   **原因：** $v$ 和 $a$ 都是 `int`，如果直接相乘可能会超过 `int` 的范围（约 $2 \times 10^9$）。
    *   **原理：** `1ll` 是 `long long` 类型。C++ 中运算会自动向高精度转换，所以 `1ll * v * a` 整个表达式都会按 `long long` 计算。

2.  **`swap(n, m)` 和 `swap(a, b)`**
    *   这是一种**归一化**技巧。通过强制让 $n$ 变小、$a$ 变小，我们只需要写一套逻辑（优先用方案一，不够了再换方案二），而不需要写“如果 $n$ 大怎么办”、“如果 $a$ 大怎么办”的 `if-else`。

3.  **向上取整技巧**
    *   代码中：`(y - m + (b - a) - 1) / (b - a)`
    *   这是整数除法向上取整的标准公式：$\lceil \frac{X}{Y} \rceil = \frac{X + Y - 1}{Y}$。
    *   在这里，$X$ 是作业券的缺口，$Y$ 是替换一次能省下的券数。

---

### 7. 易错点和注意事项

1.  **数据溢出 (Overflow)：**
    *   题目中 $n, m$ 是 $10^9$，但计算过程中会有乘法（比如份数 $\times$ 单价），结果可能达到 $10^{14}$，远超 `int` 范围。**所有涉及乘法的中间变量必须用 `long long`。**

2.  **二分死循环：**
    *   当使用 `while (l < r)` 时：
    *   如果写 `l = mid`，那么 `mid` 必须写为 `(l + r + 1) / 2`（向上取整）。
    *   如果写 `r = mid`，那么 `mid` 必须写为 `(l + r) / 2`（向下取整）。
    *   本代码使用的是第一种（找最大可行解）。

3.  **除以零错误：**
    *   在计算 `t` (替换次数) 时，分母是 `b - a`。
    *   如果 $a = b$，分母为 0。所以必须在二分前特判 `if (a == b)` 的情况。

4.  **逻辑陷阱：**
    *   不要贪心地认为“只用方案一”或者“只用方案二”就是最优的。
    *   例如：$n=100, m=2$，方案(1, 100) 和 (100, 1)。
        *   只用方案一：受限于 $m$，只能换 0 个。
        *   只用方案二：受限于 $n$，只能换 1 个。
        *   其实这题数据有点极端，但在一般情况下，混合使用往往能填补资源的空缺。

# 编程题2解析

这道题虽然代码量不大，但考察了数论中的核心性质，是一道非常经典的“思维题”。

---

### 1. 题意的理解

题目给定 $n$ 个正整数 $a_1, a_2, \dots, a_n$，以及 $q$ 组询问。
对于第 $i$ 组询问（其中 $i$ 从 1 到 $q$），我们需要计算这 $n$ 个数分别加上 $i$ 之后的最大公因数（GCD）。
即求：$\gcd(a_1+i, a_2+i, \dots, a_n+i)$。

**关键点：**
- 输入数据量较大（$n, q$ 可达 $10^5$），直接暴力计算每组询问的 GCD 会导致超时。
- 需要利用数学性质优化计算过程。

### 2. 题目核心要求

1.  **多组询问处理**：需要高效地处理 $q$ 次查询。
2.  **最大公因数计算**：熟练掌握 GCD 的计算方法（辗转相除法）。
3.  **数学推导**：利用 GCD 的差值性质将复杂问题简化。

### 3. 解题思路

#### 暴力法的局限性
如果对于每一次询问 $i$，我们都遍历一遍数组计算 $n$ 个数的 GCD，时间复杂度是 $O(q \times n \times \log(\max A))$。
在最坏情况下，$10^5 \times 10^5 = 10^{10}$，远超 1.0s 的时间限制，因此必须寻找 $O(n + q)$ 或 $O(n \log n + q)$ 的解法。

#### 数学性质优化（核心考点）
我们需要利用 GCD 的一个重要性质：**更相减损术**原理。
即：$\gcd(x, y) = \gcd(x, y-x)$。
推广到多个数：$\gcd(x, y, z) = \gcd(x, y-x, z-y, \dots)$。

对于题目要求的 $\gcd(a_1+i, a_2+i, \dots, a_n+i)$，我们可以将其变形：
设 $x = a_1 + i$。
原式 $= \gcd(a_1+i, (a_2+i)-(a_1+i), (a_3+i)-(a_1+i), \dots, (a_n+i)-(a_1+i))$
注意这里为了方便计算，我们通常取相邻差值的 GCD，效果是一样的。
原式 $= \gcd(a_1+i, a_2-a_1, a_3-a_2, \dots, a_n-a_{n-1})$

**推导结论：**
1.  不管 $i$ 是多少，数组中**相邻元素之差**是不变的（常数）。
2.  我们可以预先计算所有相邻元素差值的 GCD，记为 `g`。
    即：`g = gcd(a[2]-a[1], a[3]-a[2], ..., a[n]-a[n-1])`。
3.  对于第 $i$ 次询问，结果就是 `gcd(第一个数+i, g)`。
    即：`ans = gcd(a[1] + i, g)`。

这样，预处理差值的 GCD 需要 $O(n)$，每次询问只需要 $O(\log(\max A))$，总复杂度完全符合要求。

### 4. 样例的分析

**样例 1:**
- 输入：`5 3`，数组 `6 9 12 18 30`
- 排序后（代码中进行了排序，虽然题目未明确要求，但排序方便计算差值）：`6 9 12 18 30`
- **预处理差值 GCD (`g`)**：
    - 差值序列：`3, 3, 6, 12`
    - `g = gcd(3, 3, 6, 12) = 3`
- **询问 1 ($i=1$)**：
    - 第一个数变 $6+1=7$。
    - 结果 = `gcd(7, 3)` = **1**。
- **询问 2 ($i=2$)**：
    - 第一个数变 $6+2=8$。
    - 结果 = `gcd(8, 3)` = **1**。
- **询问 3 ($i=3$)**：
    - 第一个数变 $6+3=9$。
    - 结果 = `gcd(9, 3)` = **3**。
- 输出与样例一致。

### 5. 完整的代码和逻辑解析

参考代码已经非常精简，下面我对其进行详细的逻辑拆解。

```cpp
#include <cstdio>
#include <algorithm>
using namespace std;

// 定义数组大小，比题目最大值稍大以防止越界
const int N = 1e5 + 5;

int n, q, a[N], g;

// 自定义 GCD 函数（辗转相除法）
// 递归写法：gcd(a, b) = gcd(b, a%b)，直到其中一个为0
int gcd(int a, int b) {
    if (a == 0 || b == 0)
        return a + b; // 如果有一个是0，返回另一个（因为 0+b=b, a+0=a）
    return gcd(b, a % b);
}

int main() {
    // 1. 输入 n 和 q
    scanf("%d%d", &n, &q);

    // 2. 输入数组
    for (int i = 1; i <= n; i++)
        scanf("%d", &a[i]);

    // 3. 排序
    // 题目虽然没明说数组有序，但为了利用“差值不变”的性质，排序是最稳妥的。
    // 因为 gcd(a,b) = gcd(a, |b-a|)，排序后 a[i]-a[i-1] 必为正数，处理方便。
    sort(a + 1, a + n + 1);

    // 4. 预处理差值的 GCD
    // 初始 g 默认为 0，因为 gcd(0, x) = x，这样第一个差值可以直接赋值给 g
    for (int i = 2; i <= n; i++)
        g = gcd(g, a[i] - a[i - 1]);

    // 5. 处理 q 次询问
    for (int i = 1; i <= q; i++) {
        // 核心公式：gcd(当前第一个数, 差值的GCD)
        // 注意题目要求的 i 是从 1 开始累加的
        printf("%d\n", gcd(g, a[1] + i));
    }

    return 0;
}
```

### 6. 参考代码的逻辑解析和注释

- **`const int N = 1e5 + 5;`**
    - **考点**：数组越界防护。题目 $N \le 10^5$，开大一点是竞赛好习惯。
- **`sort(a + 1, a + n + 1);`**
    - **考点**：贪心/预处理。虽然 $\gcd(x, y) = \gcd(x, |x-y|)$，但排序后直接相减 $a[i]-a[i-1]$ 可以保证非负，避免处理绝对值函数 `abs()`，代码更简洁且不易出错。
- **`g = gcd(g, a[i] - a[i - 1]);`**
    - **考点**：前缀思想/累积计算。利用循环不断求当前 GCD 和新差值的 GCD，最终得到整个数组差分的 GCD。初始 `g=0` 是个技巧，因为 `gcd(0, x) = x`。
- **`gcd(g, a[1] + i)`**
    - **考点**：公式应用。将 $O(n)$ 的计算降维打击成 $O(1)$。

### 7. 易错点和注意事项

1.  **数据范围与排序**：
    - 题目没有保证输入的 $a_i$ 是有序的。如果不排序，计算差值 $a[i]-a[i-1]$ 可能会出现负数。虽然数学上 GCD 对负数取绝对值即可，但在编程中容易出错（例如 C++ 中负数取模结果仍为负）。**强烈建议先排序**。
2.  **GCD 的边界情况**：
    - 当 $n=1$ 时，没有差值。此时 `g` 保持为 0。结果就是 `gcd(0, a[1]+i)`，即 `a[1]+i` 本身。这是正确的，因为只有一个数，最大公因数就是它自己。代码逻辑天然支持这一点。
3.  **变量类型**：
    - 题目中 $a_i \le 1000$，但加上 $i$ 后（$i \le 10^5$），数值在 `int` 范围内，不需要 `long long`。但如果题目数据范围扩大，需注意溢出。
4.  **时间复杂度陷阱**：
    - 初学者容易直接写双重循环（外层 $q$，内层 $n$），这在 $10^5$ 的数据规模下必然 **Time Limit Exceeded (TLE)**。必须通过数学推导将内层循环消除。

## 如何推导出解题思路

在考试的高压环境下，面对这道题如果一时想不起“**更相减损术**”或 GCD 的差值性质，我们完全可以通过**逻辑推理**和**特殊值验证**现场推导出来。

以下是我在考场上引导学生进行思维推导的三个步骤：

### 第一步：从定义出发（寻找不变量）

首先，我们要回归最大公因数（GCD）的定义。
假设 $g$ 是 $a_1+i, a_2+i, \dots, a_n+i$ 的最大公因数。
这意味着什么？意味着这组数中的**每一个数**都能被 $g$ 整除。

即：
$$ (a_1 + i) \equiv 0 \pmod g $$
$$ (a_2 + i) \equiv 0 \pmod g $$
$$ \dots $$
$$ (a_n + i) \equiv 0 \pmod g $$

### 第二步：利用同余性质消元（关键推导）

既然这些数都能被 $g$ 整除，那么它们之间的**差**也一定能被 $g$ 整除。这是整除的基本性质：如果 $A$ 能被 $k$ 整除，$B$ 也能被 $k$ 整除，那么 $A-B$ 也能被 $k$ 整除。

让我们试着做减法：
$$ (a_2 + i) - (a_1 + i) = a_2 - a_1 $$
$$ (a_3 + i) - (a_2 + i) = a_3 - a_2 $$

你会发现一个惊人的现象：**变量 $i$ 被消掉了！**

这说明：无论 $i$ 是多少，这组数的公因数 $g$，必须也是它们**原始差值**（如 $a_2-a_1$, $a_3-a_2$ 等）的因数。

### 第三步：构建新的 GCD 关系

结合上面的推导，我们可以得出结论：
所求的答案 $\gcd(a_1+i, a_2+i, \dots, a_n+i)$ 实际上由两部分组成：
1. **差值的公因数**：$\gcd(a_2-a_1, a_3-a_2, \dots, a_n-a_{n-1})$。这部分与 $i$ 无关，是一个定值。
2. **基准项**：剩下的那个无法通过相减消去的项，通常取最小的那个数作为基准，即 $a_1 + i$。

所以公式就变成了：
$$ \text{Ans} = \gcd(\underbrace{\gcd(a_2-a_1, a_3-a_2, \dots)}_{\text{定值 } G}, \quad a_1 + i) $$

---

### 考场上的“特殊值验证法”（Double Check）

如果你推导出了上面的公式，但不敢确信，可以用题目给的样例快速验证一下。

**以样例 1 为例：**
数据：6, 9, 12, 18, 30
询问 $i=1$ 时，求 $\gcd(7, 10, 13, 19, 31)$。显然互质，答案是 1。

用我们的推导公式算算看：
1. 计算相邻差值：
   - $9 - 6 = 3$
   - $12 - 9 = 3$
   - $18 - 12 = 6$
   - $30 - 18 = 12$
2. 求差值的 GCD（定值 $G$）：
   $\gcd(3, 3, 6, 12) = 3$。
3. 结合基准项 $a_1 + i$：
   当 $i=1$ 时，基准项为 $6+1=7$。
   最终答案 $= \gcd(G, a_1+i) = \gcd(3, 7) = 1$。

**结果一致！** 这就能让你在考场上非常有信心地写出代码。

### 总结给学生的建议

在考场上遇到这类数论题，不要死记硬背公式。记住这个思维链条：
1. **公因数意味着整除**。
2. **整除意味着差也能被整除**。
3. **相减可以消去变化的量（$i$），留下不变的量（差值）**。

这就是“更相减损术”在代数变形中的本质体现。掌握这个逻辑，哪怕忘了名字，也能现场推导出解法。
