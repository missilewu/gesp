### 第1题：循环单链表的遍历

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：循环单链表的遍历逻辑与`do-while`循环的应用。

**2. 知识点详解**
*   **循环链表特性**：链表的尾节点（`next`）指向头节点，而不是`nullptr`。
*   **遍历逻辑**：
    *   普通单链表通常用 `while(p != nullptr)`。
    *   循环单链表必须记录头节点的位置。遍历的终止条件是“当前节点的下一个节点回到头节点”或者“当前节点再次等于头节点”。
    *   本题代码中，`p`初始指向`head`。如果使用`while`，第一次判断就会因为`p == head`而跳过（除非先移动指针）。因此，**先执行（打印）再判断**的`do-while`结构最为合适。

**3. 选项对错分析**

| 选项 | 代码逻辑 | 错误原因 |
| :--- | :--- | :--- |
| **A** | `while(p != nullptr)` | **逻辑错误**。循环链表中不存在`nullptr`（除非是空链表），这会导致死循环或不执行。 |
| **B** | `while(p->next != nullptr)` | **逻辑错误**。同上，循环链表没有`nullptr`。且如果链表只有一个节点，`p->next`指向自己，条件为真，但打印后`p`移动会出错。 |
| **C** | `do{...}while(p != head);` | **正确**。先打印当前节点（head），再移动指针。当指针再次走到head的前一个节点（即尾节点）并移动后，`p`会等于`head`，循环结束。 |
| **D** | `for(; p; p=p->next)` | **逻辑错误**。判断条件`p`等同于`p != nullptr`，同样不适用于循环链表。 |

**4. 答案**
**C**

**5. 易错点分析**
*   **混淆链表类型**：考生容易将循环链表与普通链表的终止条件（`nullptr`）混淆。
*   **头节点处理**：忘记`do-while`循环会先执行一次，导致担心头节点丢失，但实际上这里正是需要先打印头节点。

**6. 相关的知识点**
*   单链表的头插法与尾插法
*   双链表的插入删除操作（第2、3题涉及）

### 第2题：区块链（链表插入）

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：链表节点的创建与指针更新（头插法/尾插法逻辑）。

**2. 知识点详解**
*   **题目背景**：虽然题干提到了“区块链”，但本质上是一个**单链表**（每个区块指向前一个区块`prev`）。
*   **插入逻辑**：
    1.  创建新节点：新节点的`prev`指针应指向当前的`tail`（即原来的最后一个区块）。
    2.  更新头指针：创建后，`tail`指针应该指向这个新创建的节点，因为新区块是加在链尾的。
*   **构造函数分析**：`Block(int idx, const string& d, Block* p)`，第三个参数是`prev`。

**3. 选项对错分析**

| 选项 | 操作步骤 | 错误原因 |
| :--- | :--- | :--- |
| **A** | `tail = newBlock->prev;` | **错误**。`newBlock->prev`指向的是原来的`tail`，这行代码让`tail`回退到了旧节点，没有指向新节点。 |
| **B** | `tail = newBlock;` | **正确**。先创建节点（指针指向旧tail），再将全局`tail`指向新节点。 |
| **C** | `newBlock(..., tail->prev)` | **错误**。新节点的`prev`应该直接指向当前的`tail`，而不是`tail`的前一个。 |
| **D** | 组合了C和A的错误 | **错误**。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **指针方向混淆**：题目定义的链表是`prev`指向前一个，这与常规单链表`next`指向后一个相反。考生容易惯性思维写错连接方向。
*   **顺序问题**：虽然本题没有考察，但要注意如果先移动`tail`，再创建节点，会导致无法找到原来的`tail`。

**6. 相关的知识点**
*   链表的插入操作（第3题涉及删除）
*   结构体构造函数的初始化列表

### 第3题：单链表与双链表的删除复杂度

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：单链表与双链表在删除节点时的时间复杂度差异。

**2. 知识点详解**
*   **双链表删除**：已知要删除的节点`node`。
    *   只需要修改前后指针：`node->prev->next = node->next;` 和 `node->next->prev = node->prev;`。
    *   **时间复杂度：$O(1)$**。
*   **单链表删除**：已知要删除的节点`node`，但单链表只有`next`指针。
    *   要删除`node`，必须修改`node`前驱节点的`next`指针。
    *   但是，单链表无法直接找到前驱。代码中给出了`deleteSNode(head, node)`，它必须从`head`开始遍历，找到`node`的前一个节点。
    *   **时间复杂度：$O(n)$**。

**3. 选项对错分析**
*(注：原题OCR文本中选项A-D的具体复杂度数值缺失，但根据标准答案C和逻辑推断，正确选项应描述为：双链表$O(1)$，单链表$O(n)$)*

*   **正确描述**：双链表删除指定节点是 **$O(1)$**，单链表是 **$O(n)$**。
*   **错误选项**：通常会包含“单链表也是$O(1)$”或者“双链表是$O(n)$”的干扰项。

**4. 答案**
**C** (对应双链表$O(/1)$，单链表$O(n)$的描述)

**5. 易错点分析**
*   **误区**：很多初学者认为“链表删除都是$O(1)$”，忽略了单链表找前驱的开销。
*   **特例**：如果单链表删除的是“头节点”，那确实是$O(1)$；但题目问的是“指定节点”，通常指任意节点。

**6. 相关的知识点**
*   链表的时间复杂度分析
*   数组与链表的优缺点对比（随机访问 vs 插入删除）

**3. 选项对错分析**
*   **D (9)**：12不能被9整除，故不可能。

**4. 答案**
**D**

**5. 易错点分析**
*   **计算粗心**：算错 $a-b$ 的值。
*   **概念混淆**：混淆了“模”和“余数”的概念。

### 第5题：欧几里得算法（GCD）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：欧几里得算法（辗转相除法）的递归与迭代实现、空间复杂度分析。

**2. 知识点详解**
*   **gcd1 (递归)**：利用函数调用栈。时间复杂度 $O(\log n)$，空间复杂度 $O(\log n)$（因为有递归调用栈）。
*   **gcd2 (迭代)**：利用循环变量。时间复杂度 $O(\log n)$，空间复杂度 $O(1)$。
*   **效率对比**：当数值较大时，递归版本可能会因为栈帧过多导致内存占用高，甚至栈溢出；迭代版本效率更稳定，通常执行效率更高（无函数调用开销）。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | gcd1()实现为递归方式 | **正确**。 |
| **B** | gcd2()实现为迭代方式 | **正确**。 |
| **C** | gcd1()需要较多额外辅助空间 | **正确**。递归调用栈占用空间。 |
| **D** | gcd1()比gcd2()执行效率更高 | **错误**。通常情况下，迭代（gcd2）效率更高，递归有函数调用开销。 |

**4. 答案**
**D**

**5. 易错点分析**
*   **误区**：认为递归代码短就代表效率高。实际上在GCD这种简单迭代就能解决的问题上，递归的常数开销更大。
*   **空间复杂度**：容易忽略递归栈的空间消耗。

**6. 相关的知识点**
*   最小公倍数（LCM）：$LCM(a,b) = a*b / GCD(a,b)$
*   二进制gcd算法（进阶优化）

### 第6题：唯一分解定理

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：唯一分解定理（算术基本定理）的定义。

**2. 知识点详解**
*   **定理内容**：任何一个大于1的自然数N，如果N不是质数，那么N可以**唯一分解**为有限个质数的乘积，即 $N = p_1 \times p_2 \times ... \times p_n$。
*   **核心关键词**：“大于1的合数”、“质数的乘积”、“唯一”。
*   **辨析**：这与“哥德巴赫猜想”（任何大于2的偶数都可以表示为两个素数之和）是完全不同的概念。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | 任何正整数都可以表示为两个素数的和。 | **错误**。这是哥德巴赫猜想的弱化版，且不严谨（如数字3无法这样表示）。 |
| **B** | 任何大于1的合数都可以唯一分解为有限个质数的乘积。 | **正确**。完全符合唯一分解定理的定义。 |
| **C** | 两个正整数的最大公约数总是等于它们的最小公倍数除以它们的乘积。 | **错误**。公式混淆。正确的公式是：$GCD(a,b) \times LCM(a,b) = a \times b$。 |
| **D** | 所有素数都是奇数。 | **错误**。2是素数，但它是偶数。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **概念混淆**：容易将“唯一分解定理”与“哥德巴赫猜想”混淆。
*   **细节疏忽**：忽略了定理中“大于1”和“合数”的前提条件。

**6. 相关的知识点**
*   质因数分解的代码实现（试除法）
*   最大公约数与最小公倍数的关系

### 第7题：素数表的线性筛法（欧拉筛）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：线性筛法（欧拉筛）的核心逻辑——保证每个合数只被其最小的质因数筛掉。

**2. 知识点详解**
*   **算法逻辑**：
    1.  `primes`数组存储已找到的素数。
    2.  外层循环 `i` 从2到n。
    3.  内层循环遍历已找到的素数 `primes[j]`。
    4.  核心代码：`is_prime[i * primes[j]] = 0;` （标记合数）
    5.  **关键优化（去重）**：`if (i % primes[j] == 0) break;`
        *   这意味着 `primes[j]` 是 `i` 的一个质因数。
        *   如果不跳出，后续更大的质数与 `i` 相乘产生的合数，将不会被其**最小**的质因数筛掉，导致重复筛选，破坏线性复杂度。
*   **边界控制**：内层循环的条件必须包含 `i * primes[j] <= n`，防止数组越界。

**3. 选项对错分析**

| 选项 | 循环条件 | 错误原因 |
| :--- | :--- | :--- |
| **A** | `j < primes.size() && i * primes[j] <= n` | **正确**。既保证了数组不越界，又保证了筛选的数值不超过范围。 |
| **B** | `j = sqrt(n); ...` | **错误**。`j`应该是从0开始遍历素数表，而不是从`sqrt(n)`开始。 |
| **C** | `j = 1; j <= sqrt(n); ...` | **错误**。`j`是素数数组的下标，不能直接与`sqrt(n)`比较。 |
| **D** | `j = 1; ...` | **错误**。下标`j`应该从0开始（`primes[0]`通常是第一个素数2）。 |

**4. 答案**
**A**

**5. 易错点分析**
*   **下标起点**：`primes`数组通常从下标0开始存储，循环j应从0开始。
*   **核心逻辑理解**：如果不理解 `if (i % primes[j] == 0) break;` 的作用，很难确定内层循环的正确写法。

**6. 相关的知识点**
*   埃拉托斯特尼筛法（埃氏筛）
*   唯一分解定理（用于质因数分解）

### 第8题：排序算法的稳定性

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：常见排序算法的稳定性概念。

**2. 知识点详解**
*   **稳定性定义**：如果待排序的序列中存在值相等的元素，经过排序后，相等元素的相对位置不发生改变，则称该排序算法是稳定的。
*   **常见算法稳定性**：
    *   **稳定**：冒泡排序、插入排序、归并排序。
    *   **不稳定**：快速排序、堆排序、选择排序。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | 快速排序是稳定排序 | **错误**。快排在分区过程中，相等元素的相对位置可能发生改变。 |
| **B** | 归并排序通常是稳定的 | **正确**。在合并两个有序子数组时，如果遇到相等元素，通常优先取左边的，保持了稳定性。 |
| **C** | 插入排序是不稳定排序 | **错误**。插入排序是稳定的。 |
| **D** | 冒泡排序不是原地排序 | **错误**。冒泡排序只需要常数个额外空间，是原地排序（In-place）。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **概念混淆**：容易混淆“稳定性”与“时间复杂度”或“原地性”。
*   **归并排序**：虽然归并排序的时间复杂度稳定为 $O(n \log n)$，但其空间复杂度通常为 $O(n)$，但这不影响其稳定性。

**6. 相关的知识点**
*   排序算法的时间复杂度与空间复杂度
*   常见排序算法的手写实现（快排、归并）

### 第9题：归并排序

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：归并排序的时间复杂度、空间复杂度及适用场景。

**2. 知识点详解**
*   **时间复杂度**：无论最好、最坏还是平均情况，归并排序都是 $O(n \log n)$。因为它总是将数组对半分，然后合并。
*   **空间复杂度**：$O(n)$。需要一个与原数组等长的临时数组来辅助合并。
*   **适用性**：由于其时间复杂度非常稳定，且是稳定的排序算法，非常适合处理**大规模数据**或对稳定性有要求的场景。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | 归并排序的平均复杂度是 $O(n \log n)$。 | **正确**。 |
| **B** | 归并排序需要 $O(n)$ 的额外空间。 | **正确**。 |
| **C** | 归并排序在最坏情况的时间复杂度是 $O(n \log n)$。 | **正确**。 |
| **D** | 归并排序适合大规模数据。 | **正确**。 |

*(注：根据标准答案C，推测题目原文中有一个选项是错误的描述。结合选项C的文本“归并排序在最坏情况的时间复杂度是”后面可能跟了一个错误的复杂度，如$O(n^2)$，或者选项D有误。但根据常规真题逻辑，此处应选择那个包含错误描述的选项。根据提供的答案表，第9题选C，推测原文C选项可能表述为“最坏情况是$O(n^2)$”或者是关于空间复杂度的错误描述。但基于标准知识，上述分析均为正确描述，故选择那个**不正确**的陈述。)*

**4. 答案**
**C** (选择那个关于归并排序说法**不正确**的选项)

**5. 易错点分析**
*   **最坏情况**：容易受快排影响，误以为归并排序最坏情况也是 $O(n^2)$。
*   **额外空间**：容易误以为所有 $O(n \log n)$ 的排序算法都是 $O(1)$ 空间（如堆排序），而忽略了归并需要辅助数组。

**6. 相关的知识点**
*   分治法的基本思想

### 第10题：快速排序的最坏时间复杂度

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：快速排序算法的时间复杂度分析。

**2. 知识点详解**
*   **最好/平均情况**：$O(n \log n)$。每次都能均匀分割。
*   **最坏情况**：$O(n^2)$。
    *   **触发条件**：数组已经有序（或所有元素相同），且每次选择的基准（pivot）都是首元素或尾元素。
    *   **原因**：每次分区只能确定一个元素的位置，递归深度达到 $n$ 层，每层比较次数约为 $n, n-1, ...$，总次数为 $n(n-1)/2$。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | $O(n \log n)$ | **错误**。这是平均情况。 |
| **B** | $O(n^2)$ | **正确**。这是最坏情况。 |
| **C** | $O(n)$ | **错误**。 |
| **D** | $O(\log n)$ | **错误**。 |

*(注：根据提供的答案表，第10题选B。)*

**4. 答案**
**B**

**5. 易错点分析**
*   **过于乐观**：很多考生只记住了快排是“最快的排序”，潜意识里认为它总是 $O(n \log n)$。
*   **场景判断**：必须意识到当数据有序时，普通的快排（选首/尾作基准）效率会退化。

**6. 相关的知识点**
*   随机化快排（Randomized Quick Sort）
*   三数取中法优化快排

### 第11题：二分查找下界

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法
*   **具体考点**：二分查找的边界处理，寻找第一个大于等于x的元素位置（Lower Bound）。

**2. 知识点详解**
*   **代码逻辑分析**：
    *   初始化：`l = 0`, `r = arr.size()`。这里`r`取的是开区间（数组长度），意味着搜索范围是 `[l, r)`。
    *   循环条件：`while (l < r)`。这是标准的“开区间”二分写法，当 `l == r` 时，区间为空，循环结束。
    *   更新逻辑：
        *   如果 `arr[mid] >= x`，说明 `mid` 可能是答案，或者答案在左边，所以 `r = mid`（保留mid）。
        *   如果 `arr[mid] < x`，说明 `mid` 肯定不是答案，答案在右边，所以 `l = mid + 1`。
*   **正确性**：这种写法是二分查找中寻找“下界”的经典实现，逻辑严密，不会死循环。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | 上述代码逻辑正确 | **正确**。代码采用了标准的“左闭右开”区间二分法。 |
| **B** | 循环条件应该用 `l <= r` | **错误**。如果改用 `l <= r`（闭区间），那么在更新 `r = mid - 1` 时需要调整，否则可能导致死循环或漏掉答案。原代码的写法是自洽的。 |
| **C** | `mid` 计算错误 | **错误**。`mid = l + (r - l) / 2` 是防止整数溢出的标准写法。 |
| **D** | 边界条件不对 | **错误**。`r` 初始化为 `arr.size()` 是为了处理“未找到”的情况（返回arr.size()），逻辑正确。 |

**4. 答案**
**A**

**5. 易错点分析**
*   **区间概念混淆**：考生容易习惯性地认为二分必须是 `l <= r`。实际上，二分有两种主流写法：**左闭右闭** `[l, r]`（对应 `l <= r`）和**左闭右开** `[l, r)`（对应 `l < r`）。本题考察的是后者，关键在于理解 `r` 的含义。
*   **死循环恐惧**：担心 `l = mid + 1` 会跳过答案，其实当 `arr[mid] < x` 时，`mid` 确定不是解，跳过是安全的。

**6. 相关的知识点**
*   二分查找上界（Upper Bound）
*   在旋转排序数组中查找

### 第12题：二分答案（切木头）

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法
*   **具体考点**：二分答案（Binary Search on Answer）的应用。

**2. 知识点详解**
*   **问题转化**：求满足条件的最小 `x`（每段最大长度）。这是一个典型的最小化最大值问题，适合用二分答案解决。
*   **Check函数逻辑**：`int cuts = (L - 1) / x;`。这是计算将长度为L的木头切成每段不超过x，最少需要切几刀。例如，L=10, x=3，需要切3刀（分成4段）。
*   **二分逻辑**：
    *   如果 `check(L, K, mid)` 为真（即 `cuts <= K`），说明 `mid` 满足条件，但我们要求“最小”的 `x`，所以应该尝试更小的值，即 `r = mid`。
    *   如果不满足，则需要增大 `x`，即 `l = mid + 1`。

**3. 选项对错分析**

| 选项 | 代码逻辑 | 分析 |
| :--- | :--- | :--- |
| **A** | `if(check) r = mid; else l = mid + 1;` | **正确**。这是寻找满足条件的最小值的标准二分模板。 |
| **B** | `if(check) r = mid + 1; ...` | **错误**。将右边界扩大，可能导致错过最优解或死循环。 |
| **C** | `... l = mid - 1;` | **错误**。左边界不应该减小，因为 `mid` 可能是解。 |
| **D** | `... l = mid;` | **错误**。这会导致死循环（当 `l+1==r` 时，`mid` 恒等于 `l`）。 |

**4. 答案**
**A**

**5. 易错点分析**
*   **模板混淆**：容易记混“找最小值”和“找最大值”的更新逻辑。
    *   找最小值：`r = mid`（保留），`l = mid + 1`（排除）。
    *   找最大值：`r = mid - 1`（排除），`l = mid`（保留）。
*   **Check函数理解**：`(L-1)/x` 这个公式需要一定的数学直觉，如果理解为 `L/x` 就会出错（整除特性）。

**6. 相关的知识点**
*   二分答案的常见模型（最大化最小值、最小化最大值）
*   浮点数二分

### 第13题：阶乘计算的复杂度

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：递归与迭代的时间、空间复杂度对比。

**2. 知识点详解**
*   **factorial1 (递归)**：
    *   **时间复杂度**：$O(n)$。需要调用n次函数。
    *   **空间复杂度**：$O(n)$。每次调用都会在栈上开辟一个栈帧，直到递归结束。
*   **factorial2 (迭代)**：
    *   **时间复杂度**：$O(n)$。
    *   **空间复杂度**：$O(1)$。只使用了常数个变量。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| **A** | 两种方式时间复杂度相同，都为 $O(n)$。 | **正确**。两者都需要进行n次乘法操作。 |
| **B** | 两种方式空间复杂度相同... | **错误**。递归是 $O(n)$，迭代是 $O(1)$。 |
| **C** | 两种方式空间复杂度相同... | **错误**。同上。 |
| **D** | factorial1时间 $O(n)$，factorial2时间 $O(1)$ | **错误**。迭代的时间复杂度不可能是 $O(1)$。 |

**4. 答案**
**A**

**5. 易错点分析**
*   **空间复杂度盲区**：很多考生只关注时间复杂度，忽略了递归带来的栈空间开销。
*   **递归误解**：认为递归一定比迭代慢（在时间复杂度层面，两者通常是相同的，递归有常数级的函数调用开销，但量级不变）。

**6. 相关的知识点**
*   尾递归优化（Tail Recursion）
*   递归树的画法

### 第14题：贪心算法（任务调度）

**1. 考察的知识点**
*   **大纲分类**：8. 贪心算法
*   **具体考点**：区间调度/任务安排问题的经典贪心策略。

**2. 知识点详解**
*   **算法背景**：这是经典的“加里多尼亚任务调度”问题（或称“安排作业”问题）。
*   **策略**：
    1.  按照利润从大到小排序。
    2.  遍历每个任务，尝试将其安排在**不冲突**的情况下**最晚**的时间点（即从截止时间 `deadline` 往前找空槽）。
*   **代码逻辑**：内层循环 `for(int t = task.deadline; t >= 1; t--)` 就是从截止时间往前找空闲时间槽 `slot[t]`。
*   **填空内容**：一旦找到空槽 `!slot[t]`，就需要：
    1.  占用该时间槽：`slot[t] = true;`
    2.  累加利润：`totalProfit += task.profit;`

**3. 选项对错分析**

| 选项 | 代码 | 分析 |
| :--- | :--- | :--- |
| **A** | `slot[t]=true; totalProfit+=task.profit;` | **正确**。标记时间槽已占用，并累加利润。 |
| **B** | `slot[t]=false; ...` | **错误**。`false` 表示未占用，逻辑反了。 |
| **C** | `totalProfit = task.profit;` | **错误**。这是赋值，不是累加，会覆盖之前的利润。 |
| **D** | 组合了B和C的错误 | **错误**。 |

**4. 答案**
**A**

**5. 易错点分析**
*   **逻辑反向**：容易把 `slot[t] = true` 误认为是“空闲”，其实 `true` 通常代表“已被占用”。
*   **累加与赋值**：在求和时，习惯性地写成 `=` 而不是 `+=`。

**6. 相关的知识点**
*   贪心选择性质
*   活动选择问题（Activity Selection Problem）

### 第15题：高精度加法

**1. 考察的知识点**
*   **大纲分类**：3. C++高精度运算
*   **具体考点**：数组模拟高精度加法的进位处理。

**2. 知识点详解**
*   **存储方式**：`低位在前`（即个位存放在数组下标0处）。这是高精度运算的标准存储方式，便于处理进位。
*   **进位逻辑**：
    *   `carry` 变量累加了当前位的两个数字和进位。
    *   当前位的数字应该是 `carry % 10`。
    *   新的进位应该是 `carry / 10`。
*   **代码顺序**：
    1.  先将当前位的结果（`carry % 10`）压入结果数组 `c`。
    2.  再更新 `carry` 为 `carry / 10`。

**3. 选项对错分析**

| 选项 | 代码 | 分析 |
| :--- | :--- | :--- |
| **A** | `c.push_back(carry/10); carry %= 10;` | **错误**。存入的是进位值，且顺序反了。 |
| **B** | `c.push_back(carry % 10); carry /= 10;` | **正确**。存入个位数，更新进位。 |
| **C** | `c.push_back(carry % 10);` | **错误**。缺少了对 `carry` 的更新，后续进位会出错。 |
| **D** | `c.push_back(carry); carry /= 10;` | **错误**。存入的是整个carry（可能大于10），导致结果错误。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **取模与整除混淆**：容易记混哪个是取个位，哪个是取进位。
*   **顺序问题**：必须先取余数存入数组，再进行整除更新进位。如果顺序颠倒，`carry` 的值变了，取模结果就错了。
*   **最后的进位**：注意循环结束后，如果 `carry` 不为0，还需要再压入一次（代码第10行已处理）。

**6. 相关的知识点**
*   高精度减法（借位处理）
*   高精度乘法（竖式乘法模拟）

### 第1题：数组与链表的特性

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：数组与链表（线性表）的优缺点对比。

**2. 知识点详解**
*   **链表的优点**：

**3. 答案**
**×** (错误)

**4. 易错点分析**
*   **概念混淆**：考生容易将数组的特性（随机访问）套用在链表上。
*   **记忆模糊**：只记住了“链表是线性表”，却忽略了它与数组在访问方式上的本质区别。

**5. 相关的知识点**
*   顺序表（数组）的插入删除操作（需要移动元素）
*   双链表与循环链表的访问特性

### 第2题：最小公倍数（LCM）计算

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：最大公约数（GCD）与最小公倍数（LCM）的关系及代码实现。

**2. 知识点详解**
*   **数学关系**：两个数的乘积等于它们的最大公约数与最小公倍数的乘积。
    $$a \times b = GCD(a, b) \times LCM(a, b)$$
*   **推导公式**：由此可得 $LCM(a, b) = (a \times b) / GCD(a, b)$。
*   **代码分析**：
    *   函数写的是 `return a / gcd(a, b) * b;`。
    *   这个写法是**正确且巧妙的**。它先做除法再做乘法，目的是为了防止 `a * b` 时发生整数溢出（Overflow）。只要 `a` 和 `b` 是整数，`a / gcd` 一定是整数，所以这样计算既准确又安全。

**3. 答案**
**✔** (正确)

**4. 易错点分析**
*   **直觉误导**：很多初学者会写成 `return (a * b) / gcd(a, b);`，这在数值很大时容易溢出。
*   **拼写错误**：注意题目代码中写的是 `ged`，这应该是OCR识别错误（原文应为 `gcd`）。但在判断逻辑时，我们默认函数名拼写正确。

**5. 相关的知识点**
*   欧几里得算法（辗转相除法）求GCD
*   64位整数（long long）的使用与溢出防范

### 第3题：单链表O(1)删除指定节点

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：单链表删除操作的优化技巧（覆盖法）。

**2. 知识点详解**
*   **常规做法**：删除节点p，需要找到p的前驱节点prev，然后执行 `prev->next = p->next`。这需要从头遍历，时间复杂度 $O(n)$。
*   **O(1)做法**：
    1.  将 `p->next` 节点的数据域和指针域**覆盖**到 `p` 节点上。
    2.  修改指针：`p->data = p->next->data;` 和 `p->next = p->next->next;`。
    3.  删除 `p->next` 节点。
*   **前提条件**：题目明确指出“p非尾结点”，这意味着 `p->next` 存在，该方法可行。

**3. 答案**
**✔** (正确)

**4. 易错点分析**
*   **思维定势**：认为单链表删除必须找前驱，从而判断为错误。
*   **边界忽略**：如果p是尾节点，`p->next` 为空，这种方法会失效。但题目已排除此情况。

**5. 相关的知识点**
*   LeetCode经典题：删除链表中的节点（Delete Node in a Linked List）

### 第4题：线性筛法与埃氏筛法的选择

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：埃拉托斯特尼筛法（埃氏筛）与欧拉筛（线性筛）的效率对比与适用场景。

**2. 知识点详解**
*   **时间复杂度**：
    *   埃氏筛：$O(n \log \log n)$
    *   线性筛：$O(n)$
*   **常数因子**：
    *   线性筛虽然复杂度低，但代码逻辑更复杂（涉及取模判断），其**常数因子较大**。
    *   埃氏筛代码极其简洁，常数因子很小。
*   **实际应用**：
    *   对于GESP或NOIP普及组的数据范围（$n \le 10^6$ 或 $10^7$），埃氏筛通常已经足够快，且不易写错。
    *   只有在数据范围极大（如 $10^8$ 以上）且卡常数时，线性筛的优势才绝对明显。
*   **结论**：题干说“**都应当优先于**...使用”，这种说法过于绝对。在算法竞赛中，我们通常遵循“够用就好”的原则，埃氏筛因为其简洁性，在很多场景下是首选。

**3. 答案**
**×** (错误)

**4. 易错点分析**
*   **盲目追求复杂度**：只看大O符号，认为 $O(n)$ 一定优于 $O(n \log \log n)$，忽略了代码常数和实际数据范围。
*   **理解偏差**：认为“线性筛更快”是绝对真理，而实际上在小数据下，简单的算法往往运行得更快。

**5. 相关的知识点**
*   筛法的空间复杂度分析
*   区间筛法（处理大数范围）

### 第5题：二分查找的适用性

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法
*   **具体考点**：二分查找的前提条件及算法性价比分析。

**2. 知识点详解**
*   **前提条件**：二分查找**仅适用于有序数据**。这是基本常识。
*   **性价比分析**：
    *   如果数据无序，为了查找一次而进行排序，时间复杂度为 $O(n \log n)$（排序）+ $O(\log n)$（查找）。
    *   而直接遍历查找的时间复杂度是 $O(n)$。
    *   显然，$O(n \log n)$ 远大于 $O(n)$。因此，如果**仅进行一次查找**，先排序再二分是“杀鸡用牛刀”，非常不划算。
    *   只有当需要进行**多次**查找时，排序的代价才能被分摊，二分查找的优势才会体现出来。
*   **结论**：题干描述完全正确。

**3. 答案**
**✔** (正确)

**4. 易错点分析**
*   **忽略“仅一次”**：考生可能只看到“无序变有序”，就下意识认为二分总是更快，忽略了题干强调的“仅进行一次查找”这个关键条件。
*   **复杂度估算**：对排序和遍历的时间复杂度数量级没有概念。

**5. 相关的知识点**
*   二分查找的时间复杂度：$O(\log n)$
*   快速排序/归并排序的时间复杂度：$O(n \log n)$

### 第6题：快速排序的“三数取中”优化

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：快速排序的性能优化策略及其对最坏情况的规避。

**2. 知识点详解**
*   **核心逻辑**：快速排序的最坏情况（$O(n^2)$）通常发生在数组已经有序或接近有序，且基准（pivot）选择不当（如总是选首/尾元素）时。
*   **三数取中法**：取数组首、尾、中间三个元素，选择其中**中位数**作为基准。
*   **效果分析**：这种方法**并不能完全消除**最坏情况（例如特定构造的数组仍可能导致不平衡分割），但能**极大地降低**落入最坏情况的概率，使算法在实际应用中表现更稳定。题干中使用了“可降低……概率”这一表述，非常严谨。

**3. 答案**
**✔** (正确)

**4. 易错点分析**
*   **绝对化思维**：考生容易误判为错误，认为“三数取中”能“彻底解决”最坏情况。实际上，任何确定性的pivot选择策略都可能被特定数据卡住，但“降低概率”是绝对正确的描述。
*   **混淆概念**：将“降低概率”误解为“改变时间复杂度下界”。

**5. 相关的知识点**
*   随机化快排（Randomized Quick Sort）
*   《算法导论》中关于快排期望时间复杂度的证明

### 第7题：贪心算法与分治算法的区别

**1. 考察的知识点**
*   **大纲分类**：8. 贪心算法 & 7. 分治算法
*   **具体考点**：两种算法设计策略的核心思想辨析。

**2. 知识点详解**
*   **贪心算法（Greedy）**：
    *   **核心**：在每一步选择中都采取当前状态下最好或最优（即最有利）的选择，从而希望导致结果是全局最好或最优的。
    *   **特点**：**一旦做出选择，就不可回溯**。它不从整体最优上加以考虑，只求局部最优。
*   **分治算法（Divide and Conquer）**：
    *   **核心**：将一个复杂的问题分解成两个或更多的相同或相似的子问题，再把子问题分解成更小的子问题……直到最后子问题可以简单的直接求解，原问题即子问题的解的合并。
    *   **特点**：强调“分解”与“合并”。
*   **结论**：题干对两种算法的描述（贪心选局部最优、不回溯；分治分解子问题、合并解）完全准确。

**3. 答案**
**✔** (正确)

**4. 易错点分析**
*   **混淆“不回溯”**：容易将贪心的“不回溯”与动态规划的“有后效性”混淆。
*   **过度联想**：认为贪心也需要分解问题，从而觉得描述模糊。但题干精准抓住了“局部最优”和“分解子问题”这两个本质区别。

**5. 相关的知识点**
*   动态规划（DP）与贪心的区别（最优子结构 vs. 贪心选择性质）
*   分治法的经典应用：归并排序、快速排序、二分查找

### 第8题：递归实现斐波那契的时间复杂度

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：朴素递归算法的时间复杂度分析（递归树）。

**2. 知识点详解**
*   **代码分析**：
    ```cpp
    int fib(int n) {
        if (n <= 1) return n;
        return fib(n-1) + fib(n-2);
    }
    ```
*   **复杂度推导**：
    *   这是一个典型的指数级递归。
    *   递归树的深度约为 $n$，每一层的节点数大致呈指数增长。
    *   其时间复杂度约为 $O(2^n)$（严格来说是 $O(\phi^n)$，其中 $\phi$ 是黄金分割比）。
*   **结论**：题干（根据答案反推）应指出该递归实现的时间复杂度不是线性的，而是指数级的。如果题干声称其复杂度为 $O(n)$ 或类似低复杂度，则是错误的。

**3. 答案**
**×** (错误)

**4. 易错点分析**
*   **误以为“简单”就“快”**：代码只有几行，容易让人误以为执行效率很高。
*   **重复计算**：没有意识到 `fib(n-2)` 会被计算多次（重叠子问题），这是递归实现斐波那契最致命的弱点。

**5. 相关的知识点**
*   记忆化搜索（Memoization）优化递归
*   迭代法求斐波那契（$O(n)$ 时间，$O(1)$ 空间）

### 第9题：递归的终止条件与栈溢出

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：递归函数的三要素及递归的底层实现机制。

**2. 知识点详解**
*   **递归三要素**：
    1.  **函数功能定义**：函数要干什么。
    2.  **递归终止条件（Base Case）**：什么时候停止递归。
    3.  **递归公式（Recursive Relation）**：函数如何调用自身。
*   **栈溢出（Stack Overflow）**：
    *   如果没有终止条件，或者终止条件永远无法满足，递归将无限进行下去。
    *   每次函数调用都会在内存的栈区压入一个栈帧（保存参数、局部变量等）。
    *   无限递归最终会耗尽栈空间，导致程序崩溃（栈溢出）。
*   **结论**：题干描述完全正确。

**3. 答案**
**✔** (正确)

**4. 易错点分析**
*   **忽略“无限递归”的后果**：只知道递归会慢，不知道会导致程序崩溃。
*   **边界条件**：有时候写了终止条件，但逻辑错误导致无法触发，本质上还是栈溢出。

**5. 相关的知识点**
*   内存布局（栈、堆、全局区）
*   尾递归优化（Tail Call Optimization）

### 第10题：贪心算法的局限性

**1. 考察的知识点**
*   **大纲分类**：8. 贪心算法
*   **具体考点**：贪心算法的正确性证明与局限性。

**2. 知识点详解**
*   **贪心本质**：贪心算法是一种**启发式策略**。它在每一步选择中都采取当前状态下最好或最优的选择。
*   **核心缺陷**：由于贪心只看眼前（局部最优），且**不可回溯**，它很容易陷入**局部最优解**，而这个局部最优解往往**不是全局最优解**。
*   **经典反例**：0-1背包问题。如果按单位价值贪心选择，不一定能得到最优解；而动态规划可以。
*   **结论**：题干说“最终**一定**能找到全局最优解”，这是**错误**的。贪心算法并不保证全局最优，除非该问题具有“贪心选择性质”。

**3. 答案**
**×** (错误)

**4. 易错点分析**
*   **被“最优”二字误导**：听到“最优”就觉得结果肯定是对的。
*   **缺乏反例意识**：没有意识到贪心算法是有使用前提的（如无后效性、贪心选择性质）。

**5. 相关的知识点**
*   贪心算法的正确性证明（交换论证法）
*   贪心算法适用的经典问题：活动选择问题、霍夫曼编码、最小生成树（Prim/Kruskal）
