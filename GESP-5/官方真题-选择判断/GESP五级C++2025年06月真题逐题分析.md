### 第 1 题：链表与数组的效率对比

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：链表与数组在不同操作上的时间复杂度比较。

**2. 知识点详解**
数组和链表是两种基础的数据结构，它们的性能差异主要体现在内存存储方式上：
*   **数组**：内存连续。优点是支持**随机访问**（O(1)），缺点是在中间插入或删除需要移动大量元素（O(n)）。
*   **链表**：内存非连续，通过指针连接。优点是**插入和删除**只需修改指针（O(1)，前提是已找到位置），缺点是必须**遍历**查找（O(n)）。

**3. 选项对错分析**
*   **A. 随机访问元素**：错误。数组通过下标直接访问，效率为O(1)；链表必须从头或尾遍历，效率为O(n)。
*   **B. 查找指定元素**：错误。两者都需要遍历，时间复杂度均为O(n)。
*   **C. 在已知位置插入或删除节点**：**正确**。数组需要移动后续所有元素；链表只需修改前后节点的指针，效率更高。
*   **D. 遍历所有元素**：两者效率基本一致，均为O(n)，链表并无明显优势。

**4. 答案**
**C**

**5. 易错点分析**
考生容易误选A，混淆了“访问”和“修改”的场景。要牢记：**查得快（数组），改得慢；查得慢（链表），改得快**。

**6. 相关的知识点**
*   单链表、双链表的插入删除操作细节。
*   时间复杂度的计算方法（O(1) vs O(n)）。

### 第 2 题：双向链表空判断

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：双向链表空状态的逻辑判断及C++语法基础。

**2. 知识点详解**
判断链表是否为空，本质是判断头指针（`head`）或尾指针（`tail`）是否为 `nullptr`（空指针）。
*   如果 `head == nullptr`，说明没有头节点，链表为空。
*   同理，如果 `tail == nullptr`，说明没有尾节点，链表为空。
*   `size` 是计数器，如果 `size == 0`，自然也代表链表为空。

**3. 选项对错分析**
*   **A. `return head == nullptr;`**：正确写法，逻辑通顺。
*   **B. `return tail == nullptr;`**：正确写法，逻辑通顺。
*   **C. `return head.data == 0;`**：**错误**。
    1.  语法错误：`head` 是指针（`Node*`），指针类型没有 `data` 成员，应该写成 `head->data`。
    2.  逻辑错误：即使修正为 `head->data`，这也是错误的。因为链表可能未初始化（`head` 为空指针，解引用会崩溃），或者第一个节点的数据就是0，但这不代表链表为空。
*   **D. `return size == 0;`**：正确写法，逻辑通顺。

**4. 答案**
**C**

**5. 易错点分析**
本题陷阱在于C选项。部分同学只关注逻辑（数据为0代表空），而忽略了**指针访问成员的语法**（`.` 和 `->` 的区别）以及**空指针解引用**的危险性。

**6. 相关的知识点**
*   C++结构体指针访问成员运算符 `->`。
*   空指针解引用导致程序崩溃（Segmentation Fault）。

### 第 3 题：双向链表尾部插入

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：双向链表（DoubleLink）在尾部追加节点（`append`）的指针操作顺序。

**2. 知识点详解**
在双向链表尾部插入新节点 `newNode` 时，需要修改三个指针：
1.  **新节点的前驱**：`newNode->prev` 应该指向原来的尾节点（`tail`）。
2.  **原尾节点的后继**：`tail->next` 应该指向新节点（`newNode`）。
3.  **链表尾指针更新**：`tail` 指针应移动到新节点上。

**3. 选项对错分析**
*   **A**：只修改了 `tail->next`，没有修改新节点的 `prev`，也没有更新 `tail` 指针。**错误**。
*   **B**：先更新了 `tail` 指针，导致无法找到原来的尾节点来修改其 `next` 指针。**错误**。
*   **C**：代码逻辑混乱，先更新 `tail`，然后试图用 `tail`（此时已是新节点）去修改 `prev`，逻辑不通。**错误**。
*   **D**：
    1.  `tail->next = newNode;` // 原来的尾巴指向新节点
    2.  `newNode->prev = tail;` // 新节点指回原来的尾巴
    3.  `tail = newNode;` // 更新尾巴位置
    **顺序完美，无逻辑断层。正确**。

**4. 答案**
**D**

**5. 易错夹分析**
指针操作的**顺序**至关重要。如果先执行 `tail = newNode`，就会丢失对原链表最后一个节点的引用，导致无法建立双向连接。

**6. 相关的知识点**
*   链表插入操作的“四步法”：申请空间 -> 填充数据 -> 修改后向指针 -> 修改前向指针（对于双向链表）。

### 第 4 题：约瑟夫问题（循环链表）

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：循环链表的节点删除操作。

**2. 知识点详解**
约瑟夫问题模拟了报数出圈的过程。当数到第 `k` 个人（节点 `p`）时，需要将其删除。
删除操作的核心步骤是：
1.  **连接断口**：让 `p` 的前驱节点（`prev`）直接指向 `p` 的后继节点（`p->next`）。即 `prev->next = p->next`。
2.  **释放内存**：`delete p`。
3.  **移动指针**：将当前指针 `p` 移动到下一个报数的人（即 `prev->next` 或 `p->next`）。

**3. 选项对错分析**
*   **A**：
    1.  `prev->next = p->next;` // 正确，跳过p
    2.  `delete p;` // 正确，释放p
    3.  `p = prev->next;` // 正确，p移动到下一个
    **逻辑正确**。
*   **B**：先 `delete p`，然后试图使用已释放的内存 `p->next` 进行赋值。**错误（野指针）**。
*   **C**：同B，先释放内存再使用。**错误**。
*   **D**：`p = prev->next;` 这一步在 `delete p` 之前没有实际意义，且最后 `delete p` 删除的是刚刚赋值的新节点，逻辑混乱。**错误**。

**4. 答案**
**A**

**5. 易错点分析**
核心陷阱在于**内存释放与指针使用的顺序**。必须先保存 `p->next` 的地址（或者先修改 `prev` 的指针），然后再释放 `p`。一旦执行了 `delete p`，就不能再访问 `p->next`。

**6. 相关的知识点**
*   循环链表的构建与遍历。
*   C++内存管理（`new`/`delete`）。

### 第 5 题：质数判断优化

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：质数的数学性质（6k±1形式）及试除法优化。

**2. 知识点详解**
代码中的 `step = 6 - step` 是一种常见的质数判断优化技巧。
*   除了 2 和 3 以外，所有的质数都可以表示为 $6k \pm 1$ 的形式。
*   代码逻辑：从 7 开始（7 = 6*1 + 1），第一次 `step` 是 4，下一次 `step` 变成 2（因为 6-4=2）。
*   这样 `i` 的增长序列是：7 (6k+1), 9 (6k+3), 11 (6k+5/6k-1), 13 (6k+1)... 实际上是在模拟 $6k \pm 1$ 的增长，跳过了能被 2 或 3 整除的数。

**3. 选项对错分析**
*   **A**：错误。代码第5行有 `n == 5` 返回 `true`，且第7行 `n % 5 == 0` 才返回 false（针对非5的倍数）。5能被正确判断。
*   **B**：错误。`sqrt(n)` 是试除法的标准优化（只需要试除到根号n），写成 `n/2` 虽然能算对但效率极低，不是必须的。
*   **C**：**正确**。这正是 `step` 交替变化（4, 2, 4, 2...）的数学原理，旨在只检查可能为质数的 $6k \pm 1$ 形式的数。
*   **D**：错误。修改后的循环从2开始且步长为1，会检查所有偶数（如4, 6, 8...），虽然结果对，但执行时间（效率）远低于原代码。

**4. 答案**
**C**

**5. 易错点分析**
不了解 $6k \pm 1$ 这一数论性质。很多同学只知道试除法要除到 $\sqrt{n}$，但不知道为什么步长要这样设计。

**6. 相关的知识点**
*   **初等数论**：素数与合数的定义。
*   **算法优化**：埃拉托斯特尼筛法（埃氏筛）。

### 第 6 题：最大公约数算法对比

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论 -> 欧几里得算法
*   **具体考点**：欧几里得算法（`gcd0`）与暴力枚举法（`gcd1`）的时间复杂度对比及代码细节。

**2. 知识点详解**
*   **`gcd0` (欧几里得算法)**：利用递归 `gcd(a, b) = gcd(b, a % b)`。其时间复杂度为 $O(\log n)$，效率极高。
*   **`gcd1` (暴力枚举)**：从 `small` 开始向下遍历到 1，寻找第一个能同时整除两数的因子。最坏情况下时间复杂度为 $O(n)$。

**3. 选项对错分析**
*   **A**：`gcd0()` 的时间复杂度通常描述为 $O(\log n)$（以较小数为基准）。虽然选项未写完，但通常默认其描述正确。
*   **B**：`gcd1()` 的时间复杂度是 $O(n)$。虽然选项未写完，但通常默认其描述正确。
*   **C**：一般说来，欧几里得算法（对数级）的效率远高于暴力枚举（线性级）。**正确**。
*   **D**：`i > 1` 和 `i >= 1` 在这里**没有区别**。因为循环内部有 `if (big % i == 0 && small % i == 0)`，当 `i` 递减到 1 时，1 肯定能整除任何整数，所以循环一定会在 `i=1` 时返回。修改条件不会改变逻辑，也不会提高效率。**该说法错误**。

**4. 答案**
**D**

**5. 易错点分析**
考生可能会误选C，误以为递归一定比循环慢。实际上，欧几里得算法的递归深度很浅（斐波那契数列级别），远快于暴力循环。本题选**错误**的说法，D选项的修改是多余的（no-op）。

**6. 相关的知识点**
*   欧几里得算法的原理与实现。
*   暴力枚举法的优化思路。

### 第 7 题：质数判断与筛法效率

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论 -> 素数与合数、素数表的埃氏筛法和线性筛法
*   **具体考点**：单个质数判断（试除法）与批量质数筛选（埃氏筛、线性筛）的效率对比。

**2. 知识点详解**
题目中的代码是标准的试除法判断单个质数。
*   **埃氏筛 (Sieve of Eratosthenes)**：如果需要判断 $1$ 到 $n$ 范围内所有数的质数性，埃氏筛的时间复杂度为 $O(n \log \log n)$，远优于对每个数单独试除（$O(n \sqrt{n})$）。
*   **线性筛 (欧拉筛)**：时间复杂度为 $O(n)$，是处理大规模连续质数判断最高效的方法。

**3. 选项对错分析**
*   **A**：正确。埃氏筛在处理连续区间时效率更高。
*   **B**：正确。线性筛效率最高。
*   **C**：正确。如果要筛选一连串数，试除法会重复计算很多合数的因子，效率低。
*   **D**：**错误**。线性筛的时间复杂度 $O(n)$ 优于埃氏筛的 $O(n \log \log n)$。虽然常数因子上线性筛可能稍大，但理论上埃氏筛并不比线性筛效率高。

**4. 答案**
**D**

**5. 易错点分析**
本题选**错误**的说法。部分同学可能混淆了埃氏筛和线性筛的复杂度，误以为埃氏筛就是最优的。记住：**线性筛是处理大规模连续质数问题的最优解**。

**6. 相关的知识点**
*   埃拉托斯特尼筛法的实现原理（标记倍数）。
*   欧拉筛（线性筛）的实现原理（每个合数只被其最小质因子筛掉）。

### 第 8 题：唯一分解定理

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论 -> 唯一分解定理
*   **具体考点**：算术基本定理（唯一分解定理）的定义。

**2. 知识点详解**
**唯一分解定理**指出：任何一个大于1的自然数，如果它是合数，那么它都可以唯一地分解成一系列质数的乘积，且这些质数的排列顺序是唯一的（不考虑顺序的话）。
公式表达：$n = p_1^{a_1} \times p_上下{a_2} \times ... \times p_k^{a_k}$。

**3. 选项对错分析**
*   **A**：这是“哥德巴赫猜想”，不是唯一分解定理。
*   **B**：**正确**。准确描述了定理的核心：大于1的合数可唯一分解为质数乘积。
*   **C**：这是最大公约数与最小公倍数的关系公式（$gcd(a,b) \times lcm(a,b) = a \times b$）。
*   **D**：这是质数的性质（除了2以外），与定理无关。

**4. 答案**
**B**

**5. 易错点分析**
基础概念记忆混淆。需要严格区分“哥德巴赫猜想”、“唯一分解定理”和“公约公倍关系”。

**6. 相关的知识点**
*   质因数分解的实现。
*   利用质因数分解求最大公约数和最小公倍数。

### 第 9 题：分治算法识别

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：分治法的基本思想与递归实现。

**2. 知识点详解**
代码实现的是“分治法求最大值”：
1.  **分解 (Divide)**：将数组从中间分成两半。
2.  **解决 (Conquer)**：递归求解左右两半的最大值。
3.  **合并 (Combine)**：返回左右最大值中较大的那个。
这符合分治法的典型特征。

**3. 选项对错分析**
*   **A**：正确。采用了分治策略。
*   **B**：正确。使用了递归。
*   **C**：**错误**。贪心算法是每一步选择当前最优（局部最优），期望达到全局最优。而分治法是将问题分解为独立的子问题。求最大值虽然每一步都在选“大”的，但本质是通过分解子问题来解决，归类为分治更准确。且该算法没有贪心算法的“贪心选择性质”证明过程。
*   **D**：正确。这不是递推（迭代），而是递归。

**4. 答案**
**C**

**5. 易错点分析**
容易混淆“分治”和“贪心”。求最大值这个特定问题，虽然结果看起来像是贪心（选最大的），但该代码的实现逻辑是**将大问题拆解为小问题**（分治），而不是在每一步做贪心选择。在算法分类上，它属于分治。

**6. 相关的知识点**
*   分治算法的基本步骤（分解、解决、合并）。
*   递归与迭代（递推）的区别。

### 第 11 题：二分查找（寻找最后出现的位置）

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法 -> 二分查找算法
*   **具体考点**：二分查找的“右边界”查找变体（寻找目标值最后一次出现的位置）。

**2. 知识点详解**
标准的二分查找通常找任意一个匹配点，但本题要求找**最后一个** `target`。
*   **核心逻辑**：当 `lst[mid] <= target` 时，说明解在右半部分（包含 `mid`），所以 `low = mid`。
*   **细节**：`mid = (low + high + 1) / 2` 中的 `+1` 是为了避免在 `low` 和 `high` 相邻时陷入死循环（因为 `low = mid` 可能导致边界不收缩）。

**3. 选项对错分析**
*   **A**：**正确**。该算法是寻找右边界的标准写法。即使数组全由相同元素组成，循环也会正确收敛到最后一个位置。
*   **B**：错误。如果 `target` 小于所有元素，循环结束后 `lst[low] != target`，会返回 -1，而不是 0。
*   **C**：错误。改为 `<=` 且不调整 `mid` 的计算方式，会导致死循环或逻辑错误。标准的“找右边界”通常配合 `while (low < high)` 使用。
*   **D**：错误。去掉 `+1` 会导致在特定情况下（如 `[1, 3]` 查找 `3`）陷入死循环，因为 `low` 会一直等于 `mid`。

**4. 答案**
**A**

**5. 易错点分析**
二分查找的边界处理是算法中最难的细节之一。
*   **找左边界**：通常 `high = mid - 1`，`mid = (low + high) / 2`。
*   **找右边界**：通常 `low = mid`（或者 `low = mid + 1` 取决于写法），为了防止死循环，往往需要 `mid = (low + high + 1) / 2`。
本题选**正确**的说法，A是唯一正确的描述。

**6. 相关的知识点**
*   二分查找的三种情况：查找存在性、查找左边界、查找右边界。

### 第 15 题：高精度除法（试商）

**1. 考察的知识点**
*   **大纲分类**：3. C++高精度运算 -> C++数组模拟高精度除法
*   **具体考点**：高精度除法中“试商”逻辑的初始化。

**2. 知识点详解**

1.  **对齐**：先取被除数的前几位（与除数位数相同）作为初始的“余数”。
2.  **试商**：看余数里包含几个除数，这就是当前位的商。
3.  **下一位**：将余数减去商乘以除数，然后把被除数的下一位“落下来”加入余数。

**3. 选项对错分析**
题目问的是在“逐位计算商”的循环中，如何将被除数的下一位加入余数。
*   **背景**：代码第48-51行已经初始化了余数 `r` 为被除数 `a` 的前 `b.len` 位。
*   **循环逻辑**：在处理下一位时（`i` 从 `b.len` 到 `a.len-1`），需要将 `a.d[i]` 加入余数。
*   **数据结构细节**：根据 `BigInt` 结构体定义，`d[0]` 是个位，`d[1]` 是十位……这意味着数组是**逆序**存储的（个位在前）。
*   **操作**：加入下一位，实际上是将新数字放在余数的**最高位**（即数组的末尾）。
*   **选项分析**：
    *   `r.d[0]` 是个位。如果直接覆盖 `r.d[0] = a.d[i]`，会丢失低位信息。
    *   正确的做法是将新位放在高位。但在手算除法中，我们是将下一位“落”到余数的末尾。
    *   观察选项，B选项 `r.d[i] = a.d[i]` 且 `r.len++` 符合逻辑：将被除数第 `i` 位的值赋给余数的对应位置，并增加长度。

*(注：代码上下文存在省略，但根据标准高精度除法模板，试商循环中需要扩展余数的位数)*

**4. 答案**
**B**

**5. 易错点分析**
本题极易出错的地方在于**数组存储顺序**。很多同学习惯从 `d[0]` 存最高位，但本题明确注释 `d[0]` 是个位。这意味着在进行除法“落位”操作时，新加入的位在数组中的下标实际上是递增的（虽然数值上它是更高位）。需要仔细推演 `i` 的循环变量含义。

### 第 4 题：归并排序递归次数

**4. 易错点分析**

*   **贪心策略**：题目描述的“逐步选择当前距离起点最近的节点”正是**贪心算法**的典型特征——每一步都做出在当前看来最好的选择（局部最优解），希望通过一系列局部最优解达到全局最优解。

**3. 判定分析**
*   **题目说法**：“Dijkstra算法是贪心算法”。
*   **结论**：**正确（✔）**。虽然Dijkstra算法通常配合优先队列（堆）实现，但其核心选择逻辑是基于贪心策略的。

**4. 易错点分析**
容易混淆**贪心**与**动态规划**。Dijkstra算法之所以是贪心，是因为它一旦确定了某个节点的最短路径（将其加入已处理集合），就**不再改变**该节点的距离（前提是权重非负）。这与动态规划的“状态转移”和“回溯”有本质区别。

**5. 相关知识点**
*   贪心算法的“最优子结构”和“贪心选择性质”。
*   Dijkstra算法的适用条件（非负权图）。

### 第 8 题：分治算法的效率

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：分治算法的优缺点及适用场景。

**2. 题目详解**
题目说法：“分治算法……但由于分治算法需要将问题进行分解，并且需要将多个子问题的解合并为原问题的解，所以分治算法的效率通常比直接求解原问题的效率低。”
*   **逻辑辨析**：这句话具有很强的迷惑性。分治算法确实有分解和合并的开销（常数因子较大），但其核心价值在于**降低了问题的复杂度阶**。
    *   **反例1**：归并排序（分治，$O(n \log n)$）比冒泡排序（直接求解/暴力，$O(n^2)$）快。
    *   **反例2**：快速幂（分治）比朴素幂运算（循环乘）快。
*   **结论**：分治算法虽然有额外开销，但通常能将指数级或平方级的问题降维到对数级或线性对数级。因此，“通常比直接求解效率低”的说法是**错误**的。

**3. 判定分析**
*   **题目说法**：分治算法效率通常较低。
*   **结论**：**错误（×）**。分治算法的主要目的是**提高效率**，解决那些暴力法无法在合理时间内解决的问题。

**4. 易错点分析**
考生容易被“分解和合并需要时间”这一事实迷惑，从而认为分治总是慢的。实际上，算法效率主要看**时间复杂度的阶**（$O(n^2)$ vs $O(n \log n)$），常数因子的开销通常在次一级考虑。

**5. 相关知识点**
*   分治法降低时间复杂度的经典案例（归并排序、快速排序、二分查找、大整数乘法）。

### 第 9 题：递归函数与无限递归

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法 -> 递归算法的相关概念
*   **具体考点**：递归终止条件的逻辑判断及代码陷阱。

**2. 题目详解**
代码分析：
```cpp
int puzzle(int n) {
    if (n - - 1) return 1; // 注意这里！
    if (n % 2 == 0) return puzzle(n / 2);
    return puzzle(3 * n + 1); // 假设题目是 3*n+1，原文OCR有误
}
```
*   **关键陷阱**：`if (n - - 1)`。这是 `n-- - 1` 还是 `n - (-1)`？根据C++运算符优先级，`--` 高于 `-`，且这是后置自减。
    *   如果 `n` 为 1：条件判断为 `1 - (-1)`？不，实际上是 `n--` 的值是 1（真），然后减去 1？**这里代码存在严重的歧义或笔误。**
    *   **更合理的解释**：这极有可能是 `if (n <= 1)` 或 `if (n == 1)` 的笔误，但写成了 `n-- - 1`。如果按字面意思 `n-- - 1`，当 `n=2` 时，表达式值为 `2-1=1`（真），函数返回，但 `n` 变成了 1。逻辑混乱。
*   **核心逻辑**：这是一个类似“角谷猜想”的递归。如果终止条件写错（比如写成 `n--` 而不是 `n==1`），会导致 `n` 永远无法正确收敛到 1，或者在负数区间震荡。
    *   例如，如果 `n=2`，走 `n/2` 变成 1。如果终止条件是 `if (n - - 1)`（假设意为 `n-- - 1`），当 `n=1` 时，表达式为 `1 - 1 = 0`（假），不返回。然后走奇数分支 `3*1+1=4`，接着 `4->2->1`，死循环。

**3. 判定分析**
*   **题目说法**：“调用 puzzle(7)程序会无限递归”。
*   **结论**：**正确（✔）**。由于终止条件 `if (n - - 1)` 存在严重的语法/逻辑错误（很可能是想写 `n==1` 但写错了），导致递归无法在 `n=1` 时正确终止，从而陷入死循环。

**4. 易错点分析**
这是C++语法陷阱题。`n-- - 1` 等价于 `(n--) - 1`。如果 `n=1`，判断条件为 `1 - 1 = 0`（false），函数不返回，继续执行后面的递归。对于奇数 `n`，会执行 `3*n+1`，导致数值变大，且永远无法满足终止条件（因为终止条件本身是错的）。因此确实会无限递归。

**5. 相关知识点**
*   递归的三要素（边界条件、递归公式、函数功能）。
*   C++运算符优先级（后置自减 `--` 的优先级高于减法 `-`）。

### 第 10 题：线性筛法（欧拉筛）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论 -> 素数表的埃氏筛法和线性筛法
*   **具体考点**：线性筛法（欧拉筛）的核心原理与时间复杂度。

**2. 题目详解**
*   **核心原理**：线性筛法的关键在于 `if (i % primes[j] == 0) break;`。
    *   这行代码保证了每个合数只被它的**最小质因数**筛掉。
    *   例如，当 `i` 是 `primes[j]` 的倍数时，就停止。这是因为如果继续用更大的质数去筛，那个合数的最小质因数就不是当前的 `primes[j]` 了。
*   **时间复杂度**：因为每个数都只被访问一次（每个合数只被筛一次），所以时间复杂度是 $O(n)$，被称为线性筛。

**3. 判定分析**
*   **题目说法**：“每个合数只被它的最小质因数筛掉一次，时间复杂度为O(n)”。
*   **结论**：**正确（✔）**。这是对线性筛法最标准的定义和描述。

**4. 易错点分析**
容易混淆**埃氏筛**（$O(n \log \log n)$，一个合数可能被多个质因数筛多次）和**线性筛**（$O(n)$，每个合数只被筛一次）。记住“最小质因数”和“break”是线性筛的标志。

**5. 相关知识点**
*   埃拉托斯特尼筛法（埃氏筛）的优化过程。
*   欧拉筛（线性筛）的代码实现细节。
