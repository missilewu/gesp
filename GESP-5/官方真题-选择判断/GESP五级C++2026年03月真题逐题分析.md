### **第1题：链表结构特性**

1.  **考察的知识点**
    **链表** -> 单链表、双链表、循环链表的基本概念与操作复杂度。

2.  **知识点详解**
    *   **单链表**：每个节点只包含指向下一个节点的指针。在已知节点指针的情况下，删除该节点通常需要找到其前驱节点，时间复杂度为$O(n)$，除非使用“哑结点”或“复制后继值”的技巧。
    *   **循环链表**：尾节点的指针指向头节点（或首节点），形成一个环。因此，循环链表中理论上不存在指向`nullptr`的指针（除非链表为空且有头结点的特殊情况需具体分析）。
    *   **双链表**：每个节点包含指向前驱和后继的指针。

3.  **选项对错分析**
    *   **A. 错误**。在单链表中，若只知道
    * 当前节点`p`的指针，无法直接修改`p`的前驱节点的`next`指针。通常需要从头遍历找到前驱，时间复杂度是$O(n)$。有一种技巧是将`p->next`的值复制到`p`，然后删除`p->next`，但这要求`p`不是尾节点。
    *   **B. 错误**。循环链表中，如果是**带头结点**的空循环链表，头结点的`next`指针指向自身，不是空指针；但如果是指针变量本身未初始化，可能会有空指针，但通常描述链表结构特性时不以此为依据。更严谨的反例是：如果循环链表没有头结点且为空，则指针为`nullptr`。但标准定义下，循环链表的节点指针域不为空。
    *   **C. 错误**。在循环双链表中，尾结点的`next`指针指向**头结点**（或首节点），而不是`nullptr`。
    *   **D. 正确**。在带头结点的循环单链表中，如果链表为空，头结点的`next`指针会指向自身。如果链表非空，`next`指向第一个有效数据节点。

4.  **答案**
    **D**

5.  **易错点分析**
    *   混淆了“带头结点”和“不带头结点”的链表在判空时的区别。
    *   误以为循环链表绝对不能有空指针（实际上指针变量可以为空，但节点内部的指针域在非空链表中不为空）。

6.  **相关的知识点**
    *   链表的创建、插入、删除操作。
    *   哑结点（哨兵节点）的使用。

### **第2题：双向循环链表插入操作**

1.  **考察的知识点**
    **链表** -> 双链表的插入操作。

2.  **知识点详解**
    在双向循环链表中，在节点`p`之前插入节点`s`，需要修改四个指针：
    1.  找到`p`的前驱节点（设为`q`，但在代码中通常通过`p->prev`获取）。
    2.  `s->next`指向`p`。
    3.  `s->prev`指向`q`（即`p->prev`）。
    4.  `q->next`（即`p->prev->next`）指向`s`。
    5.  `p->prev`指向`s`。

3.  **选项对错分析**
    *   **A**：使用了未定义的变量`q`，且逻辑混乱。
    *   **B**：这是在`p`**之后**插入`s`的标准代码，不符合题目“之前插入”的要求。
    *   **C**：逻辑正确。
        1.  `s->next = p;` // s的后继是p
        2.  `s->prev = p->prev;` // s的前驱是p原来的前驱
        3.  `p->prev->next = s;` // p原来的前驱的后继变成s
        4.  `p->prev = s;` // p的前驱变成s
    *   **D**：将`s`的前驱设为`nullptr`，破坏了循环链表的结构。

4.  **答案**
    **C**

5.  **易错点分析**
    *   混淆了“在p前插入”和“在p后插入”的代码逻辑。
    *   忘记修改前驱指针（`prev`），导致链表变成单向链表或断裂。
    *   指针修改顺序错误导致链表断裂（例如先修改了`p->prev`，就找不到原来的前驱了）。

6.  **相关的知识点**
    *   链表指针操作的顺序（防止断链）。
    *   循环链表的结构特性。

### **第3题：单链表删除节点（哑结点技巧）**

1.  **考察的知识点**
    **链表** -> 单链表的删除操作、哑结点（哨兵节点）的应用。

2.  **知识点详解**
    使用哑结点（`dummy`）可以统一处理头结点和中间节点的删除，避免对头结点进行特殊判断。
    *   `cur`是当前检查节点的前驱（因为判断条件是`cur->next`）。
    *   当`cur->next->val == x`时，需要删除`cur->next`。
    *   操作步骤：将`cur->next`指向被删除节点的下一个节点（`del->next`），然后释放`del`。

3.  **选项对错分析**
    *   **A**：`cur = cur->next;` 这是不删除节点时的移动操作，不符合逻辑。
    *   **B**：`cur->next = del->next;` 这是正确的删除逻辑，将前驱节点`cur`的`next`指向被删除节点的后继。
    *   **C**：`del->next = cur->next;` 这是无意义的自我赋值，没有改变链表结构。
    *   **D**：`cur->next = nullptr;` 这会直接切断链表，丢失后续所有节点。

4.  **答案**
    **B**

5.  **易错点分析**
    *   误选A，忘记了删除节点后需要连接断开的链表。
    *   指针操作顺序错误：如果先`delete del`，再`cur->next = del->next`，会导致访问已释放内存的错误（野指针）。

6.  **相关的知识点**
    *   链表的删除操作。
    *   哑结点的作用（简化边界处理）。

### **第4题：欧几里得算法（GCD）执行过程**

1.  **考察的知识点**
    **初等数论** -> 欧几里得算法（辗转相除法）。

2.  **知识点详解**
    欧几里得算法基于原理：$gcd(a, b) = gcd(b, a \mod b)$。
    计算 $gcd(48, 18)$ 的过程：
    *   $gcd(48, 18)$ -> $48 \div 18 = 2$ 余 $12$，转为 $gcd(18, 12)$
    *   $gcd(18, 12)$ -> $18 \div 12 = 1$ 余 $6$，转为 $gcd(12, 6)$
    *   $gcd(12, 6)$ -> $12 \div 6 = 2$ 余 $0$，转为 $gcd(6, 0)$
    *   当 $b=0$ 时，返回 $a$，即 $6$。

3.  **选项对错分析**
    *   **A**：完全符合上述计算过程。
    *   **B**：出现了`gcd(30, 18)`，不符合`a % b`的逻辑。
    *   **C**：出现了`gcd(18, 30)`，参数顺序错误。
    *   **D**：第一步就变成了`gcd(12, 18)`，顺序和数值均错误。

4.  **答案**
    **A**

5.  **易错点分析**
    *   混淆了参数顺序，误以为是`gcd(b, a)`。
    *   计算余数错误（例如算成减法）。

6.  **相关的知识点**
    *   最大公约数（GCD）的定义。
    *   辗转相除法的递归实现。

### **第5题：欧拉线性筛法**

1.  **考察的知识点**
    **初等数论** -> 素数表的线性筛法（欧拉筛）。

2.  **知识点详解**
    线性筛的核心思想是**每个合数只被其最小的质因数筛掉**。
    *   外层循环`i`遍历从2到n的数。
    *   内层循环`j`遍历已经找到的质数列表`primes`。
    *   **关键判断条件**：`j < primes.size()`。因为我们需要用`primes[j]`去筛掉`i * primes[j]`。
    *   **终止条件**：如果`i % primes[j] == 0`，说明`primes[j]`是`i`的质因数，此时应跳出，以保证每个数只被其最小质因数筛掉。

3.  **选项对错分析**
    *   **A**：`j <= n`，数组越界且逻辑错误。
    *   **B**：`j < sqrt(n)`，这是埃氏筛的优化条件，不适用于线性筛的内层循环。
    *   **C**：`j < primes.size()`。这是正确的。因为`primes`存储了当前已找到的所有质数，我们需要用这些质数去筛。
    *   **D**：`j < i`，这没有意义，`j`是质数列表的下标，与`i`的大小无直接比较关系。

4.  **答案**
    **C**

5.  **易错点分析**
    *   将线性筛的内层循环条件与埃氏筛（`j*j <= n`）混淆。
    *   不理解`primes`数组的作用，误以为`j`应该与`i`或`n`比较。

6.  **相关的知识点**
    *   埃氏筛法（时间复杂度$O(n \log \log n)$）。
    *   线性筛法的原理（时间复杂度$O(n)$）。
    *   最小质因数的概念。

### **第6题：埃氏筛法的内层循环起始点**

1.  **考察的知识点**
    **初等数论** -> 素数表的埃拉托斯特尼筛法（埃氏筛）。

2.  **知识点详解**
    埃氏筛法的基本原理是：将已知的质数的所有倍数标记为合数。
    *   当外层循环遍历到数 $i$ 时，如果 $i$ 未被标记，则 $i$ 是质数。
    *   内层循环用于标记 $i$ 的倍数。如果从 `j = 2*i` 开始，会重复标记很多已经被更小质数筛过的数（例如 $6$ 已被 $2$ 筛过，到 $3$ 时又会筛一次）。
    *   **优化原理**：小于 $i \times i$ 的 $i$ 的倍数（如 $i \times 2, i \times 3, ..., i \times (i-1)$），这些数一定已经被比 $i$ 小的质数（如 $2, 3, ...$）筛掉了。因此，可以从 `j = i*i` 开始，以减少重复标记，提高效率。

3.  **选项对错分析**
    *   **A. 错误**。$2 \times i$ 一定是合数，但这不是从 $i \times i$ 开始的原因，因为 $2 \times i$ 也是 $i$ 的倍数，理应被筛掉。
    *   **B. 错误**。$i \times i$ 一定是合数（除非 $i=1$，但 $i$ 从 $2$ 开始），但这与起始位置的逻辑无关。
    *   **C. 正确**。准确描述了埃氏筛优化的核心逻辑：小于 $i \times i$ 的 $i$ 的倍数已经被更小的质因子处理过了。
    *   **D. 错误/不完整**。虽然这种写法能降低时间复杂度（减少常数因子），但选项表述不完整（“降为”后面无内容），且C选项解释了根本原因。

4.  **答案**
    **C**

5.  **易错点分析**
    *   误选A，认为 $2 \times i$ 是偶数所以不用筛，但忽略了 $i$ 可能是奇数（如 $3$），$2 \times 3 = 6$ 也是合数，需要被筛掉。
    *   混淆了“是否需要筛”和“是否已被筛”。$2 \times i$ 需要被筛，但可能已经被 $2$ 筛过了。

6.  **相关的知识点**
    *   埃氏筛法的时间复杂度（优化后约为 $O(n \log \log n)$）。
    *   线性筛法（欧拉筛）与埃氏筛的区别。

### **第7题：二分答案（最大化最小值问题）**

1.  **考察的知识点**
    **二分算法** -> 二分答案（二分枚举法）。

2.  **知识点详解**
    题目代码实现的是经典的“最大化最小值”问题（类似“跳石头”问题）。
    *   **问题背景**：给定数组 `a`（如距离坐标），要选出 `k` 个点，使得相邻两点间的最小距离 `dist` 最大。
    *   **`check`函数逻辑**：贪心策略。从第一个点开始，每次选择距离上一个已选点不小于 `dist` 的点，统计能选多少个点（`cnt`）。如果 `cnt >= k`，说明距离 `dist` 可行。
    *   **`solve`函数逻辑**：对答案（距离）进行二分。
        *   `l = 0`, `r = a[n-1] - a[0]`（最大可能距离）。
        *   `mid = (l + r + 1) / 2`（上取整，防止死循环）。
        *   如果 `check(mid)` 为真，说明 `mid` 可行，尝试更大的值（`l = mid`）；否则尝试更小的值（`r = mid - 1`）。

3.  **选项对错分析**
    *   **输入数据**：`a = {1, 2, 8, 4, 9}`, `n = 5`, `k = 3`。
    *   **排序后**：`a = {1, 2, 4, 8, 9}`。
    *   **模拟过程**：
        *   目标是选3个点，最大化最小距离。
        *   最优解是选 `1, 4, 8` 或 `1, 4, 9`，最小距离为 `3`（`4-1=3`）。
    *   **结论**：程序输出为 `3`。

4.  **答案**
    **B**

5.  **易错点分析**
    *   忽略了 `solve` 函数中 `std::sort` 对数组的排序。
    *   二分边界处理错误：`mid` 计算时的 `+1` 是为了在 `l` 和 `r` 相邻时向上取整，防止 `l = mid` 导致死循环。
    *   误以为是求最大距离或平均距离。

6.  **相关的知识点**
    *   二分答案的适用场景（求最大值的最小化或最小值的最大化）。
    *   贪心验证函数（`check`）的编写。

### **第8题：二分查找（Lower Bound）**

1.  **考察的知识点**
    **二分算法** -> 二分查找（查找第一个大于等于x的位置）。

2.  **知识点详解**
    这是标准的 `lower_bound` 二分查找实现。
    *   **循环不变量**：答案在区间 `[l, r)` 内。
    *   **判断逻辑**：
        *   如果 `a[mid] >= x`，说明 `mid` 可能是答案，或者答案在 `mid` 左侧（包含 `mid`）。因此，将右边界收缩到 `mid`（`r = mid`）。
        *   如果 `a[mid] < x`，说明 `mid` 一定不是答案，答案在 `mid` 右侧，因此 `l = mid + 1`。

3.  **选项对错分析**
    *   **A. `r = mid;`**：正确。符合上述“答案在左侧（包含mid）”的收缩逻辑。
    *   **B. `r = mid - 1;`**：错误。这会排除掉 `mid` 位置，而 `mid` 可能就是第一个大于等于 `x` 的元素。
    *   **C. `l = mid;`**：错误。这会导致区间不收缩，可能造成死循环。
    import io
    *   **D. `l = mid + 1;`**：这是 `a[mid] < x` 时的操作，不适用。

4.  **答案**
    **A**

5.  **易错点分析**
    *   混淆了 `lower_bound`（`>=x`）和 `upper_bound`（`>x`）的边界处理。
    *   混淆了闭区间 `[l, r]` 和半开区间 `[l, r)` 的写法。本题 `r = a.size()` 且 `while(l < r)` 表明是半开区间，收缩时不需要 `+1` 或 `-1`。

6.  **相关的知识点**
    *   二分查找的模板（循环条件、mid计算、边界收缩）。
    *   STL中的 `lower_bound` 和 `upper_bound` 函数。

### **第9题：递归与栈溢出**

1.  **考察的知识点**
    **递归算法** -> 递归调用机制、栈溢出（Stack Overflow）。

2.  **知识点详解**
    *   **A. 正确**。递归调用会不断在系统栈中压入栈帧，如果层次过深，会耗尽栈空间，导致栈溢出。
    *   **B. 正确**。尾递归是指递归调用是函数的最后一步操作。现代编译器可以优化尾递归，将其转换为循环，从而避免栈溢出。
    *   **C. 正确**。理论上，任何递归都可以通过显式使用栈（Stack）来模拟系统栈的调用过程，改写为循环。
    *   **D. 错误**。栈溢出属于严重的运行时错误（通常导致程序崩溃），在C++中通常不会抛出可被捕获的异常（如 `std::exception`），而是直接终止程序。

3.  **选项对错分析**
    题目问的是“**错误**”的说法。
    *   **D** 描述了栈溢出后“抛出异常并可以继续执行”，这在标准C++程序中是不成立的。

4.  **答案**
    **D**

5.  **易错点分析**
    *   受Java/C#等语言影响，误以为栈溢出是可捕获的异常。
    *   对尾递归优化的原理不熟悉，误以为B是错误的。

6.  **相关的知识点**
    *   函数调用栈（Call Stack）的结构。
    *   递归的空间复杂度分析。

### **第10题：二分答案（切割木头）**

1.  **考察的知识点**
    **二分算法** -> 二分答案（最大化平均值/长度问题）。

2.  **知识点详解**
    这是一个经典的“切割木头”问题，求能切出 `m` 段等长木段的最大长度。
    *   **`check`函数逻辑**：对于给定长度 `x`，计算每根木头能切出多少段（`a[i] / x`），累加总段数。如果总段数 `>= m`，返回 `true`。
    *   **二分逻辑**：
        *   `l = 1`（最小长度），`r = mx`（最长木头的长度）。
        *   `mid` 是当前尝试的长度。
        *   如果 `check(mid)` 为真，说明长度 `mid` 可行，尝试**更大的**长度（`l = mid + 1`），同时记录 `ans = mid`。
        *   如果 `check(mid)` 为假，说明长度太大，尝试**更小**的长度（`r = mid - 1`）。

3.  **选项对错分析**
    *   **A**：
        *   `l = mid + 1;` // 寻找更大的可行解
        *   `r = mid - 1;` // 寻找更小的解
        *   这符合二分查找的标准逻辑。
    *   **B**：`l = mid - 1` 和 `r = mid + 1` 逻辑混乱，会导致区间扩大或错误收缩。
    *   **C**：`r = mid` 错误，因为 `mid` 已经被证明不可行（在 `else` 分支），`mid` 及其右侧都不可行，应该收缩到 `mid - 1`。
    *   **D**：`l = mid` 会导致死循环（因为 `mid` 是下取整，`l` 可能不会变化）。

4.  **答案**
    **A**

5.  **易错点分析**
    *   混淆了“最大化”和“最小化”问题的二分方向。
    *   忽略了 `ans = mid` 的更新时机：只有在 `check` 为真时才更新，因为只有可行解才可能是答案。
    *   边界处理错误：在 `else` 分支中，`mid` 是不可行的，所以 `r` 应该设为 `mid - 1`。

6.  **相关的知识点**
    *   二分答案的整数二分模板（`while(l <= r)`）。
    *   浮点数二分答案（本题是整数）。

### **第11题：分治法求最大连续子段和**

1.  **考察的知识点**

2.  **知识点详解**

    *   易错选 $O(n^2)$（如果误以为递归树每层都是 $O(n^2)$）或 $O(n)$（如果误以为是线性扫描）。

4.  **答案**
    **(根据标准答案文档，该题答案为 C，对应 $O(n \log n)$)**

5.  **易错点分析**
    *   误以为合并过程是 $O(1)$，从而算出 $O(\log n)$。

### **第5题：归并排序求逆序对**

3.  **选项对错分析**

    **正确（✔）**

5.  **易错点分析**

    *   **最优子结构**：一个问题的最优解包含其子问题的最优解。
    *   **贪心算法条件**：贪心算法成立需要两个条件：**最优子结构** + **贪心选择性质**（局部最优能导致全局最优）。
    *   **题目分析**：题干说“若一个问题满足最优子结构性质，则一定可以用贪心算法得到最优解”，这是**错误**的。满足最优子结构是贪心算法的**必要条件**，但不是**充分条件**。例如，0-1背包问题具有最优子结构，但不能用贪心算法求解（需要动态规划）。

3.  **选项对错分析**
    *   逻辑错误。最优子结构是贪心和动态规划共有的特征，仅有它不足以保证贪心算法的正确性。

4.  **答案**
    **错误（×）**

5.  **易错点分析**
    *   混淆了“最优子结构”和“贪心选择性质”。
    *   误以为所有具有最优子结构的问题都可以用贪心解决。

6.  **相关的知识点**
    *   贪心算法的证明方法（如交换论证法）。
    *   动态规划与贪心算法的区别。

### **第9题：线性筛（欧拉筛）的核心原理**

1.  **考察的知识点**
    **初等数论** -> 素数表的线性筛法（欧拉筛）。

2.  **知识点详解**
    *   **埃氏筛缺点**：一个合数可能被多个质因子重复标记（如 $30$ 被 $2$、$3$、$5$ 各标记一次），时间复杂度约为 $O(n \log \log n)$。
    *   **线性筛核心**：每个合数只被其**最小质因数**（不是最大）筛去。
        *   代码逻辑：`if (i % primes[j] == 0) break;`
        *   原理：当 `primes[j]` 整除 `i` 时，说明 `primes[j]` 是 `i` 的最小质因数。此时 `i * primes[j]` 的最小质因数仍然是 `primes[j]`。如果继续枚举更大的质数 `primes[j+1]`，那么 `i * primes[j+1]` 的最小质因数就不是 `primes[j+1]` 了（因为 `i` 里含有更小的质因数），这会导致重复筛或逻辑错误。
    *   **题目分析**：题干描述“每个合数只被其**最大质因子**筛去”是**错误**的，正确的是**最小质因子**。

3.  **选项对错分析**
    *   关键概念错误（最大 vs 最小）。

4.  **答案**
    **错误（×）**

5.  **易错点分析**
    *   记混了“最小质因数”和“最大质因数”。
    *   对线性筛的 `break` 条件原理理解不透彻。

6.  **相关的知识点**
    *   线性筛的代码实现细节。
    *   时间复杂度 $O(n)$ 的证明。

### **第10题：递归转非递归**

1.  **考察的知识点**
    **递归算法** -> 递归的实现原理与栈模拟。

2.  **知识点详解**
    *   **递归原理**：函数调用通过系统栈（Call Stack）保存现场（参数、局部变量、返回地址）。
    *   **显式栈**：任何递归程序都可以通过显式使用一个栈（Stack）数据结构来模拟系统栈的行为，改写为非递归程序。
    *   **题目分析**：题干说“任何递归程序都可以改写为等价的非递归程序”是正确的。但后半句“改写后的非递归程序**一定需要**显式地使用栈”是**错误**的。
        *   **反例**：尾递归（Tail Recursion）。尾递归不需要显式栈，可以直接转换为循环（Loop），因为不需要保存返回地址来“回溯”。
        *   例如：`void print(int n) { if (n <= 0) return; cout << n; print(n-1); }` 可以直接改为 `for` 循环，无需栈。

3.  **选项对错分析**
    *   “一定需要”过于绝对。对于尾递归，不需要显式栈。

4.  **答案**
    **错误（×）**

5.  **易错点分析**
    *   误以为所有递归转换都必须用栈。
    *   忽略了尾递归这一特殊且重要的情况。

6.  **相关的知识点**
    *   尾递归优化（Tail Call Optimization）。
    *   迭代与递归的转换。
