### 第1题：唯一分解定理

**1. 考察的知识点**

- **分类：** 初等数论
- **具体考点：** 唯一分解定理（算术基本定理）

**2. 知识点详解**  
**唯一分解定理**（算术基本定理）是初等数论的基石。它指出：  
任何一个大于1的**合数** $N$，都可以唯一地表示为有限个**素数**的乘积。  
即：$N = p_1^{a_1} \times p_2^{a_2} \times \dots \times p_k^{a_k}$。  
这里的“唯一”是指不考虑素数排列顺序的情况下，这种分解形式是唯一的。

**3. 选项对错分析**

- **A. 任意整数都可以分解为素数的乘积**：错误。1既不是素数也不是合数，无法分解为素数乘积；负整数在基础数论讨论中通常不涉及此分解。
- **B. 每个合数都可以唯一分解为一系列素数的乘积**：**正确**。精准描述了定理的定义域（合数）和核心（唯一性）。
- **C. 两个不同的整数可以分解为相同的素数乘积**：错误。根据定理的唯一性，不同的整数分解出的素数乘积必然不同。
- **D. 以上都不对**：错误，因为B正确。

**4. 答案**  
**B**

**5. 易错点分析**

- **概念混淆**：容易忽略定理针对的是“合数”，误以为包括1或素数本身。
- **忽略“唯一”**：题目问的是“唯一分解定理”，选项中必须包含“唯一”这一特性，A选项虽然表述接近但不严谨且未体现“唯一”。

**6. 相关的知识点**

- 质因数分解
- 素数与合数的判定

### 第2题：贪心算法的核心思想

**1. 考察的知识点**

- **分类：** 贪心算法
- **具体考点：** 贪心算法的相关概念与核心思想

**2. 知识点详解**  
**贪心算法**（Greedy Algorithm）是一种在每一步选择中都采取在当前状态下最好或最优（即最有利）的选择，从而希望导致结果是全局最好或最优的算法。  
其核心在于**局部最优策略**：它不从整体最优上加以考虑，算法得到的是在某种意义上的局部最优解。贪心算法不能保证对所有问题都能得到整体最优解，必须证明其正确性。

**3. 选项对错分析**

- **A. 在每一步选择中都做当前状态下的最优选择**：**正确**。这是对贪心算法最标准的定义。
- **B. 在每一步选择中都选择局部最优解**：表述不够严谨。虽然贪心确实选择局部最优，但标准定义通常描述为“做当前状态下的最优选择”。
- **C. 在每一步选择中都选择全局最优解**：错误。贪心算法无法预知全局，只能基于当前做决定。
- **D. 以上都对**：错误，因为C明显错误。

**4. 答案**  
**A**

**5. 易错点分析**

- **偷换概念**：容易混淆“局部最优”和“全局最优”。贪心只能看到眼前（局部），无法直接选择全局。
- **理解偏差**：认为贪心总能得到正确答案（实际上需要数学证明，如活动选择问题、霍夫曼编码等）。

**6. 相关的知识点**

- 最优子结构
- 贪心选择性质
- 典型例题：找零钱问题（特定币值下）、区间调度问题。

### 第4题：双向链表删除节点

**1. 考察的知识点**

- **分类：** 链表
- **具体考点：** 双链表的删除操作

**2. 知识点详解**  
在**双向链表**中，每个节点包含三个部分：`prev`（指向前一个节点）、`data`（数据）、`next`（指向后一个节点）。  
删除节点 `current` 时，需要修改指针连接，绕过 `current`：

1. 让 `current` 的前驱节点的 `next` 指针指向 `current` 的后继节点。
2. 让 `current` 的后继节点的 `prev` 指针指向 `current` 的前驱节点。  
    题目代码中已经处理了头节点变更（`head = current->next`）和后继节点的 `prev` 指针（第13行），此处缺失的是处理前驱节点的 `next` 指针。

**3. 选项对错分析**

- **A. if (current->next != nullptr) current->next->prev = current->prev;**：错误。这是处理后继节点的逻辑，代码第13行已经写了。
- **B. current->prev->next = current->next;**：**正确**。这是处理前驱节点 `next` 指针的核心代码，使其跳过 `current` 直接指向 `current` 的下一个节点。
- **C. delete current->next;**：错误。这是删除下一个节点，逻辑完全错误。
- **D. current->prev = current->next;**：错误。这是修改 `current` 自身的 `prev` 指针，而不是修改链表连接。

**4. 答案**  
**B**

**5. 易错点分析**

- **指针逻辑混乱**：容易分不清是改 `current` 的指针，还是改 `current` 邻居的指针。删除操作的核心是**修改邻居的指针**，将 `current` “孤立”出来。
- **空指针异常**：代码第7行有判断 `current->prev != nullptr`，说明 `current` 不是头节点。因此可以直接操作 `current->prev->next` 而无需再次判空（已在 if 条件中保证）。

**6. 相关的知识点**

- 单链表的创建、插入、删除
- 循环链表的基本操作

### 第7题：高精度加法（字符串模拟）

**1. 考察的知识点**

- **分类：** C++高精度运算
- **具体考点：** C++数组/字符串模拟高精度加法

**2. 知识点详解**  
高精度加法的核心逻辑是**模拟竖式加法**：

1. 从个位（字符串末尾）开始逐位相加。
2. 处理进位（`carry`）。
3. 将结果拼接到新字符串中。

在本题代码中：

- `sum = x + y + carry;` 计算当前位的总和。
- `carry = sum / 10;` 更新进位。
- **横线处**需要将当前位的数值（`sum % 10`）转换为字符，并添加到结果字符串 `result` 的头部（因为是从低位向高位计算的）。

**3. 选项对错分析**

- **A. `result = to_string(sum % 10) + result;`**：**正确**。`sum % 10` 取出当前位的个位数，`to_string` 转为字符，拼接到 `result` 头部。
- **B. `result = to_string(carry % 10) + result;`**：错误。这里存入的是进位值，而不是当前位的值。
- **C. `result = to_string(sum / 10) + result;`**：错误。`sum / 10` 是进位值，不是当前位值。
- **D. `result = to_string(sum % 10 + carry) + result;`**：错误。逻辑混乱，重复加上了进位。

**4. 答案**  
**A**

**5. 易错点分析**

- **进位与本位混淆**：容易分不清 `sum / 10`（进位）和 `sum % 10`（本位）的区别。
- **字符串拼接顺序**：由于是从低位算起，新算出的位必须放在结果字符串的最前面（`+ result`），如果写成 `result + ...` 会导致结果逆序。

**6. 相关的知识点**

- 高精度减法（处理借位）
- 高精度乘法（竖式模拟或FFT）

### 第8题：二分查找循环次数

**1. 考察的知识点**

- **分类：** 二分算法
- **具体考点：** 二分查找算法的执行过程模拟

**2. 知识点详解**  
**二分查找**（Binary Search）的前提是序列有序。  
查找目标 `82`，序列是：`[1, 3, 6, 9, 17, 31, 39, 52, 61, 79, 81, 90, 96]`（共13个元素，下标0~12）。  
代码逻辑：

1. `left=0, right=12` -> `mid=6` -> `arr[6]=39` -> `39 < 82` -> `left = mid+1 = 7`
2. `left=7, right=12` -> `mid=9` -> `arr[9]=79` -> `79 < 82` -> `left = mid+1 = 10`
3. `left=10, right=12` -> `mid=11` -> `arr[11]=90` -> `90 > 82` -> `right = mid-1 = 10`
4. `left=10, right=10` -> `mid=10` -> `arr[10]=81` -> `81 < 82` -> `left = mid+1 = 11`
5. `left=11, right=10` -> `while` 条件 `left<=right` 不成立，循环结束。

**3. 选项对错分析**

- **A. 2**：错误。只算了前两次。
- **B. 5**：错误。可能多算了一次。
- **C. 3**：错误。
- **D. 4**：**正确**。根据上述模拟，循环执行了4次（分别计算了下标6, 9, 11, 10）。

**4. 答案**  
**D**

**5. 易错点分析**

- **边界计算错误**：容易在 `(right - left) / 2` 取整时出错（向下取整）。
- **循环条件判断**：容易漏掉最后一次 `left == right` 时的循环。
- **找不到的情况**：本题目标 `82` 不存在，需要遍历到区间为空（`left > right`）才停止，容易少算一步。

**6. 相关的知识点**

- 二分答案（二分枚举）
- 二分查找的递归实现

### 第9题：素数判定（边界修正）

**1. 考察的知识点**

- **分类：** 初等数论
- **具体考点：** 素数的判定方法（试除法）

- **问题**：当 `num` 是一个完全平方数（例如 25）时，`i` 循环到 5，因为 `5*5` 等于 `25` 并不满足 `< 25`，循环提前结束，导致无法检测到因子 5，从而错误地将 25 判定为素数。
- **修正**：循环条件必须包含等于的情况，即 `i * i <= num`，或者等价的 `i <= sqrt(num)`。

**3. 选项对错分析**

- **A. `num < 2` 改为 `num <= 2`**：错误。`num < 2` 是正确的（排除0和1），改为 `<=2` 会错误地排除2。
- **B. `i * i < num` 改为 `i * i <= num`**：**正确**。修复了完全平方数的判定漏洞。
- **C. `i <= num`**：错误。虽然逻辑正确，但时间复杂度退化为 $O(n)$，不符合高效算法要求。
- **D. `if (num % i != 0)`**：错误。逻辑反了，应该是能整除就返回 false。

**4. 答案**  
**B**

**5. 易错点分析**

- **边界思维**：容易忽略完全平方数这种特殊情况。
- **效率意识**：虽然选项C能解决问题，但在算法竞赛中，必须追求最优复杂度，因此选项B是标准答案。

**6. 相关的知识点**

- 唯一分解定理
- 埃拉托斯特尼筛法（埃氏筛）

### 第11题：素数线性筛法的时间复杂度

**1. 考察的知识点**
*   **分类：** 初等数论
*   **具体考点：** 素数表的线性筛法（欧拉筛）及其时间复杂度

**2. 知识点详解**
**线性筛法**（Linear Sieve），又称欧拉筛，是一种能在 $O(n)$ 时间复杂度内筛出 $1$ 到 $n$ 所有素数的算法。
*   **核心原理**：它通过保证每个合数都只被它的**最小质因子**筛掉，从而避免了埃拉托斯特尼筛法（埃氏筛）中的重复标记。
*   **复杂度分析**：因为每个数最多被访问一次（每个合数仅被其最小质因子标记一次），所以总的时间复杂度是线性的，即 **$O(n)$**。

**3. 选项对错分析**
*(注：原卷中选项A、B、C为空白，根据标准算法知识推断)*
*   **A. $O(n \log n)$** 或类似：错误。这是埃氏筛法的近似复杂度。
*   **B. $O(n \sqrt{n})$**：错误。这是暴力试除法的复杂度。
*   **C. $O(n)$**：**正确**。线性筛法的定义就是线性时间复杂度。
*   **D. $O(n^2)$**：错误。这是普通冒泡或选择排序的复杂度。

**4. 答案**
**C**

**5. 易错点分析**
*   **混淆筛法**：考生容易将“线性筛”与“埃氏筛”混淆。埃氏筛的时间复杂度约为 $O(n \log \log n)$，虽然接近线性但并非严格线性。题目明确问“线性筛法”，答案必然是 $O(n)$。
*   **概念模糊**：对“线性”二字的含义理解不深，误以为所有筛法都是 $O(n)$。

**6. 相关的知识点**
*   埃拉托斯特尼筛法（埃氏筛）
*   唯一分解定理
*   算法复杂度估算方法

### 第12题：归并排序的基本思想

**1. 考察的知识点**
*   **分类：** 分治算法
*   **具体考点：** 归并排序算法的核心思想

**2. 知识点详解**
**归并排序**（Merge Sort）是**分治算法**（Divide and Conquer）最典型的代表之一。
*   **分治三步走**：
    1.  **分解（Divide）**：将数组从中间一分为二。
    2.  **解决（Conquer）**：递归地对两个子数组进行归并排序。
    3.  **合并（Combine）**：将两个有序的子数组合并成一个有序数组。
*   **核心**：它不是通过交换元素位置来排序，而是通过递归分解和有序合并来实现的。

**3. 选项对错分析**
*   **A. 动态规划**：错误。动态规划强调重叠子问题和最优子结构，归并排序的子问题是独立的。
*   **B. 分治**：**正确**。归并排序是分治思想的标准实现。
*   **C. 贪心算法**：错误。贪心算法每一步做局部最优选择，归并排序没有局部最优的概念。
*   **D. 回溯算法**：错误。回溯算法是试错法，归并排序是确定性的分解合并。

**4. 答案**
**B**

**5. 易错点分析**
*   **概念混淆**：容易将“分治”与“递归”混淆。递归是实现手段，分治是解决问题的策略思想。
*   **与其他排序混淆**：容易与快速排序（也是分治）或堆排序（基于完全二叉树性质）混淆，但本题直接考察归并排序的标准定义。

**6. 相关的知识点**
*   快速排序算法
*   分治算法的递归实现

### 第13题：快速排序的主元素（Pivot）影响

**1. 考察的知识点**
*   **分类：** 分治算法
*   **具体考点：** 快速排序算法的性能分析

**2. 知识点详解**
**快速排序**（Quick Sort）也是一种分治算法。
*   **核心机制**：通过选择一个**主元素（Pivot）**，将数组分为两部分：左边小于Pivot，右边大于Pivot。
*   **Pivot的影响**：
    *   **时间复杂度**：如果每次选的Pivot都能将数组均匀分割（如选中位数），时间复杂度为 $O(n \log n)$；如果选的Pivot总是最大或最小值（如数组已有序），时间复杂度退化为 $O(n^2)$。
    *   **空间复杂度**：快排是原地排序，空间主要用于递归调用栈。Pivot的选择决定了递归的深度，从而直接影响栈空间的大小（即空间复杂度）。

**3. 选项对错分析**
*   **A. 不影响**：错误。Pivot的选择对快排性能至关重要。
*   **B. 时间复杂度**：不全面。虽然主要影响时间，但也间接影响了递归深度（空间）。
*   **C. 空间复杂度**：不全面。虽然影响栈深度，但最直接的体现是排序速度（时间）。
*   **D. 时间复杂度和空间复杂度**：**正确**。Pivot的选择直接决定了递归树的平衡性，从而同时影响了时间效率和栈空间大小。

**4. 答案**
**D**

**5. 易错点分析**
*   **只看时间**：大多数考生只记得Pivot影响快排的快慢（时间复杂度），容易忽略递归深度也由Pivot决定，从而忽略了对空间复杂度的影响。
*   **理解片面**：认为空间复杂度固定为 $O(n)$，忽略了其平均为 $O(\log n)$，最坏为 $O(n)$ 的特性。

**6. 相关的知识点**
*   快速排序的最坏情况分析
*   随机化快速排序（Randomized Quick Sort）

### 第14题：递归函数的终止条件

**1. 考察的知识点**
*   **分类：** 递归算法
*   **具体考点：** 递归算法的相关概念（基础条件）

**2. 知识点详解**
**递归**必须满足三个要素，其中最重要的是**基准情况**（Base Case）或**终止条件**。
*   **定义**：递归函数必须包含一个或多个不通过递归调用就能直接求解的条件，用于结束递归。
*   **原理**：如果没有终止条件，函数会无限调用自身，导致调用栈（Call Stack）溢出（Stack Overflow），程序崩溃。
*   虽然参数递减（B选项）通常是走向终止条件的方式，但核心必须是“有终止条件”。

**3. 选项对错分析**
*   **A. 有终止条件**：**正确**。这是避免无限递归的必要条件。
*   **B. 函数参数递减(或递增)**：错误。这是常见的手段，但不是本质。本质是状态要向终止条件靠近。
*   **C. 函数返回值固定**：错误。递归函数的返回值通常依赖于子问题的解，不是固定的。
*   **D. 以上都对**：错误。只有A是必须的。

**4. 答案**
**A**

**5. 易错点分析**
*   **混淆手段与目的**：容易误选B（参数递减）。参数递减是为了让函数最终满足终止条件，但如果只有递减没有显式的 `if` 判断终止，依然会无限递归。
*   **死循环思维**：将递归终止与循环终止混淆。

**6. 相关的知识点**
*   递归调用栈的内存管理
*   尾递归优化

### 第15题：链表查找函数返回值

**1. 考察的知识点**
*   **分类：** 链表
*   **具体考点：** 单链表的查找（遍历）操作

**2. 知识点详解**
题目给定链表：`1→3→5→7→nullptr`，调用 `searchValue(head, 5)`。
代码逻辑分析：
```cpp
int searchValue(ListNode* head, int target) {
    while (head != nullptr) {       // 遍历链表
        if (head->val == target) {  // 如果当前节点值等于目标值
            return 1;               // 返回 1 (表示找到)
        }
        head = head->next;          // 指针后移
    }
    return 0; // 循环结束未找到，返回 0
}
```
*   **执行过程**：
    1.  第一次循环：`head->val = 1`，不等于5，指针后移。
    2.  第二次循环：`head->val = 3`，不等于5，指针后移。
    3.  第三次循环：`head->val = 5`，等于5，执行 `return 1`。

**3. 选项对错分析**
*   **A. 返回1**：**正确**。目标值5存在于链表中，函数会命中 `if` 条件并返回1。
*   **B. 返回0**：错误。只有找不到时才返回0。
*   **C. 死循环，无法返回**：错误。链表末尾是 `nullptr`，循环条件会终止。
*   **D. 返回-1**：错误。代码中没有返回-1的逻辑。

**4. 答案**
**A**

**5. 易错点分析**
*   **指针移动误解**：误以为 `head = head->next` 会改变原链表结构（实际上只是改变了函数内部的局部指针变量）。
*   **逻辑短路**：容易误算节点位置，比如以为找的是下标而不是值，或者数错节点（以为5不存在）。

**6. 相关的知识点**
*   链表的遍历（Traversal）
*   指针的操作与空指针检查

### 第1题：辗转相除法的用途

**1. 考察的知识点**
*   **分类：** 初等数论
*   **具体考点：** 欧几里得算法（辗转相除法）的应用

**2. 知识点详解**
**辗转相 除法**（即欧几里得算法）是求解两个整数最大公约数（GCD）最高效的方法。
*   **核心原理**：$GCD(a, b) = GCD(b, a \mod b)$。
*   **应用**：它专门用于求**最大公约数**。如果需要求最小公倍数（LCM），通常先用此法求出GCD，再利用公式 $LCM(a, b) = (a \times b) / GCD(a, b)$ 计算。

**3. 判题分析**
*   **题目描述**：“辗转相除法用于求两个整数的最大公约数。”
*   **分析**：这是对该算法最标准、最准确的定义。
*   **结论**：**正确（✔）**

**4. 易错点分析**
*   **概念混淆**：容易与“更相减损术”混淆，或者误以为它可以同时直接求出最大公约数和最小公倍数（实际上它只直接求出GCD）。

**5. 相关的知识点**
*   最大公约数与最小公倍数的转换公式
*   扩展欧几里得算法（求解不定方程 $ax + by = gcd(a, b)$）

### 第2题：插入排序的时间复杂度

**1. 考察的知识点**
*   **分类：** 算法复杂度估算方法
*   **具体考点：** 插入排序的时间复杂度

**2. 知识点详解**
**插入排序**（Insertion Sort）的工作原理是通过构建有序序列，对于未排序数据，在已排序序列中从后向前扫描，找到相应位置并插入。
*   **实现逻辑**：通常包含两层嵌套循环。外层循环遍历每个元素，内层循环在已排序部分寻找插入位置。
*   **时间复杂度分析**：
    *   **最坏情况/平均情况**：$O(n^2)$。当输入数组是逆序时，每个元素都需要与前面所有已排序元素比较。
    *   **最好情况**：$O(n)$。当输入数组已经有序时，内层循环只需执行一次判断即可。

**3. 判题分析**
*   **题目描述**：“插入排序的时间复杂度是 $O(n)$。”
*   **分析**：题目表述**绝对化**了。虽然在“最好情况”下它是 $O(n)$，但通常在讨论算法复杂度时，如果没有特指，往往指的是**最坏情况**或**平均情况**，这两者都是 $O(n^2)$。因此，笼统地说它是 $O(n)$ 是错误的。
*   **结论**：**错误（×）**

**4. 易错点分析**
*   **忽略前提**：容易只记住“插入排序在有序情况下很快”，而忽略了题目没有给出“最好情况”这个前提条件。
*   **与其他算法混淆**：容易与“冒泡排序”的优化版本或“计数排序”等线性时间排序算法混淆。

**5. 相关的知识点**
*   冒泡排序、选择排序的时间复杂度（均为 $O(n^2)$）
*   线性时间复杂度的排序算法（如桶排序、计数排序，但有限制条件）

### 第3题：二分查找的序列要求

**1. 考察的知识点**
*   **分类：** 二分算法
*   **具体考点：** 二分查找算法的前提条件

**2. 知识点详解**
**二分查找**（Binary Search）是一种高效的查找算法。
*   **核心前提**：序列必须是**有序的**（升序或降序）。
*   **原理**：算法依赖于通过中间值与目标值的比较，来决定舍弃哪一半区间。如果序列无序，比较结果无法指导搜索方向，算法将失效。

**3. 判题分析**
*   **题目描述**：“二分查找要求被搜索的序列是有序的，否则无法保证正确性。”
*   **分析**：这是二分查找的铁律。无序序列无法使用二分查找，或者必须先排序才能使用。
*   **结论**：**正确（✔）**

**4. 易错点分析**
*   **无序查找误区**：可能会有学生认为“即使无序也能找，只是慢一点”，这是完全错误的。无序情况下二分查找会直接漏掉目标值。

**5. 相关的知识点**
*   二分答案（二分枚举）的单调性要求
*   二分查找的递归与非递归实现

### 第4题：贪心算法的局部最优与全局最优

**1. 考察的知识点**
*   **分类：** 贪心算法
*   **具体考点：** 贪心算法的性质与局限性

**2. 知识点详解**
**贪心算法**的核心是每一步都选择当前状态下的最优解（局部最优）。
*   **关键特性**：贪心算法**不能保证**所有问题都能得到全局最优解。
*   **适用条件**：只有当问题具有**贪心选择性质**和**最优子结构**时，贪心法才能得到最优解。
*   **反例**：0-1背包问题如果使用贪心（按价值密度排序），往往得不到全局最优解，而需要使用动态规划。

**3. 判题分析**
*   **题目描述**：“使用贪心算法解决问题时，每一步的局部最优解一定会导致全局最优解。”
*   **分析**：关键词是“**一定**”。贪心算法的难点就在于需要数学证明这种“一定”是成立的。对于任意问题，局部最优并不必然导致全局最优。
*   **结论**：**错误（×）**

**4. 易错点分析**
*   **理想化思维**：初学者容易认为“每一步都选最好的，结果肯定最好”，忽略了现实问题中可能存在“短视”带来的陷阱。
*   **概念混淆**：容易将贪心算法与动态规划混淆。动态规划通过保存子问题的最优解，是可以保证得到全局最优解的。

**5. 相关的知识点**
*   贪心算法的证明方法（如交换论证法）
*   典型贪心问题（如活动选择问题、霍夫曼编码、最小生成树Prim/Kruskal算法）

### 第5题：分治算法的定义

**1. 考察的知识点**
*   **分类：** 分治算法
*   **具体考点：** 分治算法的核心思想

**2. 知识点详解**
**分治算法**（Divide and Conquer）的基本思想包含三个步骤：
1.  **分解（Divide）**：将原问题分解成若干个规模较小、相互独立且与原问题形式相同的子问题。
2.  **解决（Conquer）**：若子问题规模足够小，则直接解决；否则递归地解决各个子问题。
3.  **合并（Combine）**：将各个子问题的解合并为原问题的解。

**3. 判题分析**
*   **题目描述**：“分治算法的核心思想是将一个大问题分解成多个相同或相似的子问题进行解决，最后合并得到原问题的解。”
*   **分析**：这段描述精准地概括了分治法的“分解”和“合并”过程，以及子问题的性质。
*   **结论**：**正确（✔）**

**4. 易错点分析**
*   **遗漏“合并”**：有时学生只记得“分而治之”，容易忽略最后必须有“合并”这一步骤。
*   **与递归混淆**：分治是一种解决问题的策略，递归是实现这种策略的常见手段，但二者概念不同。

**5. 相关的知识点**
*   递归与分治的关系
*   典型分治算法（归并排序、快速排序、大整数乘法、Strassen矩阵乘法）

### 第6题：归并排序的时间复杂度

**1. 考察的知识点**
*   **分类：** 分治算法
*   **具体考点：** 归并排序算法的时间复杂度

**2. 知识点详解**
**归并排序**是分治算法的完美体现。
*   **时间复杂度分析**：
    *   **分解**：将数组一分为二，时间复杂度 $O(1)$。
    *   **解决**：递归地对两个子数组排序，时间复杂度 $2T(n/2)$。
    *   **合并**：将两个有序数组合并，需要遍历所有 $n$ 个元素，时间复杂度 $O(n)$。
    *   **总复杂度**：根据主定理（Master Theorem）或递归树分析，归并排序的时间复杂度恒为 **$O(n \log n)$**。
    *   **特点**：它是一种**稳定**的排序算法，且无论最好、最坏还是平均情况，时间复杂度都是 $O(n \log n)$。

**3. 判题分析**
*   **题目描述**：“分治算法的典型应用之一是归并排序，其时间复杂度为 $O(n \log n)$。”
*   **分析**：前半句正确（归并排序是分治典型），后半句正确（复杂度确实是 $O(n \log n)$）。
*   **结论**：**正确（✔）**

**4. 易错点分析**
*   **混淆快排**：容易将其与快速排序混淆。快排的平均是 $O(n \log n)$，但最坏是 $O(n^2)$；而归并排序在任何情况下都是 $O(n \log n)$。
*   **忽略稳定性**：虽然本题未涉及，但归并排序的空间复杂度是 $O(n)$，这是它与快排的主要区别。

**5. 相关的知识点**
*   快速排序的复杂度分析
*   算法复杂度的主定理

### 第7题：埃氏筛与线性筛的时间复杂度

**1. 考察的知识点**
*   **分类：** 初等数论
*   **具体考点：** 素数表的埃氏筛法和线性筛法的时间复杂度对比

**2. 知识点详解**
*   **埃拉托斯特尼筛法（埃氏筛）**：
    *   **原理**：对于每个素数 $p$，标记其所有倍数（$2p, 3p, ...$）。
    *   **复杂度**：一个合数可能被多个因子重复标记（例如 6 会被 2 和 3 各标记一次）。其时间复杂度约为 **$O(n \log \log n)$**。虽然效率很高，但并非线性。
*   **线性筛法（欧拉筛）**：
    *   **原理**：通过限制只用每个数的**最小质因子**去筛除它，保证每个数只被访问一次。
    *   **复杂度**：**$O(n)$**。

**3. 判题分析**
*   **题目描述**：“素数表的埃氏筛法和线性筛法的时间复杂度都是 $O(n)$。”
*   **分析**：线性筛法是 $O(n)$，但埃氏筛法是 $O(n \log \log n)$。题目使用了“都是”，意味着两者必须同时满足才正确。因此该命题是**错误**的。
*   **结论**：**错误（×）**

**4. 易错点分析**
*   **概念模糊**：容易混淆“埃氏筛”和“线性筛”。在实际应用中，埃氏筛已经足够快，导致很多学生忽略了它们在理论复杂度上的严格区别。
*   **名称误导**：“线性筛”这个名字本身就暗示了它是 $O(n)$ 的，而埃氏筛不是。

**5. 相关的知识点**
*   素数判定的试除法（$O(\sqrt{n})$）
*   唯一分解定理

### 第8题：贪心算法的普适性

**1. 考察的知识点**
*   **分类：** 贪心算法
*   **具体考点：** 贪心算法的适用范围与局限性

**2. 知识点详解**
**贪心算法**是一种启发式策略。
*   **局限性**：贪心算法**不能**应用于所有问题。它仅适用于具有**贪心选择性质**（局部最优能导致全局最优）的问题。
*   **反例**：对于经典的**0-1背包问题**，贪心算法（按价值密度排序）往往得不到最优解，必须使用动态规划。
*   **结论**：贪心是一种“特殊”的解法，而非“通用”的万能解法。

**3. 判题分析**
*   **题目描述**：“贪心算法是一种可以应用于所有问题的通用解决方案。”
*   **分析**：关键词是“所有问题”和“通用”。这是典型的绝对化错误表述。
*   **结论**：**错误（×）**

**4. 易错点分析**
*   **过度自信**：初学者在解决了一些简单的贪心题（如找零钱、区间调度）后，容易误以为贪心是万能的。
*   **缺乏反例意识**：需要记住几个贪心不适用的经典反例（如0-1背包、多段图最短路径等）。

**5. 相关的知识点**
*   动态规划（解决贪心无法处理的问题）
*   回溯算法（穷举所有可能）

### 第9题：链表头部操作的时间复杂度

**1. 考察的知识点**
*   **分类：** 链表
*   **具体考点：** 单链表和双链表在头部插入/删除的时间复杂度

**2. 知识点详解**
*   **单链表（Singly Linked List）**：
    *   **头部插入/删除**：已知头指针 `head`，创建新节点指向 `head`，再更新 `head` 即可。时间复杂度 **$O(1)$**。
*   **双链表（Doubly Linked List）**：
    *   **头部插入/删除**：同样已知头指针，操作涉及 `next` 和 `prev` 指针的调整，但步骤固定，时间复杂度也是 **$O(1)$**。
*   **对比**：与数组不同，链表不需要移动元素，只需要修改指针。

**3. 判题分析**
*   **题目描述**：“单链表和双链表都可以在常数时间内实现在链表头部插入或删除节点的操作。”
*   **分析**：无论是单链表还是双链表，头部操作都不依赖于链表长度，都是常数时间操作。
*   **结论**：**正确（✔）**

**4. 易错点分析**
*   **混淆尾部操作**：如果是**尾部**插入，单链表通常需要遍历找到尾节点（$O(n)$），除非维护了尾指针。但题目明确问的是“头部”。
*   **混淆查找**：链表的查找操作是 $O(n)$，但插入/删除操作（在已知位置时）是 $O(1)$。

**5. 相关的知识点**
*   链表的插入与删除操作指针调整细节
*   循环链表的操作特性

### 第10题：递归与栈空间

**1. 考察的知识点**
*   **分类：** 递归算法
*   **具体考点：** 递归算法的空间复杂度与系统栈

**2. 知识点详解**
*   **递归的实现机制**：C/C++语言中，递归函数是通过**系统调用栈**（Call Stack）来实现的。
*   **空间消耗**：
    *   每次函数调用，系统都会在栈上分配一个**栈帧**（Stack Frame）来保存局部变量、参数和返回地址。
    *   递归调用层数越深，栈帧越多，占用的栈空间越大。
*   **栈溢出（Stack Overflow）**：如果递归深度过大（例如没有正确终止条件，或者数据规模极大），栈空间会被耗尽，导致程序崩溃。

**3. 判题分析**
*   **题目描述**：“在 C 语言中，递归的实现方式通常会占用更多的栈空间，可能导致栈溢出。”
*   **分析**：这是对递归空间特性的准确描述。相比于循环（迭代），递归通常需要更多的内存空间来维护调用栈。
*   **结论**：**正确（✔）**

**4. 易错点分析**
*   **混淆时间与空间**：容易只关注递归的时间复杂度，而忽略其空间代价。
*   **尾递归误解**：虽然某些编译器可以对**尾递归**进行优化，将其转化为循环从而节省栈空间，但在标准C语言和通用考试环境下，通常默认递归会增加栈空间消耗。

**5. 相关的知识点**
*   递归与迭代（循环）的优劣对比
*   尾递归及其优化原理
