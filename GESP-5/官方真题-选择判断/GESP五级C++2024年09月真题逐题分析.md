### 第1题：数组与链表的特性对比

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：数组与链表在内存分配、访问方式、插入删除效率及空间利用率上的区别。

**2. 知识点详解**
*   **数组 (Array)**：内存中连续存储，大小固定。支持**随机访问**（通过下标直接访问，时间复杂度 $O(1)$），但在中间插入或删除元素时，需要移动大量元素（时间复杂度 $O(n)$）。
*   **链表 (Linked List)**：内存中非连续存储，通过指针连接。大小可**动态调整**。只能**顺序访问**（从头遍历，时间复杂度 $O(n)$），但插入和删除操作只需修改指针（时间复杂度 $O(1)$，前提是已找到位置）。
*   **内存空间**：链表每个节点除了存储数据外，还需要额外的空间存储指针（如 `next` 指针），因此在存储相同数量的数据时，**链表比数组占用的内存更多**。

**3. 选项对错分析**
*   **A. 数组大小固定，链表大小可动态调整**：✅ 正确描述。
*   **B. 数组支持随机访问，链表只能顺序访问**：✅ 正确描述。
*   **C. 存储相同数目的整数，数组比链表所需的内存多**：❌ **错误描述**。这是本题的答案（问的是“错误”的描述）。实际上，链表因为有指针域，内存开销更大。
*   **D. 数组插入和删除元素效率低，链表插入和删除元素效率高**：✅ 正确描述（指指针修改部分）。

**4. 答案**
**C**

**5. 易错点分析**
容易混淆“时间效率”和“空间效率”。虽然链表操作效率高，但它是以牺牲空间（存储指针）为代价的。

**6. 相关的知识点**
*   顺序表与链表的时间复杂度对比（访问、插入、删除）。
*   单链表、双向链表的结构差异。

### 第2题：双向循环链表的插入操作

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：双向循环链表中节点的插入逻辑（指针修改的顺序）。

**2. 知识点详解**
在双向链表中插入节点 `s` 到节点 `p` 之后，需要修改四个指针：
1.  `s->next` 指向 `p->next`。
2.  `s->prev` 指向 `p`。
3.  `p->next->prev` 指向 `s`（原 `p` 的后继节点的前驱指向 `s`）。
4.  `p->next` 指向 `s`。

**关键点**：修改顺序必须保证在操作过程中不会丢失后续节点的地址。通常先处理 `s` 的指针，再修改原链表的指针。

**3. 选项对错分析**
*   **A**：`p->next->prev = s` 放在第一句，此时 `p->next` 还未改变，看似可以，但若后续 `p->next = s` 改变后，`s->next` 还没赋值，逻辑混乱且有风险。❌
*   **B**：`p->next = s` 提前执行，导致 `p->next->prev` 实际上变成了 `s->prev`，覆盖了原本要指向 `p` 的操作。❌
*   **C**：逻辑正确，但最后一句 `p->next->prev = s` 中，`p->next` 已经被更新为 `s`，所以这句变成了 `s->prev = s`，导致 `s` 指向自己，破坏了结构。❌
*   **D**：`s->next = p->next`（先连后）；`p->next->prev = s`（后节点指向前）；`s->prev = p`（前连后）；`p->next = s`（前节点指向后）。✅ 逻辑严密，没有断链。

**4. 答案**
**D**

**5. 易错点分析**
指针操作的顺序非常关键。如果先改变了 `p->next`，那么原本的 `p` 的后继节点地址就会丢失，导致无法正确连接后面的链表。必须先用 `s` 接好“断口”两边，再切断原来的连接。

**6. 相关的知识点**
*   单链表的插入与删除（需注意头节点处理）。
*   双向链表的删除操作。

### 第3题：递归与迭代的时间复杂度对比

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：递归算法与迭代算法（循环）的时间复杂度分析与对比。

**2. 知识点详解**
*   **SumA**：使用 `for` 循环从 1 累加到 n，执行了 n 次操作，时间复杂度为 $O(n)$。
*   **SumB**：递归调用。`sumB(n)` 会调用 `sumB(n-1)`，直到 `sumB(1)`。一共发生了 n 次函数调用，每次调用进行一次加法运算，时间复杂度也是 $O(n)$。
*   **效率对比**：虽然时间复杂度同阶，但递归涉及函数调用栈的压栈和出栈，系统开销（常数因子）通常比循环大，因此**递归效率通常低于迭代**。

**3. 选项对错分析**
*   **A. sumA体现了迭代的思想**：✅ 正确。
*   **B. SumB采用的是递归方式**：✅ 正确。
*   **C. SumB 函数比 SumA 的时间效率更高**：❌ **错误**。这是本题的答案。递归有函数调用的额外开销，效率更低。
*   **D. 两个函数的实现的功能相同**：✅ 正确，都是计算 1 到 n 的和。

**4. 答案**
**C**

**5. 易错点分析**
容易误以为递归是“高级”写法所以效率更高，或者忽略了函数调用本身的系统开销。在没有记忆化优化的情况下，单纯的线性递归效率通常不如循环。

**6. 相关的知识点**
*   递归的空间复杂度（通常为 $O(n)$，因为有 n 层栈）。
*   尾递归优化的概念。

### 第4题：欧几里得算法（最大公约数）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：欧几里得算法（辗转相除法）的原理与应用。

**2. 知识点详解**
欧几里得算法基于原理：$gcd(a, b) = gcd(b, a \mod b)$。
代码逻辑：
*   如果 `a % b == 0`，说明 `b` 能整除 `a`，则 `b` 就是最大公约数。
*   否则，递归计算 `fun(b, a % b)`。

**3. 选项对错分析**
计算 `fun(20, 12)`：
1.  `20 % 12 = 8`，调用 `fun(12, 8)`
2.  `12 % 8 = 4`，调用 `fun(8, 4)`
3.  `8 % 4 = 0`，满足条件，返回 `4`。

**4. 答案**
**C** (4)

**5. 易错点分析**
*   容易看错参数顺序。第一次调用是 `fun(20, 12)`，即 `a=20, b=12`。
*   容易混淆 `a%b==0` 时返回的是 `a` 还是 `b`。根据逻辑，此时 `b` 是除数，且能整除，所以 `b` 是公约数。

**6. 相关的知识点**
*   辗转相除法求最大公约数（GCD）。
*   更相减损术。
*   扩展欧几里得算法。

### 第5题：埃拉托斯特尼筛法（素数筛）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：埃拉托斯特尼筛法（埃氏筛）的实现细节。

**2. 知识点详解**
埃氏筛的原理：从小到大遍历，如果当前数 `i` 是素数，则将其所有的倍数（`2i, 3i, 4i...`）标记为合数。
*   **优化**：其实不需要从 `2i` 开始标记，因为 `2i` 在处理质数 2 时已经被标记了，`3i` 在处理质数 3 时已经被标记了。所以可以从 `i*i` 开始标记。
*   **步长**：每次增加 `i`（即 `i` 的倍数）。

**3. 选项对错分析**
*   **A. for (int j = i; j <= n; j++)**：❌ 没有步长控制，会一个一个加，且从 `i` 开始会把自己标记掉。
*   **B. for (int j = i * i; j <= n; j++)**：❌ 缺少步长 `+=i`，会遍历所有数，而不是 `i` 的倍数。
*   **C. for (int j = i * i; j <= n; j += i)**：✅ 正确。从 `i` 的平方开始，以步长 `i` 标记所有倍数。
*   **D. for (int j = i; j <= n; j += i)**：❌ 虽然能筛，但效率低。它从 `i` 开始，会重复标记 `i` 的小倍数（如 `2i`），且 `j=i` 时会把素数 `i` 自己错误地标记为非素数。

**4. 答案**
**C**

**5. 易错点分析**
*   **边界**：循环变量 `j` 的初始值应该是 `i` 还是 `i*i`？`i` 会把自己筛掉（导致素数也被标记为非素数），所以必须是 `i*i`。
*   **逻辑**：内层循环的目的是标记 `i` 的倍数，所以步长必须是 `i`。

**6. 相关的知识点**
*   素数的定义。
*   线性筛法（欧拉筛）：保证每个合数只被其最小的质因数筛掉一次，时间复杂度 $O(n)$。

### 第6题：线性筛法（欧拉筛）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：线性筛法（Linear Sieve / 欧拉筛）的内层循环条件。

**2. 知识点详解**
线性筛法的核心思想是**每个合数只被其最小的质因数筛掉一次**，从而保证时间复杂度为 $O(n)$。
*   **代码逻辑**：外层循环遍历 $i$（从2到n），内层循环遍历已找到的质数列表 `primes`。
*   **关键操作**：对于当前的 $i$ 和质数列表中的第 $j$ 个质数 `primes[j]`，我们将 $i \times \text{primes}[j]$ 标记为合数。
*   **终止条件（break）**：如果 $i$ 能被 $\text{primes}[j]$ 整除（即 `i % primes[j] == 0`），说明 $\text{primes}[j]$ 是 $i$ 的最小质因数。此时必须跳出内层循环，以确保每个数只被筛一次。

**3. 选项对错分析**
题目代码片段分析：
*   `is_prime[i * primes[j]] = 0;`：标记合数。
*   `if (i % primes[j] == 0) break;`：核心去重逻辑。
*   **内层循环变量**：`j` 是质数列表 `primes` 的下标。

*   **A. `for (int j = 0; j < primes.size() && i * primes[j] <= n; j++)`**：
    ✅ **正确**。`j` 从 0 开始遍历质数列表，循环继续的条件是：`j` 不越界（`j < primes.size()`）且待筛数 `i * primes[j]` 不超过范围 `n`。
*   **B. `for (int j = 1; j < primes.size() && i * j <= n; j++)`**：
    ❌ 错误。`j` 从 1 开始会漏掉第一个质数（下标0）；且条件 `i * j` 错误，应该是 `i * primes[j]`。
*   **C. `for (int j = 2; j < primes.size() && i * primes[j] <= n; j++)`**：
    ❌ 错误。`j` 从 2 开始漏掉了前两个质数。
*   **D. 以上都不对**：
    ❌ 错误。因为 A 是正确的。

**4. 答案**
**A**

**5. 易错点分析**
*   **下标混淆**：线性筛通常用 `j` 作为质数数组的下标，而不是直接作为质数使用（如选项B所示）。
*   **起始位置**：数组下标通常从 0 开始，质数列表的第一个元素（2）的下标是 0。

**6. 相关的知识点**
*   埃拉托斯特尼筛法（埃氏筛）：时间复杂度 $O(n \log \log n)$。
*   最小质因数分解。

### 第9题：快速排序的最坏情况

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：快速排序在特定输入（已排序数组）下的时间复杂度表现。

**2. 知识点详解**
快速排序的核心是 Partition（划分）。
*   **基准选择**：题目明确指出“总是选择第一个元素作为基准元素”。
*   **输入情况**：输入是“已排序数组”。
*   **后果**：每次划分时，基准元素（最小值）左边没有元素，右边有 $n-1$ 个元素。树的高度变成了 $n$ 层，而不是理想的 $\log n$ 层。
*   **复杂度**：这种情况下，时间复杂度退化为 **$O(n^2)$**。
*   **结论**：这是快速排序的**最坏情况**，而不是最好情况。

**3. 选项对错分析**
*   **A. 快速排序对于此类输入的表现最好**：❌ 错误。这是最坏情况。
*   **B. 时间复杂度是...**：*（选项内容缺失，但根据逻辑应为 $O(n^2)$）* ✅ 正确描述了该情况。
*   **C. 时间复杂度是...**：*（选项内容缺失，通常指 $O(n \log n)$）* ❌ 错误。
*   **D. 无法排序**：❌ 错误。它能排序，只是很慢。

**4. 答案**
**C** (注：此处根据文档答案位推断，选项C应为描述 $O(n^2)$ 的选项)

**5. 易错点分析**
*   **思维定势**：容易误以为“数组已经有序”对任何排序算法都是最好的。对于快排（首元素基准）和冒泡排序来说，这是最差的；对于插入排序来说，这才是最好的（$O(n)$）。

**6. 相关的知识点**
*   快速排序的平均时间复杂度 $O(n \log n)$。
*   随机化快速排序（Randomized Quick Sort）以避免最坏情况。

### 第10题：归并排序的递归调用次数

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：归并排序递归调用的次数估算。

**2. 知识点详解**
归并排序的递归过程形成一棵二叉树：
*   **分解过程**：每次将数组一分为二。
*   **节点数量**：对于 $n$ 个元素，递归树大约有 $n$ 个叶子节点（单个元素）。在二叉树中，总结点数大约是叶子节点数的 2 倍（$2n-1$）。
*   **调用次数**：每次递归调用对应树中的一个节点。因此，`merge_sort` 函数被调用的总次数大约是 **$2n$** 次。
*   **Merge 函数调用**：每次非叶子节点的调用都会触发一次 `merge`。`merge` 被调用的次数等于非叶子节点的数量，大约是 **$n$** 次（因为 $n$ 个叶子节点需要 $n-1$ 次合并操作）。

**3. 选项对错分析**
*   *注：原题文档中选项 A/B/C/D 为空白。*
*   **逻辑推断**：题目问的是 `merge` 函数的递归调用次数。

**4. 答案**
**$O(n)$** (对应文档答案位 C)

**5. 易错点分析**
*   **混淆函数**：题目问的是 `merge` 函数的调用次数，不是 `merge_sort` 的调用次数。`merge_sort` 调用约 $2n$ 次，`merge` 调用约 $n$ 次。
*   **复杂度层级**：容易误选 $O(n \log n)$（这是总的时间复杂度，包含 merge 内部的遍历操作），但单纯的“调用次数”只是 $O(n)$。

**6. 相关的知识点**
*   递归树的节点计数。
*   归并排序的空间复杂度 $O(n)$。

### 第11题：过河问题的算法思想

**1. 考察的知识点**
*   **大纲分类**：8. 贪心算法
*   **具体考点**：贪心策略在“过河问题”或“装载问题”中的应用。

**2. 知识点详解**
题目描述的是经典的**双指针贪心**问题（类似“乘船问题”）：
*   **场景**：$n$ 个人过河，船最多载2人，限重100kg。
*   **策略**：为了让船数最少，最优策略是**尽量让最重的人和最轻的人配对**。
*   **代码逻辑分析**：
    *   `i` 指向最轻的人（数组头），`j` 指向最重的人（数组尾）。
    *   循环尝试让 `weight[i]`（最轻）和 `weight[j]`（最重）同船。
    *   如果两人重量和 `<= 100`，说明可以同船，`i++`（轻的上船走了）。
    *   `j--`（重的肯定要上船，无论是否配对），`count++`（船数加一）。
*   **贪心思想**：每次决策都试图让一艘船坐满两人（局部最优），从而减少总船数。

**3. 选项对错分析**
*   **A. 枚举算法**：❌ 枚举是遍历所有可能方案，这里没有遍历所有配对方式。
*   **B. 贪心算法**：✅ 正确。采用了“最重+最轻”的配对贪心策略。
*   **C. 迭代算法**：❌ 迭代是一种循环实现方式，不是解决该问题的特定策略思想。
*   **D. 递归算法**：❌ 代码使用的是循环（for/while），没有函数自我调用。

**4. 答案**
**B**

**5. 易错点分析**
容易误选“迭代算法”，因为代码看起来是循环的。但题目问的是“采用的思想”，算法思想层面属于贪心策略，实现方式层面才是迭代。

**6. 相关的知识点**
*   贪心算法的经典例题：区间调度（活动选择）、找零钱问题、背包问题（分数背包）。
*   双指针技巧（Two Pointers）。

### 第12题：分治算法的概念

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：分治算法的基本定义与特征。

**2. 知识点详解**
分治算法（Divide and Conquer）的核心步骤：
1.  **分解（Divide）**：将原问题划分为若干个规模较小的子问题。
2.  **解决（Conquer）**：递归地解决这些子问题。
3.  **合并（Combine）**：将子问题的解合并为原问题的解。

**3. 选项对错分析**
*   **A. 分治算法将问题分成子问题，然后分别解决子问题，最后合并结果**：✅ **正确**。完美概括了分治三步曲。
*   **B. 归并排序不是分治算法的应用**：❌ 错误。归并排序是分治算法最典型的代表（分解为单个元素，排序，合并有序数组）。
*   **C. 分治算法通常用于解决小规模问题**：❌ 错误。分治算法通常用于解决大规模问题，通过递归分解来降低难度。
*   **D. 分治算法的时间复杂度总是优于...**：❌ 错误。分治算法的时间复杂度取决于具体实现（如快速排序最坏为 $O(n^2)$），并非总是最优。

**4. 答案**
**A**

**5. 易错点分析**
无明显陷阱，属于概念记忆题。只要记住“分而治之”的核心定义即可。

**6. 相关的知识点**
*   分治算法的适用条件（最优子结构、独立子问题）。
*   分治法与动态规划的区别（子问题是否重叠）。

### 第13题：二分查找的执行次数

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法
*   **具体考点**：二分查找算法的具体执行过程模拟。

**2. 知识点详解**
*   **数组**：`[1, 3, 6, 9, 17, 31, 39, 52, 61, 79]` (下标 0~9)
*   **目标**：`31`
*   **过程模拟**：
    1.  **第1次循环**：`left=0`, `right=9`。`mid = 0 + (9-0)/2 = 4`。`nums[4] = 17`。因为 `17 < 31`，所以 `left = mid + 1 = 5`。

*   **A. 1**：❌ 未找到。

*   **C. 3**：✅ 正确。
*   **D. 4**：❌ 第3次循环已返回结果，不会进入第4次。

**4. 答案**
**C**

**5. 易错点分析**
*   **Mid计算公式**：容易算错 `mid` 的值（特别是 `(left + right) / 2` 可能溢出，题目代码使用了防溢出写法 `left + (right - left) / 2`，结果一致）。

**6. 相关的知识点**

### 第14题：高精度运算的特性

**1. 考察的知识点**
*   **大纲分类**：4. C++高精度运算
*   **具体考点**：高精度乘法的时间复杂度分析。

**2. 知识点详解**
高精度运算通常用数组模拟竖式计算：
*   **加法/减法**：时间复杂度 $O(n)$，主要取决于位数较长的那个数。
*   **乘法（竖式模拟）**：时间复杂度 $O(n \times m)$。每一位都要与另一个数的每一位相乘。
    *   如果是大整数乘以小整数（一个位数多，一个位数少），复杂度取决于大整数的位数。
    *   如果是大整数乘以大整数，复杂度与两个整数的位数乘积有关。

**3. 选项对错分析**
*   **A. 高精度计算主要是用来处理大整数或需要保留多位小数的运算**：✅ 正确。
*   **B. 大整数除以小整数...从左到右逐位尝试**：✅ 正确。这是高精度除法（模拟人工试商）的标准流程。
*   **C. 高精度乘法的运算时间只与参与运算的两个整数中长度较长者的位数有关**：❌ **错误**。这是本题的答案。如果是**高精度 $\times$ 高精度**，时间复杂度是 $O(n \times m)$。只有在**高精度 $\times$ 低精度**（小整数）时，才只与长整数的位数有关。
*   **D. 高精度加法运算的关键在于逐位相加并处理进位**：✅ 正确。

**4. 答案**
**C**

**5. 易错点分析**
容易忽略“高精度乘高精度”的情况。在竞赛中，如果两个数都非常大，朴素的乘法算法复杂度是两数位数的乘积。

**6. 相关的知识点**
*   高精度加法、减法、乘法（大数 $\times$ 小数，大数 $\times$ 大数）、除法（大数 $\div$ 小数）的模板。
*   进位与借位的处理。

**正确（✔）**

**5. 易错点分析**

**6. 相关的知识点**
*   单链表、双向链表、循环链表的区别。

### 第2题：素数筛法的效率

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：埃氏筛与线性筛的时间复杂度对比。

**2. 知识点详解**
*   **埃拉托斯特尼筛法（埃氏筛）**：
    *   原理：标记每个质数的倍数。
    *   缺点：一个合数可能会被其多个质因子重复标记（例如 12 会被 2 和 3 各标记一次）。
    *   时间复杂度：$O(n \log \log n)$。
*   **线性筛法（欧拉筛）**：
    *   原理：通过判断 `i % primes[j] == 0` 来保证每个合数只被其**最小质因数**筛掉一次。
    *   优点：每个数仅被访问一次。
    *   时间复杂度：$O(n)$。
*   **结论**：线性筛法的效率确实高于埃氏筛法，尤其是在数据规模很大时。

**3. 选项对错分析**
*   **题目描述**：“线性筛法效率更高。”
*   **分析**：该描述正确。从时间复杂度上看，$O(n)$ 优于 $O(n \log \log n)$。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **误解“效率”**：可能会有同学认为“写起来简单的效率高”，或者认为两者差不多。
*   **空间换时间**：虽然线性筛法时间复杂度更低，但它通常需要维护一个额外的质数数组，空间复杂度与埃氏筛相当，但在时间上确实更优。

**6. 相关的知识点**
*   两种筛法的代码实现细节（特别是线性筛的 `break` 条件）。
*   筛法的适用场景（预处理大量素数时）。

**错误（×）**

**5. 易错点分析**
*   **记忆模糊**：容易混淆“质因数分解”（乘法）与“拆分整数”（加法）的概念。

### 第4题：贪心算法的性质

**1. 考察的知识点**
*   **大纲分类**：8. 贪心算法
*   **具体考点**：贪心算法的局限性（是否总能得到全局最优解）。

**2. 知识点详解**

**3. 选项对错分析**

*   **分析**：该描述**错误**。关键词是“一定”。贪心算法很多时候只能得到近似解或局部最优解。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **过度自信**：在学习了几个贪心成功的例子（如排队接水、找零钱）后，容易误以为贪心是万能的。
*   **概念混淆**：将贪心算法与动态规划混淆（动态规划通过记录状态通常能保证全局最优）。

**6. 相关的知识点**

### 第5题：快速排序与归并排序的稳定性

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：排序算法的“稳定性”概念。

**2. 知识点详解**
*   **稳定性定义**：如果排序前 $A=B$ 且 $A$ 在 $B$ 前面，排序后 $A$ 依然在 $B$ 前面，则算法是稳定的。
*   **归并排序（Merge Sort）**：
    *   在合并时，通常写法是 `L[i] <= R[j]` 时取左边的元素。
    *   这保证了相等元素的相对位置不变。
    *   **结论**：归并排序是**稳定**的。
*   **快速排序（Quick Sort）**：
    *   在分区（Partition）过程中，基准元素（Pivot）会与后面的元素交换位置。
    *   这会导致相等元素的相对位置发生改变。
    *   **结论**：快速排序是**不稳定**的。

**3. 选项对错分析**
*   **题目描述**：“...且**都是稳定排序**。”
*   **分析**：该描述**错误**。因为快速排序是不稳定的。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **混淆概念**：容易将“时间复杂度的稳定性”（平均/最坏情况）与“排序结果的稳定性”（相等元素顺序）混淆。
*   **记忆偏差**：容易记错哪个排序是稳定的。**归并排序是分治算法中少有的稳定且高效的排序算法。**

**6. 相关的知识点**
*   冒泡排序、插入排序（稳定） vs 选择排序、堆排序、快速排序（不稳定）。
*   稳定性在实际应用中的意义（例如对多关键字排序时）。

### 第6题：插入排序与快速排序的时间复杂度对比

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：不同排序算法的时间复杂度对比（最坏情况 vs 平均情况）。

**2. 知识点详解**
*   **插入排序 (Insertion Sort)**：
    *   **平均/最好时间复杂度**：$O(n^2)$。
    *   **特点**：对于接近有序的数组非常快（$O(n)$），但对于随机或逆序数组较慢。
*   **快速排序 (Quick Sort)**：
    *   **平均时间复杂度**：$O(n \log n)$。
    *   **最坏时间复杂度**：$O(n^2)$（例如数组已有序且选首元素为基准时）。
*   **对比分析**：
    *   题目说“插入排序的时间复杂度**总是**比快速排序低”。
    *   这是错误的。通常情况下（平均情况），快速排序的 $O(n \log n)$ 远快于插入排序的 $O(n^2)$。
    *   只有在特定情况（如数据量极小 $n<50$，或者数组已经基本有序）下，插入排序才可能比快速排序快。

**3. 选项对错分析**
*   **题目描述**：“插入排序的时间复杂度总是比快速排序低。”
*   **分析**：关键词是“**总是**”。由于存在大量反例（如随机大数组），该描述**错误**。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **以偏概全**：容易记住“插入排序在小数据量时快”或者“插入排序在数据有序时快”，从而忽略了“平均情况下快速排序更快”这一普遍规律。
*   **混淆概念**：混淆了“时间复杂度低”（数值小代表快）和“效率高”。

**6. 相关的知识点**
*   各种排序算法的时间复杂度表（最好、平均、最坏）。
*   排序算法的适用场景（例如STL中的 `std::sort` 通常混合了快排、堆排和插入排序）。

### 第7题：分治策略的效率与并行优化

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：分治策略引入的目的和优势。

**2. 知识点详解**
分治策略（Divide and Conquer）的核心优势：
1.  **降低复杂度**：将难以解决的大问题分解为容易解决的小问题（例如归并排序将 $O(n^2)$ 降为 $O(n \log n)$）。
2.  **并行计算**：分治产生的子问题通常是相互独立的。这意味着它们可以被分配到不同的CPU核心或线程中同时计算（例如MapReduce模型）。
3.  **充分利用资源**：现代计算机多为多核架构，分治算法天然适合并行化，从而提升整体效率。

**3. 选项对错分析**
*   **题目描述**：“引入分治策略往往可以提升算法效率...分治后有利于系统的并行优化。”
*   **分析**：该描述**正确**。这是分治算法在现代计算中被广泛使用的重要原因之一。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **认知局限**：初学者往往只关注分治在“降低时间复杂度”上的作用，容易忽略“并行计算”这一高级应用场景。
*   **逻辑陷阱**：题目中用了“往往可以”而不是“一定可以”，表述比较严谨。

**6. 相关的知识点**
*   并行计算基础。
*   分治法与动态规划的区别（子问题是否独立）。

### 第8题：二分查找的前提条件

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法
*   **具体考点**：二分查找算法的适用前提。

**2. 知识点详解**
*   **二分查找 (Binary Search)** 的核心逻辑：通过比较中间值，排除一半的搜索空间。
*   **必要条件**：序列必须是**有序的**（升序或降序）。
    *   如果序列无序，比较中间值无法确定应该舍弃哪一半，算法无法保证正确性。
*   **补充条件**：通常还需要支持随机访问（如数组），以便 $O(1)$ 时间获取中间元素。

**3. 选项对错分析**
*   **题目描述**：“二分查找要求被搜索的序列是有序的，否则无法保证正确性。”
*   **分析**：该描述**正确**。这是二分查找算法的基石。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **特殊情况**：虽然有“二分答案”算法，但“二分答案”通常也是在有序的解空间中进行二分，本质上还是依赖有序性。
*   **无明显陷阱**：这是最基础的算法常识。

**6. 相关的知识点**
*   旋转数组的二分查找（虽然整体无序，但局部有序，属于进阶题型）。

### 第9题：递归与栈空间

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：递归的底层实现机制与空间复杂度。

**2. 知识点详解**
*   **调用栈 (Call Stack)**：C++程序在运行时维护一个栈结构来管理函数调用。
*   **递归过程**：
    *   每次函数调用自身，都会在栈上压入一个新的**栈帧**（保存局部变量、返回地址等）。
    *   递归结束（触底）后，栈帧才开始逐层弹出。
*   **后果**：
    *   **空间占用多**：递归深度越深，占用的栈空间越多（空间复杂度通常为 $O(n)$，n为深度）。
    *   **栈溢出 (Stack Overflow)**：如果递归层数太深（例如无穷递归或数据规模过大），栈空间耗尽，程序就会崩溃。

**3. 选项对错分析**
*   **题目描述**：“递归的实现方式通常会占用更多的栈空间，可能导致栈溢出。”
*   **分析**：该描述**正确**。这是递归算法的主要缺点。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **与迭代混淆**：容易忘记递归是“用空间换时间”（虽然也不总是换时间），而迭代（循环）通常空间复杂度更低。
*   **尾递归优化**：虽然现代编译器可能对尾递归进行优化以避免栈溢出，但在标准C++和GESP考试范畴内，通常默认递归会消耗栈空间。

**6. 相关的知识点**
*   递归的空间复杂度分析。
*   尾递归的概念。

### 第10题：递归调用的定义

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：递归调用的严格定义（直接递归 vs 间接递归）。

**2. 知识点详解**
*   **递归调用 (Recursion)** 的定义：**函数直接或间接地调用自身**。
*   **直接递归**：函数 A 在其内部代码中调用了 A 自己。
*   **间接递归**：函数 A 调用函数 B，函数 B 又调用函数 A。
*   **题目分析**：
    *   代码：`y = sin(sin(x));`
    *   这里 `sin` 是标准库函数（三角函数）。
    *   `sin` 函数内部并没有调用 `sin` 函数本身（它是通过泰勒展开或查表等迭代方式实现的）。
    *   这只是一个**嵌套函数调用**（Nested Function Call），而不是递归调用。

**3. 选项对错分析**
*   **题目描述**：“应用程序中的语句 `y=sin(sin(x))`；是一种递归调用。”
*   **分析**：该描述**错误**。虽然看起来像一层套一层，但不符合“函数调用自身”的定义。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **视觉误导**：看到 `f(f(x))` 这种数学形式，容易联想到递归公式 $f(n) = f(n-1) + ...$。
*   **概念混淆**：混淆了“数学上的复合函数/递推关系”与“编程语言中函数的自我调用”。

**6. 相关的知识点**
*   函数的嵌套调用与递归调用的区别。
*   标准库函数的实现原理（通常不使用递归以避免栈溢出）。
