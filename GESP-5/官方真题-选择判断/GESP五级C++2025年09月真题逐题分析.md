# 单选题

### 1. 第1题：链表与数组的应用场景

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：链表与数组的特性对比。重点考察在何种业务场景下选择链表作为数据结构更优。

**2. 知识点详解**
*   **数组 (Array)**：
    *   **优点**：支持**随机访问**（通过下标O(1)获取元素），内存空间连续，缓存友好。
    *   **缺点**：在数组中间或头部插入/删除元素时，需要移动大量后续元素，效率较低（O(n)）。
*   **链表 (Linked List)**：
    *   **优点**：插入和删除操作效率高（O(1)），只需修改指针指向，无需移动数据。
    *   **缺点**：不支持随机访问，必须从头遍历（O(n)），且每个节点需要额外空间存储指针。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| A | 数据量固定且读多写少 | **错误**。这种场景下数组的随机访问优势明显，且不需要频繁修改结构，数组更合适。 |
| **B** | **需要频繁在中间或开头插入、删除元素** | **正确**。这是链表的核心优势所在。数组在头部插入需移动全部元素，而链表只需修改头指针或前驱节点的指针。 |
| C | 需要高效随机访问元素 | **错误**。这是数组的强项，链表无法做到O(1)随机访问。 |
| D | 存储空间必须连续 | **错误**。这是数组的特性（物理上连续），链表的节点在内存中是分散的，通过指针连接。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **混淆核心优势**：部分考生容易混淆“插入删除”和“随机访问”这两个对立的核心考点。只要看到“频繁插入/删除”，首选链表；只要看到“频繁查找/读取”，首选数组。
*   **忽略头插法代价**：特别注意“在开头”插入这一条件，对于数组来说，这需要将所有元素后移一位，代价最大。

**6. 相关的知识点**
*   链表的物理存储结构
*   数组的动态扩容机制（vector）

### 2. 第2题：单链表的节点删除操作

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：单链表的删除操作。重点考察如何通过修改指针来“跳过”目标节点，并正确释放内存。

**2. 知识点详解**
在单链表中删除一个节点（假设为`del`），必须修改其前驱节点（`cur`）的`next`指针，使其指向`del`的后继节点（`del->next`）。
**操作顺序**：
1.  记录要删除的节点：`Node* del = cur->next;`
2.  修改前驱指针：`cur->next = del->next;` （这一步是逻辑删除的关键，把“链条”接上）
3.  释放内存：`delete del;`

**3. 选项对错分析**

| 选项 | 代码逻辑 | 分析 |
| :--- | :--- | :--- |
| A | `del = cur; cur = del->next;` | **错误**。逻辑混乱，试图删除当前节点，且未正确连接链表。 |
| B | `del = cur->next; cur->next = del;` | **错误**。这是死循环操作，将`cur`的下一个节点指向了自己（`del`就是`cur->next`），没有实现跳过。 |
| **C** | `del = cur->next; cur->next = del->next; delete del;` | **正确**。标准的三步走：记录 -> 重连 -> 释放。 |
| D | `del = cur->next; delete del; cur->next = del->next;` | **错误**。这是典型的**野指针**错误。先释放了`del`指向的内存，再访问`del->next`是非法的，且逻辑顺序错误。 |

**4. 答案**
**C**

**5. 易错点分析**
*   **内存释放与指针修改的顺序**：选项D是高频错误选项。考生必须明白，释放内存（`delete`）后，该指针指向的内容是不可访问的。必须先用`cur->next`指向`del`的下一个节点（保存位置），然后再释放`del`。
*   **哑节点（Dummy Node）的理解**：题目中使用了哑节点（`dummy`），这保证了头节点的删除和其他节点的删除逻辑一致，避免了对头节点的特殊判断。

**6. 相关的知识点**
*   指针的基本操作
*   内存管理（new/delete）
*   哑节点（哨兵节点）技巧

### 3. 第3题：Floyd判圈算法（快慢指针）

**1. 考察的知识点**
*   **大纲分类**：4. 链表
*   **具体考点**：链表中环的检测算法（Floyd判圈算法）。考察快慢指针的移动逻辑。

**2. 知识点详解**
Floyd判圈算法利用两个在链表上移动的指针：
*   **慢指针 (slow)**：每次向前移动 **1** 步（`slow = slow->next`）。
*   **快指针 (fast)**：每次向前移动 **2** 步（`fast = fast->next->next`）。
如果链表中存在环，快指针最终会追上慢指针（两者相遇）；如果无环，快指针会先到达链表尾部（nullptr）。

**3. 选项对错分析**

| 选项 | 代码逻辑 | 分析 |
| :--- | :--- | :--- |
| **A** | `slow = slow->next; fast = fast->next->next;` | **正确**。完全符合Floyd算法的定义：slow走一步，fast走两步。 |
| B | `slow = fast->next; ...` | **错误**。slow的移动依赖于fast，逻辑错误，slow应该独立走一步。 |
| C | `fast = slow->next->next;` | **错误**。fast的移动依赖于slow，逻辑错误，fast应该独立走两步。 |
| D | `slow = fast->next; ...` | **错误**。同B，逻辑混乱。 |

**4. 答案**
**A**

**5. 易错点分析**
*   **指针更新的独立性**：考生需注意，`slow`和`fast`的更新是基于**当前**各自位置的，不能互相引用作为基准（除非是追赶逻辑，但标准写法是各自独立更新）。
*   **空指针检查**：虽然本题未考察，但在实际编写代码时，必须在`while`循环条件中判断`fast`和`fast->next`是否为空，否则`fast->next->next`可能导致空指针解引用。

**6. 相关的知识点**
*   龟兔赛跑算法
*   链表的遍历

### 4. 第4题：完全数与因数枚举优化

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：因数的枚举。重点考察如何通过“成对出现”的性质将时间复杂度从O(n)优化到O(√n)。

**2. 知识点详解**
求一个数$n$的所有真因数（或判断完全数），不需要从1遍历到$n$。
*   **性质**：因数是成对出现的。如果$i$是$n$的因数，那么$n/i$也是$n$的因数。
*   **优化**：只需要遍历到$\sqrt{n}$（即$i * i <= n$）。
    *   当`n % i == 0`时，同时累加`i`和`n/i`。
    *   特判：如果`i == n/i`（即完全平方数的情况），避免重复累加。

**3. 选项对错分析**

| 选项 | 循环条件 | 分析 |
| :--- | :--- | :--- |
| A | `i <= n` | **错误**。虽然逻辑正确，但效率极低（O(n)），不符合算法优化要求。 |
| **B** | `i*i <= n` | **正确**。这是标准的优化写法，等价于`i <= sqrt(n)`，利用了因数成对出现的性质。 |
| C | `i <= n/2` | **错误**。虽然除了自身外最大的因数不会超过n/2，但遍历范围仍然很大（O(n)），不如B选项优。 |
| D | `i < n` | **错误**。效率低，且逻辑上虽然能跑通，但不是最优解。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **边界条件**：在循环体内，当找到因数`i`时，代码中`sum += i; if (i != n / i) sum += n / i;`这一句是为了防止完全平方数（如36，i=6时，n/i=6）重复计算。
*   **初始值**：代码第3行`sum = 1`是因为1是所有正整数的因数（除了1本身需要特判），这里从2开始循环是为了避免1的重复处理。

**6. 相关的知识点**
*   约数（因数）个数定理
*   素数判定的试除法（同样是O(√n)）

### 5. 第5题：最大公约数（GCD）与欧几里得算法

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：欧几里得算法（辗转相除法）的实现细节。重点考察循环结束条件和返回值。

**2. 知识点详解**
欧几里得算法的核心原理是：$gcd(a, b) = gcd(b, a \mod b)$。
代码逻辑：
1.  `while (b != 0)`：当`b`为0时，循环结束。
2.  计算`temp = a % b`。
3.  将`b`的值赋给`a`。
4.  将`temp`的值赋给`b`。
**循环结束时**，`b`已经变成了0，而`a`存储的是上一轮的`b`，也就是最后那个非零余数，即最大公约数。

**3. 选项对错分析**

| 选项 | 返回值 | 分析 |
| :--- | :--- | :--- |
| A | `b` | **错误**。循环结束时`b`为0，返回0没有意义。 |
| **B** | `a` | **正确**。循环结束时，`a`的值即为最大公约数。 |
| C | `temp` | **错误**。`temp`是局部变量，循环结束后其值为0（最后一次赋值），且作用域仅在循环内。 |
| D | `a * b` | **错误**。这是求最小公倍数（LCM）的一部分，不是GCD。 |

**4. 答案**
**B**

**5. 易错点分析**
*   **返回值的混淆**：考生容易记混最后返回的是`a`还是`b`。记住口诀：“**非零即为公因数**”，循环是因为`b`变成了0才停的，所以答案在`a`里。
*   **swap的作用**：代码第2-3行的`if (a < b) swap(a, b);`其实不是必须的。因为如果`a < b`，第一次`a % b`的结果就是`a`，随后会自动交换位置。但这一步可以减少一次循环迭代。

**6. 相关的知识点**
*   最小公倍数（LCM）的计算：$LCM(a, b) = a * b / GCD(a, b)$
*   扩展欧几里得算法

### 6. 第6题：埃拉托斯特尼筛法（埃氏筛）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：素数表的生成算法——埃拉托斯特尼筛法（Sieve of Eratosthenes）。重点考察内层循环的起始位置。

**2. 知识点详解**
埃氏筛的核心思想是：**从小到大遍历，如果当前数i是素数，则将其所有的倍数（除了自身）标记为合数**。
*   外层循环 `i` 从2开始。
*   当 `is_prime[i]` 为真时，说明 `i` 是素数。
*   **内层循环**：需要从 `i` 的某个倍数开始，将 `i` 的倍数在数组中划掉（标记为`false`）。
    *   不能从 `i` 开始（`i*1`），因为这会把 `i` 自身（素数）给错误地标记掉。
    *   通常的做法是**从 `i` 的2倍开始**，即 `j = i * 2`（或者 `j = i + i`），或者更优化的写法是从 `i*i` 开始（因为小于 `i*i` 的合数已经被更小的素因子筛过了）。但在基础埃氏筛中，标准起始点是 `2*i`。

**3. 选项对错分析**

| 选项 | 代码逻辑 | 分析 |
| :--- | :--- | :--- |
| A | `j = i` | **错误**。这会把 `i` 自己（当前的素数）标记为合数，导致结果错误。 |
| B | `j = i+1` | **错误**。`i+1` 不一定是 `i` 的倍数，无法正确筛去 `i` 的倍数。 |
| **C** | **`j = i*2`** | **正确**。这是最标准、最直观的写法。从 `i` 的2倍开始，将 `2i, 3i, 4i...` 全部标记为合数。 |
| D | `j = i*i` | **视情况而定**。虽然在算法优化中常用（因为小于 `i²` 的 `i` 的倍数肯定已经被更小的质数筛掉了），但题目考察的是基础埃氏筛的逻辑完整性。如果从 `i*i` 开始，对于较小的 `n`（例如 `n=4, i=2`），`j=4` 是对的，但逻辑上不如 `2*i` 严谨且通用。在本题语境下，`2*i` 是更基础、更普适的答案。 |

**4. 答案**
**C**

**5. 易错点分析**
*   **起始点混淆**：容易混淆是从 `i` 开始还是从 `2*i` 开始。记住：**要保留素数 `i`，所以从它的第一个合数倍数 `2*i` 开始筛**。
*   **与线性筛混淆**：不要将这里的起始点与线性筛（欧拉筛）的逻辑混淆，线性筛的内层循环逻辑更为复杂。

**6. 相关的知识点**
*   线性筛（欧拉筛）的实现
*   筛法的时间复杂度分析（埃氏筛为 $O(n \log \log n)$）

### 7. 第7题：线性筛法（欧拉筛）

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：线性筛（欧拉筛）的核心优化条件。重点考察如何保证每个合数只被其**最小质因数**筛掉一次。

**2. 知识点详解**
线性筛的核心在于**打破内层循环的时机**，以确保每个合数只被标记一次。
代码逻辑：
1.  遍历 `i`（当前数字）。
2.  遍历已知的素数列表 `primes`。
3.  标记 `i * p` 为合数（`p` 是当前遍历到的素数）。
4.  **关键判断**：`if (________) break;`
    *   如果 `i % p == 0`，说明 `p` 是 `i` 的一个质因数。
    *   此时必须跳出循环，否则后续的素数 `p'`（大于 `p`）与 `i` 相乘得到的合数 `i * p'`，其最小质因数其实是 `p`（因为 `i` 里已经有 `p` 了），如果继续筛，就会导致 `i * p'` 被 `p`（非最小质因数）筛掉，造成逻辑冗余或重复。

**3. 选项对错分析**

| 选项 | 判断条件 | 分析 |
| :--- | :--- | :--- |
| **A** | **`i % p == 0`** | **正确**。这是线性筛的灵魂。当 `p` 整除 `i` 时，说明 `p` 是 `i` 的最小质因数（因为素数表是从小到大遍历的），此时必须跳出，以保证后续更大的素数不会与 `i` 相乘产生重复筛除。 |
| B | `p % i == 0` | **错误**。此时 `p` 是素数且小于等于 `i`，`p % i` 除非 `p==i`，否则结果就是 `p`，逻辑不通。 |
| C | `i == p` | **错误**。虽然此时 `i % p == 0` 成立，但条件过于苛刻。例如 `i=4, p=2` 时，`4%2==0` 需要跳出，但 `4!=2`，如果不跳出就会导致重复筛。 |
| D | `i * p == n` | **错误**。这只是一个边界条件，与筛法的去重逻辑无关。 |

**4. 答案**
**B** (注：根据你提供的答案键，此处标准答案为 **B**，但根据代码选项文本，应选择 `i % p == 0` 对应的选项。此处选项A文本为 `i % p == 0`，故答案应为 **A**。若原卷选项顺序有微调，请以逻辑为准。根据标准逻辑，填入 `i % p == 0`。)

*(注：根据你上传的文档中第7题选项A的文本 `i % p == 0`，正确答案应为 **A**。)*

**5. 易错点分析**
*   **理解“最小质因数”**：这是最难理解的一点。考生需要明白，线性筛的目的是让每个合数被“构造”它时的最小素数筛掉。
*   **break的位置**：必须在标记 `is_prime[p * i] = false` **之后**立即判断并 `break`。

**6. 相关的知识点**
*   埃氏筛与线性筛的时间复杂度对比
*   唯一分解定理

### 8. 第8题：埃氏筛与线性筛的比较

**1. 考察的知识点**
*   **大纲分类**：1. 初等数论
*   **具体考点**：两种筛法的特性对比。重点考察对“标记次数”和“实际运行效率”的理解。

**2. 知识点详解**
*   **埃氏筛**：一个合数可能被其多个质因数多次标记（例如12会被2和3分别标记）。
*   **线性筛**：理论上每个合数只被标记一次，时间复杂度为 $O(n)$。
*   **实际效率**：虽然线性筛理论复杂度更优，但在实际应用中（尤其是GESP/NOIP范围内），埃氏筛因为代码简单、常数小、缓存命中率高，往往表现得比线性筛更快，或者差距不明显。

### 11. 第11题：快速排序算法分析

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：快速排序（Quick Sort）的实现细节与算法特性。重点考察对分区函数（partition）逻辑和算法复杂度的理解。

**2. 知识点详解**
快速排序采用“分治”策略：
1.  **分区（Partition）**：选择一个基准（pivot），将数组分为两部分，左边小于等于基准，右边大于基准。
2.  **递归**：对左右子数组递归排序。
*   **平均时间复杂度**：$O(n \log n)$。每层划分约 $n$ 次操作，递归深度约 $\log n$。
*   **最坏时间复杂度**：$O(n^2)$。当数组已有序且选择首/尾元素为基准时，每次划分只能减少一个元素，递归深度为 $n$。
*   **稳定性**：快速排序是**不稳定**的，因为在交换过程中可能改变相同元素的相对位置。
*   **Partition逻辑**：通常使用双指针，一个从左找大于基准的，一个从右找小于基准的，找到后交换。**顺序不能随意交换**，否则逻辑会出错。

**3. 选项对错分析**

| 选项 | 内容 | 分析 |
| :--- | :--- | :--- |
| A | 快速排序之所以叫“快速”，是因为它在平均情况下运行速度较快... | **正确**。这是对快排的客观描述，常数小，实践中通常很快。 |
| B | 在平均情况下，划分的递归层数为 logn...总时间为O(nlogn)。 | **正确**。符合平均复杂度分析。 |
| C | 在最差情况下...总时间为O(n²)。 | **正确**。符合最坏情况分析。 |
| D | 划分函数 partition 中“从右往左查找”与“从左往右查找“的顺序可以交换。 | **错误**。**这是本题的答案**。在标准的双指针实现中，如果先从左边开始找，可能会导致基准元素（通常在首位）被错误地覆盖或逻辑混乱。通常先从右往左找（不包含基准的位置），再从左往右找，最后将基准放到相遇点。顺序交换会导致算法不正确。 |

**4. 答案**
**D**

**5. 易错点分析**
*   **混淆“快”与“稳”**：考生容易误以为“快速”意味着它总是最快的（实际上最坏情况很慢），或者误以为它是稳定的。
*   **Partition细节**：很多初学者不理解为什么先从右边开始。这是因为基准选在左边（`arr[low]`），如果先动左边指针，它会直接停在原地（因为`arr[i] <= pivot`成立），导致逻辑失效。必须先动右边指针来寻找“坑位”。

**6. 相关的知识点**
*   归并排序的比较
*   随机化快速排序（Randomized Quick Sort）

**2. 知识点详解**
归并排序的合并过程：
1.  创建临时数组 `tmp`。
2.  使用两个指针 `i`（指向左子数组开头）和 `j`（指向右子数组开头）。
3.  比较 `nums[i]` 和 `nums[j]`，将较小者放入 `tmp`，并移动相应指针。
4.  **处理剩余元素**：当其中一个子数组遍历完后，另一个子数组剩下的元素一定是有序的且比已合并的元素大，直接依次复制到 `tmp` 中。
    *   如果是左子数组有剩余，执行 `while (i <= mid)`。
    *   如果是右子数组有剩余，执行 `while (j <= right)`。

**3. 选项对错分析**

| 选项 | 代码逻辑 | 分析 |
| :--- | :--- | :--- |
| A | `i < mid` | **错误**。这是左子数组的处理逻辑（且边界应为 `<=`），而第14行是在处理右子数组（`nums[j++]`）。 |

| C | `i <= mid` | **错误**。虽然边界对，但逻辑错。这里是在执行 `tmp[k++] = nums[j++]`，必须是 `j` 指针的判断，而不是 `i`。 |

**4. 答案**
**D**

*   **边界符号**：循环条件是 `<` 还是 `<=`。因为数组下标通常包含 `right`，所以必须是 `<=`。
*   **指针混淆**：容易看错当前处理的是哪个子数组。根据第15行代码 `nums[j++]`，可以确定当前处理的是右子数组，因此判断条件必须包含 `j`。

### 2. 第2题：最大公约数与最小公倍数的应用

**1. 考察的知识点**

*   **具体考点**：最小公倍数（LCM）的计算公式。考察对 `LCM(a, b) = (a * b) / GCD(a, b)` 的实际应用。

**2. 知识点详解**

*   **代码逻辑**：

*   **结论**：该说法是错误的。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **混淆GCD与LCM**：考生容易看到 `gcd` 函数就以为答案是求最大公约数，而忽略了变量名 `patternLength` 和公式 `(a*b)/gcd` 明确指向最小公倍数。
*   **阅读理解**：题目问的是“函数返回2”这个陈述是否正确，而不是问代码有没有语法错误。

### 3. 第3题：斐波那契数列的时间复杂度

**1. 考察的知识点**
*   **大纲分类**：6. 递归算法
*   **具体考点**：递归算法的时间复杂度分析。重点考察带备忘录（Memoization）的递归与朴素递归的区别。

**2. 知识点详解**
代码分析：
*   `if (n <= 1) return n;`：基础情况。
*   `if (memo[n] != -1) return memo[n];`：**备忘录检查**。这是关键！
*   如果 `memo[n]` 已经计算过，直接返回，不再递归。
*   **复杂度分析**：
    *   **朴素递归**（无备忘录）：时间复杂度是 $O(2^n)$，因为存在大量重复计算。
    *   **带备忘录递归**（记忆化搜索）：每个状态 `fib(i)` 只会被计算一次，后续都是查表。因此时间复杂度是 $O(n)$。
*   题目中明确初始化了 `memo` 数组并使用了 `if (memo[n] != -1)` 判断。

**3. 选项对错分析**
*   **题目陈述**：下述递归实现的斐波那契数列的时间复杂度为 $O(2^n)$。
*   **分析**：由于代码中使用了 `memo` 数组来存储已经计算过的值，它避免了指数级的重复计算。该实现的时间复杂度是线性的 $O(n)$，而不是指数级的 $O(2^n)$。
*   **结论**：该说法是错误的。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **忽略备忘录**：很多考生看到“递归”两个字，就直接联想到 $O(2^n)$，而忽略了代码中关键的 `memo` 数组和提前返回的判断。
*   **混淆概念**：需要分清“递归树的节点数”（在朴素递归中是指数级）和“实际执行的操作数”（在记忆化搜索中是线性级）。

**2. 知识点详解**
题目陈述链表的特性：
1.  **通过更改指针实现高效的结点插入与删除**：**正确**。这是链表的核心优势，O(1)时间（前提是找到位置）。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **缓存友好性**：这是较深入的考点。初学者可能只关注时间复杂度，而忽略了计算机体系结构中的缓存（Cache）概念。链表的非连续存储导致其缓存性能差。
*   **相对性**：链表的“插入删除高效”是相对于数组而言的（不需要移动元素），但前提是已经找到了插入位置。如果需要先查找位置，总时间复杂度还是O(n)。

**6. 相关的知识点**
*   数组与链表的对比

### 5. 第5题：二分查找的适用条件

**1. 考察的知识点**
*   **大纲分类**：5. 二分算法
*   **具体考点**：二分查找算法的前提条件。考察对“有序性”和“数据结构”的理解。

**2. 知识点详解**
题目陈述：
*   “二分查找依赖数据的有序性”：**正确**。无序数据无法进行二分。
*   “通过循环逐步缩减一半搜索区间”：**正确**。这是二分的核心逻辑。
*   “且仅适用于数组或基于数组实现的数据结构”：**正确**。
    *   二分查找的关键是**随机访问**（O(1)时间访问中间元素）。
    *   **链表**无法高效实现二分查找，因为找到中间节点需要O(n)时间，这会破坏二分查找O(log n)的效率优势。
    *   因此，二分查找通常只适用于数组（Array）、向量（Vector）等支持下标随机访问的结构。

**3. 选项对错分析**
*   **题目陈述**：上述关于二分查找的描述是正确的。

*   **结论**：该说法是正确的。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **链表能否二分**：有考生可能会想“链表也可以找中间点啊”，但忽略了找中间点的时间复杂度。在链表上做二分查找，时间复杂度会退化为 $O(n \log n)$ 甚至更差，失去了二分的意义。
*   **有序性**：必须是完全有序（升序或降序）。

**6. 相关的知识点**
*   二分查找的迭代与递归实现
*   lower_bound 与 upper_bound 的区别

*   **题目陈述**：归并排序在合并阶段不需要比较元素大小。
*   **分析**：这是错误的。比较是归并操作的核心驱动力。
*   **结论**：该说法是**错误**的。

**4. 答案**
**错误（×）**

**5. 易错点分析**
*   **混淆“分解”与“合并”**：考生可能误以为“分解”阶段不需要比较（确实不需要），而题目问的是“合并”阶段。

### 8. 第8题：快速排序的稳定性

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：排序算法的**稳定性**。重点考察对“相同元素相对位置是否改变”的理解，以及快速排序的内部交换机制。

**2. 知识点详解**
*   **稳定性定义**：如果在原序列中，`a[i] == a[j]` 且 `i < j`，排序后 `a[i]` 仍然在 `a[j]` 前面，则称算法是稳定的。
*   **快速排序的不稳定性**：
    *   快速排序的分区过程（Partition）通常涉及首尾指针的交换。
    *   例如序列 `[3, 3, 1, 2]`，选第一个3为基准。右指针找到1，交换首尾：`[1, 3, 3, 2]`。此时两个3的相对位置虽然没变，但在后续处理中，基准3会被交换到中间位置，可能导致原本在前的3跑到后面去，或者反之。
    *   标准的Lomuto或Hoare分区方案通常**不保证**稳定性。

题目中的陈述：“...快速排序是**不稳定**的...在处理相等元素时，可能会改变它们的相对顺序。”
*   这是对快速排序特性的准确描述。

**3. 选项对错分析**
*   **题目陈述**：快速排序是不稳定的。
*   **分析**：这是正确的。虽然存在稳定的变种（如三路快排配合特定策略，或使用额外空间），但标准快排被视为不稳定算法。
*   **结论**：该说法是**正确**的。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **混淆算法**：容易将快排与归并排序（稳定）或堆排序（不稳定）混淆。
*   **认为“相等就不交换”**：考生可能认为代码里有 `<=` 判断，相等就不动了，所以是稳定的。但实际上，基准元素（pivot）最终插入到中间位置时，可能会跨越相等的元素，导致顺序改变。

**6. 相关的知识点**
*   稳定的排序算法：冒泡、插入、归并、计数排序。
*   不稳定的排序算法：选择、希尔、快排、堆排。

### 9. 第9题：分治法求最大子数组和

**1. 考察的知识点**
*   **大纲分类**：7. 分治算法
*   **具体考点**：分治法求解最大子数组和问题。重点考察对“跨越中点情况”的处理逻辑。

**2. 知识点详解**
分治法思路：
1.  **左半部分**的最大和。
2.  **右半部分**的最大和。
3.  **跨越中点**的最大和（必须包含中点附近的元素）。
    *   计算跨越中点的和时，需要分别计算从中点向左扩展的最大和（`left_sum`），以及从中点向右扩展的最大和（`right_sum`）。
    *   跨越中点的总和 = `left_sum + right_sum`。
4.  返回三者中的最大值。

题目中的陈述：“...求解跨越中点的最大子数组和时，我们需要**分别计算左半部分和右半部分的最大和**...”
*   这里的表述稍微有些模糊，但结合算法逻辑，它指的就是计算 `left_sum` 和 `right_sum` 这两个独立的部分。这是算法中必不可少的步骤。

**3. 选项对错分析**
*   **题目陈述**：求跨越中点的和时，需要分别计算左右部分的最大和。
*   **分析**：这是正确的。如果不分别计算，就无法得到跨越中点的完整最大和。
*   **结论**：该说法是**正确**的。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **误解为独立子问题**：考生可能误以为“左半部分的最大和”是指整个左子数组的最大子段和（那是步骤1），而这里是指“从中点开始向左延伸的最大和”。虽然术语相近，但在分治代码实现中，计算跨越中点时确实需要两个独立的循环来分别求左右延伸的和。

**6. 相关的知识点**
*   Kadane算法（动态规划解法）
*   分治法的时间复杂度递推式

### 10. 第10题：图的广度优先搜索（BFS）

**1. 考察的知识点**
*   **大纲分类**：10. 图论
*   **具体考点**：广度优先搜索（BFS）的实现机制。重点考察对**队列（Queue）**数据结构的应用以及**层级遍历**特性的理解。

**2. 知识点详解**
题目陈述：“...使用**队列**来管理待访问的节点...确保先访问距离起始节点更近的节点...”
*   **BFS原理**：利用队列的“先进先出（FIFO）”特性。
    *   将起始节点入队。
    *   出队一个节点，访问它，然后将它的所有未访问邻居入队。
    *   这样，距离为1的节点先入队先出队，距离为2的节点后入队后出队，从而保证了按距离层级进行遍历。
*   这也是求解无权图最短路径的标准方法。

**3. 选项对错分析**
*   **题目陈述**：BFS使用队列，确保先访问距离起始节点更近的节点。
*   **分析**：这是对BFS算法最核心、最准确的描述。
*   **结论**：该说法是**正确**的。

**4. 答案**
**正确（✔）**

**5. 易错点分析**
*   **混淆DFS与BFS**：深度优先搜索（DFS）使用栈（递归或显式栈），是“一条路走到黑”，不保证按距离层级访问。
*   **数据结构记错**：如果使用栈来做BFS，就变成了DFS；只有队列才能实现BFS的层级遍历效果。

**6. 相关的知识点**
*   深度优先搜索（DFS）
*   Dijkstra算法（带权图的BFS推广）
