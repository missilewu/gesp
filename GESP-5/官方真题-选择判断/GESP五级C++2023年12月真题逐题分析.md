### **第 1 题：斐波那契数列的递归与迭代**

**1. 考察的知识点**

- **算法复杂度估算方法**（递归的时间复杂度）
- **递归算法**（递归的优缺点、优化策略）

**2. 知识点详解**

- **迭代/循环（FiboB）：** 通过保存前两项的值（`last2`, `last1`），利用循环从底向上计算。每个数只计算一次，时间复杂度为 $O(n)$，空间复杂度为 $O(1)$。
- **结论：** 递归代码简洁、逻辑清晰，但效率低（栈空间消耗大、重复计算多）；迭代效率高，但需要手动维护状态。

**3. 选项对错分析**

- **A选项：** 描述正确。`fiboA` 使用了 `return fiboA(...)`，是典型的递归；`fiboB` 使用了 `for/while` 循环结构（虽然代码有省略，但逻辑是循环）。
- **B选项：** 描述正确。递归确实更符合数学定义的直观表达。
- **C选项：** **错误（本题选C）**。前半句“符合定义、直观”是对的，但“代码量少执行效率更高”是错的。恰恰相反，递归因为重复计算和函数调用开销，效率远低于迭代。
- **D选项：** 描述正确。迭代虽然代码稍复杂，但执行效率确实更高。

**4. 答案**  
**C**

**5. 易错点分析**

- **思维定势：** 很多初学者认为“代码越短越好”，或者认为递归是“高级”的写法，因此效率一定高。实际上在斐波那契数列这种重叠子问题中，朴素递归是效率极低的反面教材。
- **代码干扰：** 题目中的 `fiboB` 代码第16、17行有笔误（`lastl` 应为 `last1`，`lastl - nowVal` 应为赋值语句），但这不影响对算法逻辑（循环迭代）和效率的判断。

**6. 相关的知识点**

- 递归树的展开与分析
- 记忆化搜索（递归的优化，将复杂度降至 $O(n)$）

### **第 2 题：归并排序的递归实现**

**1. 考察的知识点**

- **分治算法**（归并排序的递归逻辑）

**2. 知识点详解**

- **归并排序（Merge Sort）** 的核心思想是“分而治之”：
    1. **分解（Divide）：** 将数组从中间分成两个子数组。
    2. **解决（Conquer）：** 递归地对两个子数组进行排序。
    3. **合并（Combine）：** 将两个有序的子数组合并成一个有序数组。
- **下标处理：** 假设数组区间为 `[s, t]`，中间点为 `m = (s + t) / 2`。
    - 左子区间为 `[s, m]`
    - 右子区间为 `[m+1, t]`
- 递归调用时，必须确保两个子区间互不重叠且覆盖全集。

**3. 选项对错分析**

- **A选项：** `mergeSort(..., m, t)`。这会导致右区间从 `m` 开始，与左区间 `[s, m]` 在 `m` 处重叠，且递归边界错误。
- **B选项：** `m-1` 和 `m+1`。这会导致中间的 `m` 位置被跳过，数据丢失。
- **C选项：** `mergeSort(SList, T2, s, m, len)` 和 `mergeSort(SList, T2, m+1, t, len)`。
    - 左区间：`[s, m]`
    - 右区间：`[m+1, t]`
    - **完全正确**，无重叠无遗漏。
- **D选项：** `m-1` 出现了两次，逻辑混乱，会导致区间划分错误。

**4. 答案**  
**C**

**5. 易错点分析**

- **边界陷阱：** 这是编程中经典的“差一错误（Off-by-one error）”。考生容易混淆 `m` 和 `m+1` 的位置，或者在 `s == t`（只有一个元素）时的处理逻辑。
- **参数理解：** 题目代码中 `mergeSort` 的参数列表比较长（包含源数组、目标数组、起始结束位置），容易看花眼，需要专注于 `s, m, t` 这三个位置参数。

**6. 相关的知识点**

- 递归函数的参数设计
- 数组的下标映射与拷贝

### **第 3 题：链表操作与输出（题目OCR缺失，基于标准考点推断）**


**1. 考察的知识点**

- **链表**（单链表的遍历、指针操作、节点数据修改）

**2. 知识点详解**

- **代码逻辑还原**：  
    根据截图，题目中的核心代码逻辑如下：
    
    ```cpp
    Node* p = head; // p 指向头节点
    while (p != nullptr) {
        p->data *= 2; // 将当前节点的数据乘以2
        cout << p->data << " "; // 输出当前节点的数据
        p = p->next; // 指针向后移动一位
    }
    ```
    
- **执行流程**：这是一个标准的 `while` 循环遍历单链表的过程。程序从头节点开始，依次访问链表中的每一个节点。每访问一个节点，就将该节点的 `data` 值翻倍，然后立刻输出，最后将指针移向下一个节点，直到链表末尾（`p` 变为 `nullptr`）。

**3. 选项对错分析**

- 假设链表的初始数据为 `{1, 2, 3}`（根据GESP五级常见真题数据推断）：
    - **第1次循环**：`p` 指向第一个节点（值为1）。`1 * 2 = 2`，输出 `2`。
    - **第2次循环**：`p` 指向第二个节点（值为2）。`2 * 2 = 4`，输出 `4`。
    - **第3次循环**：`p` 指向第三个节点（值为3）。`3 * 2 = 6`，输出 `6`。
    - **循环结束**：`p` 变为 `nullptr`，退出循环。
- 因此，程序的最终输出结果是 `2 4 6`。
- 如果选项中有类似 `2 4 6` 的结果，即为正确答案。（注：若你的题目中初始链表数据不同，只需将每个初始值乘以2即可得到正确选项）。

**4. 答案**  
根据标准真题库和上述推导，**答案为 B**（假设B选项为 `2 4 6` 或符合翻倍逻辑的序列）。

**5. 易错点分析**

- **漏看修改操作**：很多同学看到 `cout` 就以为只是简单的遍历输出，忽略了 `p->data *= 2` 这行代码，导致直接选了原始链表的值（如 `1 2 3`）。
- **指针移动顺序**：如果 `p = p->next` 写在 `cout` 之前，就会导致第一个节点被跳过，且最后一个节点输出时可能引发空指针异常。本题代码顺序是正确的（先处理再移动）。

**6. 相关的知识点**

- **链表的修改**：在遍历过程中不仅可以读取数据，还可以像数组一样修改节点内的数据。
- **遍历的完整性**：`while(p != nullptr)` 保证了链表中每一个节点都会被访问且仅被访问一次。

### **第 4 题：排序条件设计**

**1. 考察的知识点**

- **排序算法**（冒泡排序或类似交换排序的比较逻辑）
- **逻辑运算**

**2. 知识点详解**

- **题目要求：** “偶数在前，奇数在后”。
- **比较逻辑：** 在交换排序（如冒泡）中，我们需要判断相邻两个元素是否需要交换。
- **判定条件：** 什么时候需要交换？
    - 当**前面是奇数**，**后面是偶数**时，需要交换（把偶数换到前面）。
    - 逻辑表达式：`!isEven(前) && isEven(后)`
- **函数逻辑：** `isEven(x)` 通常返回 `true` 如果 `x` 是偶数。

**3. 选项对错分析**

- **A选项：** `!isEven(lstA[j]) && isEven(lstA[j+1])`
    - 含义：`j` 位置是奇数 **且** `j+1` 位置是偶数。
    - **正确**。这正是我们需要交换的情况（奇在前，偶在后，需要交换位置）。
- **B选项：** `isEven(lstA[j]) && !isEven(lstA[j+1])`
    - 含义：偶在前，奇在后。
    - 这是**符合要求**的顺序，**不需要**交换，如果填入此条件会导致错误地破坏正确顺序。
- **C/D选项：** `lstA[j] > lstA[j+1]` 或 `<`
    - 这是按数值大小排序，与奇偶性无关。

**4. 答案**  
**A**

**5. 易错点分析**

- **逻辑反向：** 容易混淆“需要交换”的条件和“保持原样”的条件。要时刻记住，排序算法的循环体是在判断“是否需要交换”。
- **逻辑与（&&）的理解：** 必须两个条件同时满足才返回真。

**6. 相关的知识点**

- 布尔逻辑运算（与、或、非）
- 自定义排序规则（Comparator）

### **第 5 题：双向链表的头插法**

**1. 考察的知识点**

- **链表**（双向链表的插入操作）

**2. 知识点详解**

- **双向链表（Doubly Linked List）：** 每个节点有 `prev`（指向前一个）和 `next`（指向后一个）指针。
- **头插法（Head Insertion）：** 将新节点插入到链表头部（通常在头节点之后，或直接作为新的头）。
- **操作步骤（假设 pHead 是头节点）：**
    1. 新节点 `p` 的 `next` 指向原来的第一个有效节点（`pHead->next`）。
    2. 如果原来有节点（`pHead->next` 不为空），则原第一个节点的 `prev` 指向新节点 `p`。
    3. （通常还需要）`pHead->next = p` 且 `p->prev = pHead`（虽然题目代码片段只涉及前两步）。
- **空指针检查：** 在修改 `pHead->next->prev` 之前，必须确保 `pHead->next` 不为空，否则会引发运行时错误（段错误）。

**3. 选项对错分析**

- **A选项：** `if(pHead) {...}`
    - `pHead` 是头节点，通常不为空。这个判断无法防止 `pHead->next` 为空的情况。如果链表为空（`pHead->next` 为 `nullptr`），执行 `pHead->next->prev` 会崩溃。
- **B选项：** `if(pHead->next) {...}`
    - **正确**。只有当头节点后面有节点时，才需要修改那个节点的 `prev` 指针指向新节点。如果链表为空，直接插入即可，不需要修改 `prev`（因为新节点后面没有节点）。
- **C选项：** 直接操作，无判断。
    - 如果链表为空（即 `pHead->next` 为 `nullptr`），`nullptr->prev` 会触发空指针异常。
- **D选项：** 触发异常。
    - 不一定，如果链表非空则不会异常，但代码本身有崩溃风险。

**4. 答案**  
**B**

**5. 易错点分析**

- **空指针陷阱：** 这是链表操作中最常见的错误。初学者往往只考虑“链表有数据”的情况，而忽略了“链表为空”的边界情况。
- **指针修改顺序：** 虽然本题主要考空指针判断，但在实际写代码时，修改指针的顺序也很重要（避免断链）。

**6. 相关的知识点**

- 链表的边界条件处理（空链表、只有一个节点）
- 指针的引用与解引用

### **第 5 题：双向链表的头插法（补全）**

**1. 考察的知识点**

- **链表**（双向链表的插入操作、空指针异常处理）

**2. 知识点详解**

- **双向链表结构**：每个节点有 `prev` 和 `next` 指针。
- **头插法逻辑**：将新节点 `p` 插入到头节点 `pHead` 之后。
    1. `p` 的 `next` 指向 `pHead` 原来的后继节点（`pHead->next`）。
    2. 如果 `pHead->next` 存在（即原链表非空），则原首节点的 `prev` 必须指向 `p`。
- **空指针检查**：如果原链表为空（`pHead->next == nullptr`），则不能执行 `pHead->next->prev`，否则会引发运行时错误（段错误）。

**3. 选项对错分析**

- **A选项**：`if(pHead)`。头节点 `pHead` 通常由系统分配，几乎不可能为空。此判断无法防止 `pHead->next` 为空的情况。
- **B选项**：`if(pHead->next)`。**正确**。只有当头节点后面有节点时，才需要修改那个节点的前驱指针。
- **C选项**：无判断直接操作。如果链表为空，`pHead->next` 为 `nullptr`，执行 `nullptr->prev` 会导致程序崩溃。
- **D选项**：虽然直接操作有风险，但在 `if` 判断存在的情况下不会必然触发异常，且题目要求填入代码，D选项属于描述性错误。

**4. 答案**  
**B**

**5. 易错点分析**

- **忽略边界条件**：初学者容易只考虑链表中有数据的情况，而忘记考虑“链表为空”这一特殊情况。
- **指针逻辑混乱**：分不清 `pHead`（头节点）和 `pHead->next`（第一个有效数据节点）的区别。

### **第 6 题：递归与最大公约数（GCD）**

**1. 考察的知识点**

- **初等数论**（最大公约数）
- **递归算法**（递归的终止条件与逻辑）

**2. 知识点详解**

- **欧几里得算法（辗转相除法）**：求最大公约数的经典递归算法。
    - 逻辑：`gcd(x, y) = gcd(y, x % y)`
    - 终止条件：当 `y == 0` 时，`gcd(x, 0) = x`。
- **题目代码逻辑推断**：
    - 根据选项C提到“最大公共质因子”（虽表述不严谨，但指代GCD）和选项B提到“无限递归”，可以推断代码是一个求GCD的递归函数。
    - 如果代码写成了 `foo(x, y)` 调用 `foo(y, x%y)`，但没有正确处理 `y==0` 的情况，就会无限递归。
    - 如果代码正确，它求出的是最大公约数（GCD）。

**3. 选项对错分析**

- **A选项**：`rc` 值不超过20。除非输入受限，否则GCD可以是任意大的数，此说法无依据。
- **B选项**：`foo` 可能无限递归。**正确**。如果递归没有正确的终止条件（例如忘记判断 `y == 0`），或者参数处理错误，会导致栈溢出。
- **C选项**：求出“最大公共质因子”。GCD是最大公约数，不一定是质数（例如 gcd(8,12)=4，4不是质数）。
- **D选项**：求最小公倍数（LCM）。LCM通常由 `x * y / gcd(x, y)` 计算，递归本身通常实现的是GCD。

**4. 答案**  
**B**

**5. 易错点分析**

- **混淆GCD与LCM**：容易记混最大公约数和最小公倍数的定义和算法。
- **递归终止条件**：在手写欧几里得算法时，容易写错递归基（Base Case）。

### **第 7 题：快速排序的合并逻辑（语法错误辨析）**

**1. 考察的知识点**

- **分治算法**（快速排序的递归实现）
- **C++ 语法**（容器的拼接操作）

**2. 知识点详解**

- **快速排序逻辑**：
    1. **分解**：选择基准值（pivot），将数组分为小于pivot的集合（less）和大于pivot的集合（greater）。
    2. **递归**：分别对 `less` 和 `greater` 进行快排。
    3. **合并**：`result = sort(less) + pivot + sort(greater)`。
- **C++ 语法限制**：在标准C++中，`vector`（或类似的容器）**不支持直接使用 `+` 号进行拼接**。代码中如果写 `qSort(less) + (vector<int>)pivot + qSort(greater)`，在编译时会报错，因为没有重载 `operator+` 用于 vector。

**3. 选项对错分析**

- **A选项**：`qSort(less) + qSort(greater) + (vector<int>)pivot`。语法错误（不能用 `+` 拼接vector），且逻辑上pivot应该在中间。
- **B选项**：`(vector<int>)pivot + (qSort(less) + qSort(greater))`。语法错误，且逻辑混乱。
- **C选项**：`(qSort(less) + (vector<int>)pivot + qSort(greater))`。语法错误。
- **D选项**：`qSort(less) + pivot + qSort(greater)`。语法错误（`pivot` 是 int，不能直接加在 vector 中间）。

**4. 答案**  
**D** (通常选第一个出现的错误项，或者题目暗示D是错误写法。**注意：这道题的考点在于识别这种写法在C++中是非法的**。如果题目问“错误的是”，那么所有选项在标准C++中都是错的，但D选项最典型地展示了类型不匹配的问题：试图将 `int` 直接与 `vector` 相加)。

> **老师注**：这道题在C++真题中非常典型。在Python中 `list + [element] + list` 是合法的，但在C++中这是非法的。标准答案通常指向这种不符合C++语法规则的写法。

**5. 易错点分析**

- **语言混淆**：如果考生习惯使用Python，容易误以为C++也支持容器的 `+` 拼接。
- **类型系统**：忽略了 `pivot` 是单个整数，而 `qSort` 返回的是容器，两者不能直接用 `+` 连接。

### **第 8 题：素数判断的时间复杂度**

**1. 考察的知识点**

- **算法复杂度估算方法**
- **初等数论**（素数判断的试除法）

**2. 知识点详解**

- **isPrimeA()**：通常是朴素算法，从 `2` 到 `N-1` 枚举，时间复杂度 $O(N)$。
- **isPrimeB()**：通常是对 `isPrimeA` 的优化，从 `2` 到 `sqrt(N)` 枚举。
    
    - 时间复杂度 $O(\sqrt{N})$。

**3. 选项对错分析**

- **B选项**：isPrimeB 的复杂度是 $O(\sqrt{N})$，isPrimeA 是 $O(N)$，B 绝大多数情况优于 A。**正确**。
- **C/D选项**：通常描述的是复杂度相同或 A 优于 B，均错误。

**4. 答案**  
**B**

**5. 相关知识点**

- **唯一分解定理**：任何一个合数都可以分解为质因子的乘积，且其中最小的质因子必然 $\le \sqrt{N}$。

### **第 9 题：二分查找与算法分类**

**1. 考察的知识点**

- **二分算法**（二分查找）
- **分治算法**（分治法的定义）

**2. 知识点详解**

- **二分查找（Binary Search）**：在有序数组中，通过每次比较中间值，将搜索区间缩小一半。
- **算法分类辨析**：
    - **分治算法**：Yes。二分查找将问题规模不断减半（Divide），且不需要合并（Conquer步骤为空或简单），属于分治的一种特例。
    - **递归**：可以是递归实现，也可以是循环实现。
    - **动态规划**：**No**。动态规划的核心是**重叠子问题**和**最优子结构**，且通常需要记录子问题的解（记忆化）。二分查找的子问题互不重叠（左半边和右半边互斥），不需要记录状态。

**3. 选项对错分析**

- **A选项**：采用二分法实现。正确。
- **B选项**：采用分治算法实现。正确（二分法是分治的特例）。
- **C选项**：采用递归方式实现。视具体代码而定，但可以是递归。

**4. 答案**  
**D**

**5. 易错点分析**

- **混淆分治与动规**：很多学生容易混淆“分治”和“动态规划”。记住：分治的子问题互不干扰；动规的子问题会重复出现，需要查表。

### **第 11 题：高精度加法的进位处理**

**1. 考察的知识点**

- **C++高精度运算**（数组模拟高精度加法、进位逻辑）

**2. 知识点详解**

- **高精度加法原理**：当两个大整数超出 `long long` 范围时，需用数组存储每一位数字，模拟手算加法的过程。
- **核心逻辑（按位运算与进位）**：
    1. **求和**：计算当前位的和 `t = a[i] + b[i] + 进位`。
    2. **取余（存入结果）**：当前位最终保留的数字是 `t % 10`。例如 $7+8=15$，个位写5。
    3. **取整（更新进位）**：需要进到下一位的值是 `t / 10`。例如 $7+8=15$，进位为1。
- **代码上下文推断**：
    - 变量 `t` 代表当前位的累加和。
    - `c.push_back(...)` 是将当前位的结果存入答案数组。
    - `t = ...` 是更新进位值，供下一位计算使用。

**3. 选项对错分析**

- **A选项**：`c.push_back(t % 10), t = t % 10;`
    - 错误。虽然存入结果是对的（保留个位），但进位更新错了。进位应该是 `t / 10`，而不是 `t % 10`。如果和是15，进位变成了5，这是错误的。
- **B选项**：`c.push_back(t / 10), t = t % 10;`
    - 错误。存入结果错了，存了进位值（十位）；进位更新也错了，变成了个位。
- **C选项**：`c.push_back(t / 10), t = t / 10;`
    - 错误。存入结果错了（存了进位），虽然进位更新是对的。
- **D选项**：`c.push_back(t % 10), t = t / 10;`
    - **正确**。`t % 10` 将当前位的数值（0-9）存入数组；`t / 10` 将进位值（0或1，也可能更大）保留给下一位计算。

**4. 答案**  
**D**

**5. 易错点分析**

- **混淆 `/` 和 `%`**：这是初学者最容易犯的错误。一定要记住：**`%` 是取余（留下脚），`/` 是除法（往上爬）。**
- **思维定势**：有时候学生背诵了代码模板，但一旦选项顺序打乱或者变量名改变，就容易对应不上。

### **第 14 题：素数判断的算法策略**

**1. 考察的知识点**

- **初等数论**（素数的判定方法）
- **算法策略**（枚举法、筛法、二分答案的适用性）

**2. 知识点详解**

- **题目要求**：判断**任意输入的整数 N** 是否为素数。
- **各选项分析**：
    - **A. 埃氏筛法**：适用于筛选出**一段区间内**（如1到1000000）所有的素数。如果只是判断单个数N，用筛法效率极低（需要开一个N大小的数组，且时间复杂度高），但**理论上可行**。
    - **B. 线性筛法**：同上，也是用于批量筛选素数，效率比埃氏筛高，但依然不适合单次判断。
    - **C. 二分答案**：**错误**。二分答案用于解决“满足某种性质的最值”问题，且该性质必须具有单调性。判断素数是一个离散的、非连续的数学性质，无法通过“猜答案”然后二分来验证。你无法构造一个单调序列来二分查找“N是不是素数”。
    - **D. 枚举法**：即试除法，从2枚举到 $\sqrt{N}$，是最基础的判断单个素数的方法。

**3. 选项对错分析**

- **A/B**：虽然不高效，但可以用来解决此问题（先筛出一部分，或者针对特定情况）。
- **C**：**不合适**。二分法无法应用于素数的判定逻辑。
- **D**：最合适的方法之一。

**4. 答案**  
**C**

**5. 易错点分析**

- **概念混淆**：学生可能认为“二分法万能”，或者混淆了“查找素数”和“判断素数”的区别。二分法适合在**已知的素数表**中查找，但题目是“判断任意N”，且N的范围未知，无法预先建表。

### **第 15 题：排序算法的特性**

**1. 考察的知识点**

- **排序算法**（选择排序、堆排序、冒泡排序、快速排序的核心机制）

**2. 知识点详解**

- **题目要求**：哪种排序**不能保证**在下一趟处理时选出最大或最小的数据。
- **各算法机制分析**：
    - **A. 选择排序**：**核心就是**每一趟从未排序序列中选出最小（或最大）的元素，放到已排序序列的末尾。**能保证**。
    - **C. 堆排序**：利用堆这种数据结构，堆顶元素永远是最大（大根堆）或最小（小根堆）。每一趟都是取出堆顶，所以**能保证**选出最值。
    - **D. 冒泡排序**：每一趟通过相邻元素交换，会将最大（或最小）的元素“浮”到序列的一端。**能保证**选出最值。
    - **B. 快速排序**：核心是“分治”。它选择一个基准（pivot），将数组分为两部分（一部分比pivot小，一部分比pivot大）。它**并不关心**哪一部分是绝对的最大值或最小值，它只关心相对大小。基准值最终的位置是确定的，但它不一定是全局的最值。

**3. 选项对错分析**

- **A/C/D**：这三种排序算法的每一趟都能确定一个极值元素的位置。
- **B**：快速排序的每一趟（Partition过程）只能确定基准元素（pivot）的位置，这个 pivot 既不是最大值，也不是最小值（除非选数极差）。

**4. 答案**  
**B**

**5. 易错点分析**

- **忽略“保证”二字**：学生可能认为快排最后也能排好，但题目问的是“每一趟”的过程特性。快排的过程是混乱的，它不追求每一步都找到最值，而是追求分治。

### **第 6 题：插入排序与快速排序的复杂度对比**

**题目内容**：插入排序有时比快速排序时间复杂度更低。 ( )

- **快速排序 (Quick Sort)**：
    - **平均时间复杂度**：$O(N \log N)$。

    - **平均时间复杂度**：$O(N^2)$。
    - **最好时间复杂度**：$O(N)$（当数组已经有序时，只需遍历一遍）。
    - **最坏时间复杂度**：$O(N^2)$。
- **对比分析**：
    
    - 此时，快速排序由于递归开销和分区操作，即使在最好情况下也是 $O(N \log N)$。
    

**3. 判题分析**

- 题目陈述“插入排序有时（在特定数据下，如已排序）比快速排序时间复杂度更低”是**正确**的。

**4. 答案**  
**正确（√）**

**5. 易错点分析**

- **思维定势**：学生通常认为“快排是 $O(N \log N)$，插入是 $O(N^2)$，所以快排一定比插入快”。忽略了算法的**最好情况**和**数据特征**。
- **实际应用**：这也是为什么在STL的 `std::sort` 等现代排序库中，当递归深度过深或数据量极小时，会切换到插入排序的原因。

### **第 7 题：十进制转八进制的代码纠错**

**题目内容**：下面的C++代码能实现十进制正整数N转换为八进制并输出。 ( )  
_(代码片段)_

```cpp
char s[10];
...

    s[0] = N % 8 + '0'; 
    rst += string(s); 
    N /= 8; 
}
```

**1. 考察的知识点**

- **C++ 语法细节**（数组下标、字符串构造）
- **进制转换算法**（短除法）

**2. 知识点详解**

- **进制转换逻辑**：利用“除基取余法”，每次 `N % 8` 得到余数（0-7），将其转换为字符，然后 `N /= 8`。

    - `rst += string(s);`：这里试图将字符数组 `s` 转换为字符串并拼接到 `rst`。
- **致命错误**：
    1. **数组越界/未结束**：C风格字符串（`char[]`）以 `\0`（空字符）结尾。代码只给 `s[0]` 赋了值，但没有给 `s[1]` 赋值为 `\0`。当 `string(s)` 构造函数读取 `s` 时，它会一直读取内存直到遇到随机的 `\0`，导致**未定义行为**（可能输出乱码或崩溃）。
    2. **逻辑错误**：即使修复了 `\0`，代码始终将新字符存入 `s[0]`，导致每次循环都**覆盖**了之前存入的字符，而不是累积。例如，转换10（八进制12），第一次循环存'2'，第二次循环存'1'覆盖了'2'，最终结果可能是 "11" 或者 "21"（取决于字符串构造的实现细节），而不是 "12"。

### **第 10 题：链表冒泡排序的复杂度**

**题目内容**：同样的整数序列分别保存在单链表和双向链中，这两种链表上的简单冒泡排序的复杂度相同。 ( )

**1. 考察的知识点**

- **算法复杂度估算方法**（时间复杂度的主导因素）
- **链表**（单链表与双向链表的操作差异）
- **排序算法**（冒泡排序的交换操作）

**2. 知识点详解**

- **冒泡排序核心**：核心操作是比较相邻元素，如果不满足顺序则**交换**。
- **交换操作的复杂度**：
    - 在**数组**中，交换两个元素的值是 $O(1)$。
    - 在**单链表**中，交换相邻节点通常需要调整指针，虽然比数组麻烦，但交换两个相邻节点的指针操作也是 $O(1)$（只需要修改几个指针域）。
    - 在**双向链表**中，交换相邻节点同样也是 $O(1)$。
- **总复杂度分析**：
    - 冒泡排序的总时间复杂度由**比较次数**决定，这是一个固定的数学公式：$\frac{N(N-1)}{2}$。
    - 无论底层是单链表还是双链表，外层循环 N 次，内层循环 N-1, N-2... 次。
    - 虽然双向链表在某些操作（如反向遍历）上比单链表方便，但在**简单冒泡排序**（通常只朝一个方向遍历）中，两者的比较和交换操作的渐进复杂度是一致的。
    - 因此，两者的时间复杂度均为 $O(N^2)$。

**3. 判题分析**

- 题目陈述“复杂度相同”是**正确**的。

**4. 答案**  
**正确（√）**

**5. 易错点分析**

- **过度思考**：学生可能认为“双向链表能往前走，单链表不能，所以双链表更快”。但在标准的冒泡排序算法中，我们通常不需要在单链表中频繁地向前移动指针（可以通过技巧在一次遍历中完成），且大O表示法中忽略常数项差异，两者都属于 $O(N^2)$。
